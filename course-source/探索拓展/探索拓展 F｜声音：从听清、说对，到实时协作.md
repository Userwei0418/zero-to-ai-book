# 探索拓展 F｜声音：从听清、说对，到实时协作

*附录｜探索拓展。这一条支线讲的是“让机器听和说”。它是这本书里最老的一条支线之一，头一站在 1952 年。这一篇可以单独读，结尾接回第 14 章的验收。*

## 一条语音通知

今晚海豚要发版。组长说：通知别只发文字了，做一条语音丢到群里，值班的人在路上也能听。等他们听完，有人开口问一句，最好还能有个声音答他。

念一段话，听一句话，接一句话。这一篇就拿这三件小事当尺子，看机器是哪一年学会哪一样的。

## 第一站：十个数字

1952 年，贝尔实验室造了一台叫 Audrey 的机器。它占了好几个机柜，会的事情只有一样：听一个人对着话筒念数字，认出是 0 到 9 里的哪一个。

换一个人念，它就不大行了。

![[零基础学AI/attachments/探索拓展 F｜声音：从听清、说对，到实时协作/EA3UbKBlloi91Dx5orhcZ2T1n7e.png|一屋子的机柜，只为了听出一个数字。]]

十年以后，IBM 在世界博览会上展出了一台能认 16 个词的机器。又过了将近三十年，1990 年，头一款卖给普通人的听写软件上市了。用它的人得一个词一个词地、顿开来说。

“让机器听懂人话”这件事，比这本书里几乎所有的事都开始得早。它走得很慢，因为声音这东西没有空格，没有标点，一百个人有一百种说法。

你的通知在这一站只有一条路：找个人念，录下来。

## 第二站：照着它的句式说

2011 年 10 月 14 日，苹果的新手机里带上了 Siri。很多人第一次对着一台机器说了一句整话：明天早上七点叫我。它照办了。

那几年的新鲜劲过去以后，人们发现它的脾气：你得照着它听得懂的那几种句式说。说岔了，它就回你一句“我不太明白”。很多年后，有家报纸说它是“市面上最笨的聊天机器人之一”。

回头看，它卡在哪儿很清楚。它“听”的那一步其实不差。它差在听完以后：后面接的是一套人写的规则，这句话对得上哪条规则，就办哪件事。这是第 01 章。

2024 年，苹果开始往 Siri 里接大模型。2026 年，它选了谷歌的模型来驱动新的 Siri。十五年前最早开口说话的那个助手，最后换了一副别人的脑子。

## 第三站：听清了

2022 年 9 月 21 日，OpenAI 把一个叫 Whisper 的识别模型开源了出来。从这一站起，“把录音转成字”成了一件随手可做的事。

我们的通知可以开工了。把字变成声音，把声音变回字，现在各是一次调用。

```python
# voice.py：一张嘴，一对耳朵。say 把字念成声音，hear 把声音听成字。两个都记下花了多少秒
import json, os, time, urllib.request, uuid

BASE = "https://api.senseaudio.cn/v1"
KEY = os.environ["LLM_API_KEY"]

def _post(path, data, content_type):
    req = urllib.request.Request(BASE + path, data=data,
                                 headers={"Content-Type": content_type, "Authorization": "Bearer " + KEY})
    began = time.time()
    with urllib.request.urlopen(req, timeout=180) as resp:
        return json.loads(resp.read().decode("utf-8")), time.time() - began

def say(text, path, voice="female_0033_b"):
    """字 → 声音。存成一个 mp3，交回花了几秒"""
    body = {"model": "sensenova-tts-2.0", "text": text, "stream": False,
            "voice_setting": {"voice_id": voice}, "audio_setting": {"format": "mp3", "sample_rate": 32000}}
    result, seconds = _post("/t2a_v2", json.dumps(body).encode("utf-8"), "application/json")
    open(path, "wb").write(bytes.fromhex(result["data"]["audio"]))
    return seconds

def hear(path, model="senseaudio-asr-1.5-260319", hotwords=None):
    """声音 → 字。交回听到的字，和花了几秒"""
    fields = {"model": model, "language": "zh"}
    if hotwords:
        fields["hotwords"] = ",".join(hotwords)
    mark = uuid.uuid4().hex
    parts = [f'--{mark}\r\nContent-Disposition: form-data; name="{k}"\r\n\r\n{v}\r\n'.encode("utf-8")
             for k, v in fields.items()]
    parts.append(f'--{mark}\r\nContent-Disposition: form-data; name="file"; filename="a.mp3"\r\n'
                 f'Content-Type: audio/mpeg\r\n\r\n'.encode("utf-8") + open(path, "rb").read() + b"\r\n")
    parts.append(f"--{mark}--\r\n".encode("utf-8"))
    result, seconds = _post("/audio/transcriptions", b"".join(parts), "multipart/form-data; boundary=" + mark)
    return result["text"].strip(), seconds
```

`say` 是一张嘴，`hear` 是一对耳朵。先用嘴，把八句通知念出来，文件夹里多了八段录音。

然后呢？一份文字通知发出去之前，你会扫一眼。一段录音，你没法扫一眼。更麻烦的是，听的时候你手里拿着原文，耳朵会自动替它补上。真正的听众手里没有原文。

所以用一个笨办法：念出来以后，再找一对不认识原文的耳朵听回去，写成字，然后和原文比。

比之前得先想好比什么。八句通知里，我给每一句都标了“丢不得的东西”：版本号，时间，人名，文件名，还有那几个“不”字。一共十九样。

```python

# 用法：python3 loop.py            标准的耳朵
#       python3 loop.py 轻量        换一对轻量的耳朵
#       python3 loop.py 热词        轻量的耳朵，事先告诉它“会听到哪些词”
# 声音只合成一次，三对耳朵听的是同一段录音
import os, re, sys
from voice import say, hear

NOTICE = [   # 每一句后面，是这一句里丢不得的东西。每样东西列出几种算数的写法
    ("海豚 2.10.3 版今晚 22:30 发布。", {"版本号": ["2.10.3", "二点一零点三", "二点十点三"], "时间": ["2230", "22点30", "二十二点三十", "二十二点半"]}),
    ("这次升级不需要重启，也不用清缓存。", {"不需要": ["不需要"], "不用": ["不用"]}),
    ("9 月新增缺陷 72 条，不是 27 条。", {"72": ["72", "七十二"], "不是 27": ["不是27", "不是二十七"]}),
    ("未通过验收的改动，一律不得合入。", {"未通过": ["未通过"], "不得": ["不得"]}),
    ("有问题请找测试组的章蔚，或者在群里找小陈。", {"章蔚": ["章蔚"], "小陈": ["小陈"]}),
    ("resident.py 的日志在 logs 目录下，文件名以 1113 开头。", {"resident.py": ["resident.py"], "logs": ["logs"], "1113": ["1113", "一一一三"]}),
    ("灯塔的权限申请截止到 11 月 14 日，过期不候。", {"权限": ["权限"], "截止": ["截止"], "日期": ["11月14日", "十一月十四日", "十一月十四号"]}),
    ("松鼠的数据要重新导出，重点看 8 月。", {"重新": ["重新"], "重点": ["重点"], "8 月": ["8月", "八月"]}),
]
WORDS = ["海豚", "灯塔", "松鼠", "章蔚", "小陈", "resident.py", "logs", "缓存", "合入"]

def bare(text):
    """去掉标点和空格，字母一律小写"""
    return re.sub(r"[\s，。、：；！？,!?:;]", "", text).lower()

if __name__ == "__main__":
    mode = sys.argv[1] if len(sys.argv) > 1 else "标准"
    same = kept = total = 0
    for n, (line, musts) in enumerate(NOTICE, 1):
        path = f"audio/notice_{n}.mp3"
        if not os.path.exists(path):
            say(line, path)
        if mode == "标准":
            heard, _ = hear(path)
        else:
            heard, _ = hear(path, "senseaudio-asr-lite-1.5-260319", WORDS if mode == "热词" else None)
        lost = [name for name, ways in musts.items() if not any(bare(w) in bare(heard) for w in ways)]
        same += bare(heard).rstrip("。.") == bare(line).rstrip("。.")
        kept += len(musts) - len(lost); total += len(musts)
        print(f"{n}. 念的：{line}\n   听的：{heard}\n   " + ("要紧的都在" if not lost else "丢了：" + "、".join(lost)))
    print(f"\n八句里，听回来和原文一字不差的有 {same} 句。要紧的 {total} 样东西，还在的有 {kept} 样")
```

## 字和声音之间

最后一行有两个数，差得很远。

一字不差的只有 2 句。可丢了要紧东西的只有 3 句。中间那 3 句是怎么回事？

你看第 1 句和第 3 句。“22:30”听回来是“二十二点三十分”，“9 月”听回来是“九月”。意思一点没丢，写法变了。要是我只写了一把“逐字比对”的尺子，它会告诉我八句里错了六句，而其中三句根本没错。

声音里没有“写法”这回事。“9”和“九”念出来是同一个音。字变成声音的那一刻，写法就丢了；声音变回字的时候，是耳朵替你重新挑了一种。

这也是第 5 句出事的原因。念的是“章蔚”，听回来是“张卫”。

![[零基础学AI/attachments/探索拓展 F｜声音：从听清、说对，到实时协作/XTQUbs829oB569xBzeZcUJ5wnHg.png|同一个音，它写成了另外两个字。]]

三个字的音，一个都没听错。它只是不知道这位同事的名字是哪两个字。你也不知道，要是你没见过她的工牌。声音里本来就没有这个信息。

第 6 句丢了两样。`resident.py` 成了“Resident Pi”。“1113”成了“一千一百一十三”。

后面这个值得多看一眼。原文说的是文件名以 1113 开头，那是 11 月 13 日的意思，该一个数字一个数字地念。听回来是一个四位数。这是嘴念错了，还是耳朵听错了？

只看这一圈，分不出来。这个笨办法能告诉你“这儿有事”，告诉不了你事出在哪一半。

第 3 句最要紧。原文是“72 条，不是 27 条”。听回来是“七十二条，补失二十七条”。

那个“不是”没了。

让机器听人说话，这件事做了几十年。2022 年 9 月 21 日，OpenAI 把一个叫 Whisper 的识别模型开源了出来，训练它用了 68 万小时带文字的录音。它没有提出什么新奇的结构，就是数据多、口音杂、环境乱，于是很皮实。从那以后，“把录音转成字”成了一件随手可做的事。会议、访谈、课堂、电话，这些原先只能听的东西，一下子都成了第 10 章说的那种可以检索的资料。

皮实，不等于不出错。2024 年 10 月，美联社的一篇报道汇集了几位研究者和工程师的发现：Whisper 有时会写出录音里根本没有的话。同年一项研究查了一万三千多段短录音，其中大约 1.4% 的转写里有凭空多出来的内容。

多出来一句，和少掉一个“不”字，是同一类毛病：稿子读起来通顺，你看不出哪儿不对。

## 换一对耳朵

平台上的耳朵不止一对。换一对轻量的，同一段录音再听一遍。这一对还有个本事：你可以事先告诉它一张词表，“这些词你多半会听到”。这叫**热词**。把产品名、人名、文件名填进去，再听第三遍。下面是从两遍输出里摘出来的几行。

```

6. 听的：resident派的日志在logs目录下，文件名以一千一百一十三开头。
八句里，听回来和原文一字不差的有 1 句。要紧的 19 样东西，还在的有 16 样

（轻量，加热词）

5. 听的：有问题请找测试组的章蔚，或者在群里找小陈。
6. 听的：resident py的日志在logs目录下，文件名以1113开头。
八句里，听回来和原文一字不差的有 2 句。要紧的 19 样东西，还在的有 17 样
```

15，16，17。看分数，是一路变好。请别只看分数。

**人名救回来了。** 加了热词以后，“张卫”变回了“章蔚”。耳朵不知道的那个信息，你从外面递给了它。这和第 10 章是同一个道理：它不知道的事，你得给它。

**“不是”丢了两回。** 标准的那一对丢了，加了热词的那一对也丢了，只有中间那一对听对了。热词表里没有“不是”，也不该有。你没法把所有要紧的小词都列成热词。

**有一格是蒙对的。** 加了热词以后，1113 那一项算“还在”。可三对耳朵听的是同一段录音。另外两对听到的都是“一千一百一十三”。第三对多半也是，它只是把听到的数写成了阿拉伯数字。写出来的“1113”和原文一模一样，我的尺子就放过去了。

**有一处尺子根本没查。** 第 2 句的“清缓存”，两对轻量的耳朵都听成了“轻缓存”。我标的“丢不得的东西”里只有“不需要”和“不用”，没有这个“清”字。这一处是我读输出的时候才看见的。

还有一件事要交代。同一句“不是 27 条”，我前后合成过两次。头一次的录音，标准的耳朵听成了“不是”。第二次的录音，它听成了“补失”。同一行字，两次念出来的声音不完全一样。

所以这一篇里的数，请当成“这一回”的数。

## 第四站：说得像任何人

耳朵说完了，说嘴。

机器念字，原先一听就是机器。2023 年 1 月 5 日，微软研究院公布了 VALL-E：给它三秒钟某个人的录音，它就能用那个人的嗓音念任意一段话。后面两年，这类模型一个接一个，中文的也有了，比如 2024 年 7 月的 CosyVoice。它们的做法和第 04 章以后的语言模型是一路的：先把声音切成一个一个的“声音 token”，然后一个接一个地往下猜。

同一个月，一家叫 ElevenLabs 的创业公司把它的语音平台开放了出来。传几段短录音上去，就能得到一副可以念任何话的嗓音。那年 10 月它又出了配音功能：把一段话翻成二十多种语言，嗓音还是原来那个人的。

几秒钟的录音。这个数把另一个问题带了出来。

2024 年 2 月，美国新罕布什尔州的两万多位选民接到了自动拨出的电话，电话里是模仿总统嗓音的声音，劝他们不要去投票。事后有音频专家认定，那段声音是用 ElevenLabs 的工具做的。同月，美国的通信监管机构禁止了在自动拨号电话里使用 AI 仿造的人声。

2024 年 5 月，OpenAI 发布 GPT-4o 时带了五种预设的嗓音。其中一种，很多人觉得像一位著名的女演员。一周以后，这个嗓音被停用了。公司的说法是，它出自另一位配音演员，没有模仿谁。那位女演员的说法是，公司此前找过她，她拒绝了。

三件事的是非各不相同，这里不替谁下结论。它们放在一起，说明一件事：对一段声音，要问的问题有三个，而且互相替代不了。

**像不像。** 自然不自然，像不像人，像不像某个人。这要人的耳朵来听。

**对不对。** 字念对了没有，数念对了没有，“不”字还在不在。这一篇前面量的全是这个。

**能不能用。** 这是谁的嗓音，他同不同意。这一条没法量，要凭证。

这一篇用的平台也有克隆嗓音的接口，同时有一份专门的用户协议。本篇只用了平台自带的两种预设嗓音，没有克隆任何人。

## 第五站：会唱了

说话之后是唱歌。

2023 年 4 月，一首叫 Heart on My Sleeve 的歌出现在各个音乐平台上。唱的像是两位当红的歌手，可他们谁也没有参与。两周以后，唱片公司发出通知，歌被下架了。

那首歌用的还是“学某个人的嗓子”。再往后，连这一步都不要了。2023 年 12 月，一个叫 Suno 的产品开放给了所有人：打一句话进去，出来一整首歌，有词，有曲，有人声，有伴奏。2024 年 4 月，另一家叫 Udio 的也来了。

两个月以后，美国的唱片业协会牵头把这两家都告了，理由是拿有版权的录音去训练，索赔每首最高 15 万美元。

然后事情拐了弯。2025 年 10 月，Udio 和环球音乐和解，答应以后只用授权过的音乐来训练，还给了老用户 48 小时把旧作下载走。11 月，Suno 和华纳和解，签了授权。打官司的一边和被告的一边，坐到了一张桌上分钱。另外两家大公司还在告，2026 年 9 月又告了一次。

听歌的那一头也在变。2025 年 7 月，流媒体平台上一支叫 The Velvet Sundown 的乐队被人发现不对劲：攒了 85 万听众，却查不到一场演出，查不到任何一位成员。没过多久，它的简介改成了“一个由人做创意指导的合成音乐项目”。那时候它每月的听众已经过了一百万。11 月，一首生成的歌登上了美国一张乡村音乐销量榜的榜首。

## 第六站：接得上话

最后是组长的那个念想：有人问一句，有个声音答他。

2024 年 5 月 13 日，OpenAI 发布了 GPT-4o。它和以前的做法有一处根本的不同：声音进，声音出，中间不再先转成文字。演示很惊艳。真正交到付费用户手上，拖到了那年 9 月。

为什么要费这个劲？先照老办法搭一个，你就知道了。

值班的人听完通知，开口问了一句：“海豚这一版今晚几点发布？要不要重启？”

要让机器答他，最直接的搭法是三段接力：耳朵听成字，模型想出一句回答，嘴念出来。三段你手上都有了。

```python
# turn.py：有人开口问了一句。听清，想好，说出来，一个来回要几秒
import os, time
from voice import say, hear
from llm import chat
from loop import NOTICE

QUESTION = "海豚这一版今晚几点发布？要不要重启？"
if not os.path.exists("audio/question.mp3"):
    say(QUESTION, "audio/question.mp3", voice="male_0004_a")

notice = "\n".join(line for line, _ in NOTICE)
for n in (1, 2, 3):
    heard, t_hear = hear("audio/question.mp3")
    began = time.time()
    answer = chat(f"下面是一份通知。\n{notice}\n\n有人问：{heard}\n请用一句口语回答，不超过三十个字。")
    t_think = time.time() - began
    t_say = say(answer, f"audio/answer_{n}.mp3")
    print(f"第 {n} 回：听 {t_hear:.1f} 秒，想 {t_think:.1f} 秒，说 {t_say:.1f} 秒，合计 {t_hear + t_think + t_say:.1f} 秒")
    print(f"    听到的：{heard}\n    回答的：{answer}")
```

```
    回答的：今晚22:30发布，不用重启。
第 2 回：听 1.2 秒，想 0.4 秒，说 1.0 秒，合计 2.6 秒

    听到的：海豚这一版今晚几点发布要不要重启
    回答的：今晚22:30发布，不用重启。
```

答得对，一个字不多。

可是请你现在停下来，默数三秒。

当面说话，对方三秒不出声，你已经开始想他是不是没听见了。

而且这三秒还是往少里算的。它没算“等你把话说完”：机器得先确定你是说完了，还是只是换了口气。它也没算路上的网络。

回合制的打字聊天里，没有人在乎这三秒。一开口说话，它就成了第一件要解决的事。这两年的实时语音，下的功夫都在这上面：三段不再排队，一边听一边想，一边想一边说；你中途插话，它得立刻停下来；有的干脆让一个模型直接听声音、直接出声音，中间不再经过文字。这一篇用的平台上就列着这样一个接口，我没有试。

请留意最后那种做法的代价。中间不经过文字了，前面那个“念出来再听回去、拿字来比”的笨办法，也就少了一个下手的地方。

2024 年 5 月那个模型做的，就是把这三段并成一段。

## 接回验收卡

声音这一行的验收卡，“量过什么”那一节照着那三个问题来填。

**像不像，谁听的。** 这一篇没有人逐段去听。所有“念成了什么”的判断，都是从听回来的字推出来的。这一栏在本篇是空着的，得照实写空着。

**对不对，拿什么比的。** 丢不得的东西列了哪些，没列的有哪些。尺子放过的，像那个 1113，有没有人回头看。

**能不能用，凭证在哪儿。** 嗓音是谁的，许可在哪儿。

要是它得当场答话，再添一行：**一个来回几秒，谁数的，算没算上等人说完的那一段。**

## 合上之前，想一想

1. “章蔚”听成了“张卫”，三个音一个没错。请想一想：你平时在电话里报自己的名字，是怎么让对方写对的？这个办法能不能教给机器？
2. “不是 27 条”听成了“补失 27 条”。假如这段转写直接进了会议纪要，下一个读纪要的人会得出什么结论？请为“否定词”设计一种比热词更靠得住的检查办法。
3. 1113 那一项，我的尺子在第三对耳朵那儿放过了它。请改一改 `loop.py`，让“一千一百一十三”和“1113”不再被当成两回事，也不再被当成一回事。你打算让它怎么判？
4. 这个“念出来再听回去”的办法，嘴和耳朵要是出自同一家、同一批训练数据，可能会出现什么情况？（提示：嘴念错的地方，耳朵恰好也这么听。）
5. 默数三秒的那个实验，请找一位同事真的试一次：你问他一个问题，请他故意等三秒再答。你的感觉是什么？两秒呢？一秒呢？
6. 第五站里，一支查无此人的乐队攒了上百万听众。假如你在歌单里听到一首喜欢的歌，后来得知它是生成的，你对它的喜欢会变吗？为什么？
