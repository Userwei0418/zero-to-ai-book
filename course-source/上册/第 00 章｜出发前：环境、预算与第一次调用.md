第一次调用很少一次就通。与其等你撞上了再慌，不如现在故意撞一遍，认一认它们各自长什么样。

## 每次都这么写太麻烦？封装出 `llm.py` 初版

`hello.py` 跑通了第一句话。可你很快就会发现一个问题：如果我想紧接着再问第二句、第三句，难道每次都要把 `urllib.request.Request`、请求头、`json.loads` 这二十行复制粘贴一遍吗？

就像刚学写程序时，发现一段逻辑要反复用，最自然的反应就是**把它封装成一个函数**。我们把刚才那串寄信和拆信的动作包进 `llm.py` 的第一版（以后它会随着资料助手一起越长越大，加进 JSON 模式、工具调用和更细的账本）：

```python
# llm.py（初版）：把寄信和拆信包成一个函数，顺手记一本花销账
import json, os, urllib.request

SPENT = {"calls": 0, "in": 0, "out": 0}                # 一本账：问了几次，读进去多少 token，写出来多少 token

def chat(messages):
    if isinstance(messages, str):                      # 只给一句话也行
        messages = [{"role": "user", "content": messages}]
    request = urllib.request.Request(
        os.environ["LLM_BASE_URL"].rstrip("/") + "/chat/completions",
        data=json.dumps({"model": os.environ["LLM_MODEL"], "messages": messages}).encode("utf-8"),
        headers={"Content-Type": "application/json", "Authorization": "Bearer " + os.environ["LLM_API_KEY"]})
    with urllib.request.urlopen(request, timeout=120) as response:
        reply = json.loads(response.read().decode("utf-8"))
    usage = reply.get("usage", {})
    SPENT["calls"] += 1
    SPENT["in"] += usage.get("prompt_tokens", 0)
    SPENT["out"] += usage.get("completion_tokens", 0)
    return reply["choices"][0]["message"]["content"].strip()
```

就这么二十来行。它只从环境变量里读地址、密钥和模型名——以后不管是换别的云端模型，还是换成你自己训练出来的本地小模型，调用方式都长这个样子。

## 三轮调用小实验：它为什么不记得刚才说过的话？

既然封装好了 `chat()`，我们来做个三轮调用的小实验，顺便看懂第一张账单：连续问它三句话，最后让它“把上一句的回答翻译成英文”。

```python
# bill.py：连续发起三轮调用，看账单，也看它记不记得上一轮
import os
from llm import chat, SPENT

PRICE_IN = float(os.environ.get("PRICE_IN", 1.0))      # 读进去的，每一百万 token 多少钱
PRICE_OUT = float(os.environ.get("PRICE_OUT", 2.0))    # 写出来的，每一百万 token 多少钱

for question in ["你好。", "用三句话解释什么是 token。", "把上面那个问题的回答翻译成英文。"]:
    before = dict(SPENT)
    reply = chat(question)
    print(f"问：{question}\n答：{' '.join(reply.split())[:70]}\n   读进去 {SPENT['in'] - before['in']} 个 token，写出来 {SPENT['out'] - before['out']} 个\n")

cost = SPENT["in"] / 1e6 * PRICE_IN + SPENT["out"] / 1e6 * PRICE_OUT
print(f"三次一共：读进去 {SPENT['in']}，写出来 {SPENT['out']}。按每百万 {PRICE_IN} 和 {PRICE_OUT} 算，是 {cost:.6f}")
```

跑完这三轮，账单上有两件怪事，都请你现在就记住：

**第一件：“你好”两个字，为什么读进去 216 个 token？**

token 是模型数字数的单位，一个汉字大约一个上下。两个字，怎么读出了两百多？看它的回答，它自我介绍了一番——多半是平台在你的话前面垫了一段它自己的开场白，告诉模型它是谁、该怎么说话。这一段你看不见，可它每一次都要读，读了就算你的。所以说到花费，从来不靠估，每个数字都要从 `usage` 那一栏读实数。

**第二件（更反直觉）：第三轮，它把前两轮全忘了。**

你明明刚让它解释完什么是 token，紧接着第三轮让它“把上面那个问题的回答翻译成英文”，它却反过来问你：请提供你要翻译的内容。

为什么？因为大模型本质上就像编程里一个**无状态的纯函数** `f(x) -> y`——好比一位每次接诊都会失忆的医生：你递过去一张写着问题的纸条，它给你开出一张回答的处方；转过身去，下一秒它就把刚才发生的事忘得干干净净。**调用一次，只给一次回答；下一次再调，它永远从一张白纸开始。**

这就留下了一个很值得琢磨的悬念：**既然模型本身只是个“调一次忘一次”的函数，那为什么我们平时用的聊天软件、甚至后面要做的 Agent，却能记得你是谁、上一步干了什么、昨天做到第几步？**

先别急着猜答案。真相不在模型的脑子里，而在我们围着这个函数套上去的那层程序里。到了第 05 章和第 11 章，我们会亲手把这个“让无状态函数长出记性”的机关拆开给你看。

最后是钱。账单最底下那一行，是把 token 换成钱的算法：读进去的和写出来的分开计价，各自乘上单价。代码里那两个单价是我随手填的，只为演示怎么算。请你去查你用的那家平台的价目表，换成真的。

给你一个量级上的参考。这本书各章的实验，少的几万个 token，多的几十万个。花费最高的是第 12 章，因为那一章请了好几位帮手，反复办同一批事。把简单活儿分给本地小模型，可以省下线上接口调用费，但仍有本机算力成本；本版第 12 章尚未接入自训模型，不能把这个方向说成已经测过的结果。

## 没有网，或者不想花钱

如果你没法使用线上的平台，还有一条路：在自己的电脑上跑一个开源的小模型。

现在有一些工具可以把模型下载到本机运行，并且对外提供同一种 Chat Completions 的寄法。那样的话，`LLM_BASE_URL` 填本机的地址，`LLM_API_KEY` 随便填几个字，`LLM_MODEL` 填你下载的那个模型的名字，书里的代码照样不用改。

这条资料助手主线的目标，仍是看清从模型到工具箱、再到循环的关系。当前第 04 章（上）能从零练的是 592 参数的纯 Python 玩具；第 04 章（下）只有 MiniMind 训练骨架。完整的 MiniMind 训练、保存重载，以及自训小模型与强模型在工具任务上的同题对照，尚待补齐。后面的 Harness 实验先用接口模型，不把这段缺口说成已经跑通。
