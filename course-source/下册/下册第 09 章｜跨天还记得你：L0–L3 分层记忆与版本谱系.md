## 为什么“拿一个 Markdown 文件存记忆”过几天就会乱套？

上册第 00 章我们做过那个三轮调用实验：大模型本身是一个调一次忘一次的无状态函数。要让它跨天、跨会话还记得你说过的事，必须在它外面配一个记忆本。

很多开源小项目做记忆本的办法非常直接：建一个 `memory.md`，每聊完几句就让大模型“把值得记的事更新进 `memory.md`”。

刚用头两天挺惊艳，用上两个礼拜，三个大坑就会挨个爆雷：

1. **新旧口径打架（原地覆盖丢历史，只追加又串台）**：你周一说“下周三（11 月 25 日）上午去体检”，周二又说“体检改期到 11 月 27 日周五了”。如果只往文件末尾追加，明天召回时两句话都在，模型分不清到底哪天去；如果让模型直接改写原文件，万一它改错了把别的记忆误删了，你连改之前的版本都找不回来。
2. **把随口提问当成长期事实**：你问了一句“感知机为什么卡在楼梯灯？”，粗糙的整理器会把“用户询问了楼梯灯问题”也写进长期记忆，过几天画像里塞满了鸡毛蒜皮的聊天流水。
3. **锚点在，路断了**：记忆里写着一句结论，你觉得不对劲想查查当时到底是怎么说的，却没有任何从高层结论跳回原始对话的链路。

## 企业级四层记忆架构（L0 → L1 → L2 → L3）

在企业级智能体记忆系统中，记忆从来不是平铺的一张纸，而是严格分成四层，遵循 **“事实只追加、版本不覆盖、视图按需投影、原话可回查”**：

| 层级           | 存储文件              | 职责与核心纪律                                                                                                                                                                               |
| ------------ | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **L0 原始流水账** | `l0_events.jsonl` | **只追加、绝不修改**。每轮对话由外侧程序强制落盘（不靠模型自觉），分配唯一事件编号 `E-0001`、会话号与精确日期                                                                                                                         |
| **L1 原子记忆**  | `l1_atoms.jsonl`  | 提炼出的最小事实单元，按 `(topic, key)` 归档。**更新时绝不原地覆盖**：把旧版本的 `status` 标为 `"superseded"`（已作废），新建一条 `version = 旧版 + 1`、`status = "active"` 的记录，并用 `supersedes` 指向旧版 ID、用 `source_events` 绑定 L0 锚点 |
| **L2 场景记忆**  | `l2_topics.json`  | 只筛选 `status == "active"` 的最新 L1 原子记忆，按话题（如“日程安排”“环境配置”）聚合成场景视图，彻底隔离已作废的历史旧账                                                                                                           |
| **L3 核心画像**  | `l3_profile.md`   | 从 L2 每个话题浓缩出的顶层画像摘要。对话启动时按 **L3（常驻）→ L2（按问题关键词匹配）→ L0（按需顺着锚点回查）** 在字符预算内装配上下文                                                                                                         |

![[零基础学AI/attachments/下册第 10 章｜请一位整理的人：在旁边看，慢慢理/Cdvabxiv7ofXfvxnlTickzp5nzf.png|旧版本标为作废留在谱系里备查，前台永远只看当前有效的最新版本。]]

## 完整四层记忆与版本谱系实现：`memory.py`

打开 `课件/ch09/memory.py`，不到 140 行标准库代码就把这套四层架构完整立了起来：

```python
# memory.py：第 09 章实战成品——L0 流水账 → L1 原子记忆（不可变版本谱系）→ L2/L3 分层归纳与来源回查
# 参考企业级记忆引擎架构：绝不原地覆盖旧记忆，修订必须留版本与来源锚点，支持按预算召回与 L0 原话溯源
import json
import os
import time
import uuid

MEM_DIR = os.path.join(os.path.dirname(__file__), "mem_store")
L0_PATH = os.path.join(MEM_DIR, "l0_events.jsonl")
L1_PATH = os.path.join(MEM_DIR, "l1_atoms.jsonl")
L2_PATH = os.path.join(MEM_DIR, "l2_topics.json")
L3_PATH = os.path.join(MEM_DIR, "l3_profile.md")


def _ensure():
    os.makedirs(MEM_DIR, exist_ok=True)


def _next_event_id():
    if not os.path.exists(L0_PATH):
        return "E-0001"
    with open(L0_PATH, encoding="utf-8") as f:
        n = sum(1 for line in f if line.strip())
    return f"E-{n + 1:04d}"


def record_l0(session_id, role, text, day=None):
    """L0 原始流水账：只追加不修改，程序自动采集（不靠模型自觉）。"""
    _ensure()
    eid = _next_event_id()
    ev = {
        "event_id": eid,
        "session_id": session_id,
        "role": role,
        "day": day or time.strftime("%Y-%m-%d"),
        "text": text,
    }
    with open(L0_PATH, "a", encoding="utf-8") as f:
        f.write(json.dumps(ev, ensure_ascii=False) + "\n")
    return ev


def read_events(event_ids):
    """顺着锚点（如 ['E-0003']）回查 L0 原始对话原话，补齐可追溯链路。"""
    if not os.path.exists(L0_PATH):
        return []
    wanted = set(event_ids)
    out = []
    with open(L0_PATH, encoding="utf-8") as f:
        for line in f:
            if not line.strip():
                continue
            ev = json.loads(line)
            if ev["event_id"] in wanted:
                out.append(ev)
    return out


def _load_l1():
    if not os.path.exists(L1_PATH):
        return []
    with open(L1_PATH, encoding="utf-8") as f:
        return [json.loads(line) for line in f if line.strip()]


def publish_l1(topic, key, fact, source_events):
    """L1 原子记忆发布：若同一 (topic, key) 已有 active 版本，不原地覆盖，而是将旧版标为 superseded 并递增版本号。"""
    _ensure()
    atoms = _load_l1()
    prev_ver = 0
    prev_id = None
    for a in atoms:
        if a["topic"] == topic and a["key"] == key and a["status"] == "active":
            a["status"] = "superseded"
            prev_ver = a["version"]
            prev_id = a["atom_id"]

    new_atom = {
        "atom_id": f"A-{uuid.uuid4().hex[:8]}",
        "topic": topic,
        "key": key,
        "version": prev_ver + 1,
        "status": "active",
        "supersedes": prev_id,
        "fact": fact,
        "source_events": list(source_events),
        "updated_at": time.strftime("%Y-%m-%d %H:%M:%S"),
    }
    atoms.append(new_atom)
    with open(L1_PATH, "w", encoding="utf-8") as f:
        for a in atoms:
            f.write(json.dumps(a, ensure_ascii=False) + "\n")
    rebuild_l2_l3(atoms)
    return new_atom


def rebuild_l2_l3(atoms=None):
    """L2 场景聚合 & L3 核心画像归纳：只基于 active 版本的 L1 原子记忆投影生成。"""
    _ensure()
    atoms = atoms if atoms is not None else _load_l1()
    active = [a for a in atoms if a["status"] == "active"]
    by_topic = {}
    for a in active:
        by_topic.setdefault(a["topic"], []).append(
            f"- [{a['key']} v{a['version']}] {a['fact']} (来源: {','.join(a['source_events'])})"
        )
    with open(L2_PATH, "w", encoding="utf-8") as f:
        json.dump(by_topic, f, ensure_ascii=False, indent=2)

    profile_lines = ["# 核心记忆画像 (L3)", ""]
    for topic, items in sorted(by_topic.items()):
        profile_lines.append(f"## {topic}")
        profile_lines.extend(items[:3])
        profile_lines.append("")
    with open(L3_PATH, "w", encoding="utf-8") as f:
        f.write("\n".join(profile_lines))


def recall(query="", budget_chars=800):
    """按 L3 -> L2 优先级在字符预算内装配上下文，绝不把过时(superseded)记忆混进提示词。"""
    parts = []
    if os.path.exists(L3_PATH):
        parts.append(open(L3_PATH, encoding="utf-8").read().strip())
    if query and os.path.exists(L2_PATH):
        l2 = json.load(open(L2_PATH, encoding="utf-8"))
        for topic, items in l2.items():
            if any(w in topic or w in "\n".join(items) for w in query.split()):
                parts.append(f"### 场景记忆：{topic}\n" + "\n".join(items))
    joined = "\n\n".join(parts)
    return joined[:budget_chars]


if __name__ == "__main__":
    for p in (L0_PATH, L1_PATH, L2_PATH, L3_PATH):
        if os.path.exists(p):
            os.remove(p)
    e1 = record_l0("S1", "user", "我用商汤 Token Plan 跑下册实验，默认模型是 sensenova-6.8-flash。", day="2026-11-16")
    e2 = record_l0("S1", "user", "下周三上午我去体检，需要空腹。", day="2026-11-16")
    e3 = record_l0("S2", "user", "体检改期了，改到 2026-11-27 周五上午。", day="2026-11-17")

    publish_l1("环境配置", "默认模型", "使用商汤 Token Plan，默认 sensenova-6.8-flash", [e1["event_id"]])
    publish_l1("日程安排", "体检时间", "2026-11-25 周三上午体检，需空腹", [e2["event_id"]])
    v2 = publish_l1("日程安排", "体检时间", "改期至 2026-11-27 周五上午体检，需空腹", [e3["event_id"]])

    print("== 召回结果（只含 active 最新版，绝不带出已作废的周三安排）==")
    print(recall("体检"))
    print("\n== 顺着来源锚点回查 L0 原话 ==")
    print(read_events(v2["source_events"]))
```

## 实跑验证：改期之后不串台，原话随时查得到

运行 `python3 课件/ch09/memory.py`，模拟连续两天两个会话（`S1` 先说周三体检，`S2` 改期到周五）：

```

## 日程安排
- [体检时间 v2] 改期至 2026-11-27 周五上午体检，需空腹 (来源: E-0003)

## 环境配置
- [默认模型 v1] 使用商汤 Token Plan，默认 sensenova-6.8-flash (来源: E-0001)

### 场景记忆：日程安排
```

再打开底层的 `mem_store/l1_atoms.jsonl` 看一眼，你会发现 `v1` 和 `v2` 都完好无损地躺在文件里：

- `v1` 的 `status` 变成了 `"superseded"`，留作历史审计；
- `v2` 的 `status` 是 `"active"`，且 `supersedes` 字段精确指向上一条 `v1` 的 `atom_id`；
- 当助手看到 `(来源: E-0003)` 想核对原话时，直接调 `read_events(["E-0003"])` 就能把当时的原始对话捞出来——**锚点在，路也通了。**

> **老办法，新地方**
>
> “底层事实只追加不修改（Event Sourcing），每次状态变更生成带前驱指针的新版本（MVCC 多版本并发控制），上层读取只看活跃视图投影”，这是数据库和 Git 版本控制用了几十年的压箱底手艺。把它搬进 Agent 记忆里，既不怕改错丢历史，又不会让新旧口径在提示词里打架。

不过，一旦你有好几个助手或者后台整理线程**同时**调 `publish_l1()` 往 `l1_atoms.jsonl` 里写东西，或者网络重试把同一条消息发了两遍，文件马上就会写花。**第 10 章**，我们用**单写者锁 + 请求幂等键 + 独立出处审查员**把多助手并发关进笼子里。
