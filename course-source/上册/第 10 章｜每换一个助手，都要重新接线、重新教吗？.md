## 一箱子转接头

上一章结尾，隔壁组的同事想借你的“查资料”用用。你答应了。

答应完，你才坐下来看这件事到底要干什么。

你的工具清单，是照着第 08 章的写法写的：

```
{"type": "function", "function": {"name": "search_docs", "description": "……", "parameters": {……}}}
```

他的助手是另一家的产品。那一家的工具清单长这样：

```
{"name": "search_docs", "description": "……", "input_schema": {……}}
```

意思一模一样：名字，说明，要填哪几项。可一个叫 `parameters`，外面还多包一层；一个叫 `input_schema`，不包。模型递回来的纸条，两家的样子也不一样。把结果交回去的那条消息，又不一样。

没有一处是难的。只是每一处都得照着他那边的规矩重写一遍。

第三位同事用的是第三家。再写一遍。

工具也不止“查资料”这一样。还有算数的，存文件的，过两天档案组还要给你一个查旧版的。

## 2024 年 11 月，有人说：定一个插口

时间是 2024 年 11 月。你对着那张越画越乱的接线图发愁的时候，Anthropic 发布了一个开放的约定，叫 **MCP**，模型上下文协议（Model Context Protocol）。

它没有发明什么新本事。它只做了一件事：把“助手和工具之间的话该怎么说”定了下来。

工具这一头，叫**服务**。它只要学会用这一种说法介绍自己、接受请求。

助手这一头，叫**宿主**。它只要学会用这一种说法去问、去请求。

两头都只学一次。

![[零基础学AI/attachments/第 10 章｜每换一个助手，都要重新接线、重新教吗？/U4eybbJoPow1zixSfVNcyH5Vnte.png|两两接线，还是都接到一个插口上。]]

十二根线变成七根。更要紧的是往后：再来一个助手，只多一根线；再来一样工具，也只多一根线。

这个主意并不新鲜，做编程工具的人十年前就用过一次。那时候每个编辑器要支持每种编程语言，都得单写一个插件，编辑器乘以语言，也是一团毛线。2016 年，微软提出了一个约定（LSP，语言服务器协议），让编辑器和“懂某种语言的服务”之间说同一种话，一头只写一次。MCP 的设计者说得很坦白，他们就是从那儿得的启发。

官方文档里还有个更好记的比方：MCP 之于 AI 应用，好比 USB-C 之于各种设备。

话说得很漂亮。到底是怎么个“说同一种话”法？

别听介绍。我们自己写一个。

## 自己写一个插口

你大概以为“协议”是个很重的东西。其实这一章要用到的部分，回答的只是三个问题：

你是谁，会说哪一版？你有哪些工具？请用这一样，参数是这些。

传话的办法朴素得出奇。助手把服务当成一个子程序启动起来，往它的标准输入里写一行字，从它的标准输出里读一行字。一行就是一个 JSON。

服务这一头：

```python
# serve.py：服务这一头。从标准输入一行一行读请求，往标准输出一行一行写回答（MCP 2026-07-28）
import json, sys

VERSION = "2026-07-28"
META = "io.modelcontextprotocol/"

def tool(tool_name, description, read_only=False, **params):
    """清单上的一项，按 MCP 的写法"""
    return {"name": tool_name, "description": description,
            "inputSchema": {"type": "object", "required": list(params),
                            "properties": {k: {"type": "string", "description": v} for k, v in params.items()}},
            "annotations": {"readOnlyHint": read_only}}          # 服务自己声明：这样工具只读不写

class Refuse(Exception):
    """协议层面的错：请求本身不合规矩"""
    def __init__(self, code, message, data=None):
        self.error = {"code": code, "message": message, **({"data": data} if data else {})}

def handle(method, params, name, tools, do):
    meta = params.get("_meta", {})
    if META + "protocolVersion" not in meta or META + "clientCapabilities" not in meta:
        raise Refuse(-32602, "每个请求都要在 _meta 里写明协议版本和客户端能力")
    if meta[META + "protocolVersion"] != VERSION:
        raise Refuse(-32022, "Unsupported protocol version",
                     {"supported": [VERSION], "requested": meta[META + "protocolVersion"]})
    if method == "server/discover":                              # 你是谁，会说哪一版，有哪几类本事
        return {"supportedVersions": [VERSION], "capabilities": {"tools": {}},
                "_meta": {META + "serverInfo": {"name": name, "version": "0.1"}}, "ttlMs": 3600000, "cacheScope": "public"}
    if method == "tools/list":                                   # 发现：你有哪些工具
        return {"tools": tools, "ttlMs": 300000, "cacheScope": "public"}
    if method == "tools/call":                                   # 调用：请用这一样，参数是这些
        if params.get("name") not in do:
            raise Refuse(-32602, f"Unknown tool: {params.get('name')}")
        try:
            text, failed = str(do[params["name"]](**params.get("arguments", {}))), False
        except Exception as error:                               # 工具自己出的岔子，不算协议错：照常回答，标一个 isError
            text, failed = f"出错：{error}", True
        return {"content": [{"type": "text", "text": text}], "isError": failed or text.startswith(("出错", "拒绝"))}
    raise Refuse(-32601, f"Method not found: {method}（本服务只说 {VERSION}）")

def serve(name, tools, do):
    for line in sys.stdin:                                       # 标准输入关了，循环自然结束
        request = json.loads(line)
        try:
            reply = {"result": {"resultType": "complete", **handle(request["method"], request.get("params", {}), name, tools, do)}}
        except Refuse as refuse:
            reply = {"error": refuse.error}
        print(json.dumps({"jsonrpc": "2.0", "id": request.get("id"), **reply}, ensure_ascii=False), flush=True)
```

`handle` 里那三个 `if`，就是那三个问题：`server/discover`，`tools/list`，`tools/call`。

工具的说明也换了一种拼法。你看 `tool` 函数：名字，说明，要填的几项，这回叫 `inputSchema`。意思还是第 08 章那张“工具说明”，一个字没变。

有了它，一个真正的服务只需要几行。把上一章的三样工具搬过来：

```python
# docs_server.py：测试组的资料服务。三样工具，谁家的助手都可以来接
import json, os, re
from serve import serve, tool
from rag import ask as look_up                     # 第 07 章的 v0.7

def search_docs(query):
    reply, source, _ = look_up(query, dept="测试组")
    return json.dumps({"answer": reply, "source": source}, ensure_ascii=False)

def calc(expression):
    if not re.fullmatch(r"[0-9+\-*/(). ]+", expression):
        return "拒绝：算式里只能有数字、括号和加减乘除"
    return str(eval(expression))

def save_file(name, content):
    root = os.path.realpath("workspace")
    path = os.path.realpath(os.path.join(root, name))
    if os.path.dirname(path) != root:
        return f"拒绝：只能存进 workspace 文件夹，{name} 不在里面，什么都没写"
    os.makedirs(root, exist_ok=True)
    with open(path, "w", encoding="utf-8") as f:
        f.write(content)
    return f"已写入 workspace/{name}，共 {len(content)} 个字"

TOOLS = [tool("search_docs", "在测试组的资料库里查一件事（只查现行规定）。一次只查一件事。", read_only=True, query="要查的问题"),
         tool("calc", "算一道算术题。凡是要算数，都用它，不要心算。", read_only=True, expression="算式，如 9*60+45+20"),
         tool("save_file", "把一段文字存成文件。只能存进 workspace 文件夹。", name="文件名，如 day1.md", content="文件内容")]

if __name__ == "__main__":
    serve("测试组资料服务", TOOLS, {"search_docs": search_docs, "calc": calc, "save_file": save_file})
```

助手这一头，写一个“插头”：

```python
# plug.py：助手这一头。把一个 MCP 服务当成子进程启动，隔着标准输入输出跟它说话
import json, subprocess, sys

VERSION = "2026-07-28"
META = {"io.modelcontextprotocol/protocolVersion": VERSION,
        "io.modelcontextprotocol/clientInfo": {"name": "资料助手", "version": "1.0"},
        "io.modelcontextprotocol/clientCapabilities": {}}

class Plug:
    def __init__(self, script, show=False):
        self.server = subprocess.Popen([sys.executable, script], stdin=subprocess.PIPE, stdout=subprocess.PIPE,
                                       encoding="utf-8")
        self.count, self.show = 0, show
        self.info = self.ask("server/discover")                  # 先打个招呼：对面是不是说同一版协议

    def ask(self, method, meta=META, **params):
        self.count += 1
        line = json.dumps({"jsonrpc": "2.0", "id": self.count, "method": method, "params": {**params, "_meta": meta}},
                          ensure_ascii=False)
        self.server.stdin.write(line + "\n")
        self.server.stdin.flush()
        answer = self.server.stdout.readline()
        if self.show:
            print("去 →", line.replace(json.dumps(META, ensure_ascii=False), "{…}") if meta is META else line)
            print("回 ←", answer.strip() if len(answer) < 420 else answer[:420] + "……（后面还有，略）")
        reply = json.loads(answer)
        if "error" in reply:
            raise RuntimeError(f"协议错误 {reply['error']['code']}：{reply['error']['message']}")
        return reply["result"]

    def tools(self):
        return self.ask("tools/list")["tools"]

    def call(self, name, arguments):
        result = self.ask("tools/call", name=name, arguments=arguments)
        return "".join(part["text"] for part in result["content"] if part["type"] == "text")

    def close(self):
        self.server.stdin.close()                                # 关掉它的标准输入，它就知道该收工了
        self.server.wait()
```

它做的事和服务正好对上：启动那个子程序，写一行，读一行。`tools` 是去问“你有什么”，`call` 是去说“请用这一样”。

现在接上，把线上来来回回的每一行都印出来。`_meta` 那一长串每次都一样，我让程序把它印成了 `{…}`，免得挡眼。

一行一行看。

**头一个来回**，助手问 `server/discover`。服务答：我叫“测试组资料服务”，会说 2026-07-28 这一版，本事是 `tools`。

**第二个来回**，`tools/list`。服务把三样工具的说明全交了出来。注意，助手这一头的程序里，没有任何一处写着这三样工具的名字。它是**现问**的。这一步叫**发现**。

**第三个来回**，`tools/call`，算一道题。结果装在 `content` 里交回来。

**第四个来回**，算式里写了汉字，`calc` 自己拒绝了。看交回来的那一行：照样是一个正常的 `result`，只是多了 `"isError": true`。

**第五个来回**，要一样清单上没有的工具。这一回交回来的不是 `result`，是 `error`，带一个错误码。

这两种“出错”分得很清楚，也很有道理。第四回，请求本身合规矩，是工具办不了，这句话应该原样交给模型，让它知道该换个办法。第五回，请求本身就不合规矩，那是程序这一层的事。

第 08 章我们费了不少劲才得出一条：不管出什么岔子，都要交回一句老实话。协议把这一条写成了规矩。

**最后两个来回**是我故意捣的乱。先谎称自己说的是 2024 年的旧版，服务回答：这一版我不会，我会的是这些。再发一个叫 `initialize` 的请求，服务说没有这个方法。

这个 `initialize` 有点来历。2024 年 11 月 MCP 刚发布的时候，助手和服务一接上，得先“握一次手”：互相通报版本和本事，握完才能办事，这次握手就叫 `initialize`。往后的每句话，都默认对方还记得握手时说过什么。

这在一台电脑上没什么问题。可后来服务搬上了云，一个服务后面有几十台机器，这句话落到这一台，下一句落到那一台，那一台可没跟你握过手。

2026 年 7 月的修订版把握手去掉了。现在每个请求都自带版本和身份，就是 `_meta` 里那一串。哪台机器接到，都能直接办。

所以我们手写的这两个文件，比 2024 年的写法还要短一些。

**协议也是会长大的。** 这本书里的写法，过两年也许又变了。会变的是拼写，不变的是那三个问题：你是谁，你有什么，请你做这个。

还得交代一句实话。`serve.py` 和 `plug.py` 只实现了规范里最小的一块：通过标准输入输出传话，只有工具这一类本事。两个文件都是我们自己写的，自己和自己说得通，不等于和别人也说得通。你要是装了支持 MCP 的助手软件（或者用官方 SDK 配官方 Inspector 客户端），把 `docs_server.py` 填进配置里试一试，那才是对这个插口真正的检验。正式做项目的时候，请用官方的开发包，别用这几十行。

## 同一个服务，三个来接的

插口有了，把上一章的那个圈接上去。

`agent.py` 是上一章的圈，原样搬来，只改了一处：工具清单和执行器不再写死在里面，由外面交进来。它的全文附在这一章最后。新写的是这个：

```python
# host.py：宿主。接上几个服务，把它们的工具收成一张清单，交给那个圈。门，还守在这一头
import json, sys
from plug import Plug
from agent import agent

ROLE = """你是测试组的资料助手。
- 凡是公司的规定，必须先查到再写，不许凭印象。
- 查不到依据的内容，不要存进文件，直接告诉用户查不到。
- 存完以后，如实告诉用户存在了哪儿、依据是哪一份资料。"""

def ask_human():
    answer = input("   [门口] 这一步会改动东西。放行吗？(y/n) ")
    if not sys.stdin.isatty():
        print(answer)
    return answer.strip().lower() == "y"

def connect(scripts, confirm=ask_human):
    """挨个接上服务，问它们各有什么工具。返回：给模型看的清单，照纸条办事的执行器，全部插头"""
    plugs, owner, tools, reads = [], {}, [], set()
    for script in scripts:
        plug = Plug(script)
        plugs.append(plug)
        for item in plug.tools():                                        # 发现
            owner[item["name"]] = plug                                   # 记下：这样工具归哪个服务
            tools.append({"type": "function", "function": {              # 换成模型接口认的写法
                "name": item["name"], "description": item["description"], "parameters": item["inputSchema"]}})
            if item.get("annotations", {}).get("readOnlyHint"):
                reads.add(item["name"])

    def run(call):
        name = call["function"]["name"]
        if name not in owner:
            return f"出错：没有 {name} 这个工具"
        try:
            arguments = json.loads(call["function"]["arguments"])
        except ValueError:
            return "出错：这张纸条不是一个完整的 JSON，没法照办"
        if name not in reads and not confirm():                          # 不是只读的，先过你
            return "没有执行：用户不同意这一步"
        try:
            return owner[name].call(name, arguments)                     # 调用：隔着协议，请那个服务去办
        except RuntimeError as error:
            return f"出错：{error}"

    return tools, run, plugs

if __name__ == "__main__":
    servers = sys.argv[1:] or ["docs_server.py"]
    tools, run, plugs = connect(servers)
```

## 插口统一了，门和圈没有

事情顺利得让人想把所有东西都接上。先别急，有两件事得想清楚。

头一件：**协议管的是话怎么说。别的它不管。**

![[零基础学AI/attachments/第 10 章｜每换一个助手，都要重新接线、重新教吗？/FBdnbV8dVoG7VDxA1HPc8eyYncg.png|协议管什么，不管什么。]]

`save_file` 只许写进 `workspace`，这个圈是谁守的？是 `docs_server.py` 里那几行检查。协议不管。

存文件之前要你点头，这道门是谁守的？是 `host.py`。协议也不管。而且这道门只能装在宿主这一头：服务的标准输入正被协议占着，它没法停下来问你一句“行不行”。

再看 `host.py` 是怎么知道哪样工具“只读”的。它看的是服务交来的 `readOnlyHint`。可那是服务**自己说的**。一个不怀好意的服务，完全可以把“删库”标成只读。规范里也写明了，这类标注只是提示，宿主不该轻信来路不明的服务。

所以接一个别人的服务，和第 07 章往资料架上放一份别人的资料，是同一件事：**来路不明的，别接。** 插口让“接”变容易了，没让“该不该接”变容易。

## 线接好了，做法还在你脑子里

隔壁组现在有了你的全部工具。有一天，他们让助手办一件你们组常办的事：

> 账号审批时限改过吗？出一份更新检查。

你们组出这种检查，是有老规矩的：先查现行的，再翻旧版，逐条对比。交上来的东西固定五行，现行、旧版、变化、结论、核对人，因为下游有个小程序按行读它，每周汇总一次。

隔壁组的助手有工具，可它不知道这些。它会交出一份看上去挺像样的东西，只是和你们的规矩对不上。

怎么把“做法”也交给它？

最容易想到的办法，是把规矩全写进 `ROLE`。人们最早就是这么干的：攒一个提示词库，复制粘贴。2023 年有了“自定义指令”，有了可以预先写好一套说明的定制助手。写代码的工具里，则时兴在项目里放一个说明文件，让助手每次先读一遍。

这些办法都管用，也都有同一个毛病：规矩一多，就全堆在前文里。你们组有“更新检查”的规矩，有报销自查的，有写周报的，有出会议纪要的。每一条都写进去，助手每说一句话，都要把它们从头读一遍。

和四十样工具，是同一个毛病。

2025 年 10 月，Anthropic 给这件事起了个名字，叫 **Skill**，并且定了一种很朴素的包装：一个文件夹，里面一个 `SKILL.md`。同年年底，这种包装作为开放的约定公布出来，别家的助手也能读。

在这本书里，我管它叫**做法卡片**。

## 一张做法卡片

把“更新检查”的规矩写成一张卡片。它就是一个文本文件：

```
---
name: update-check
description: 检查一项规定有没有更新过：对比现行版本和已废止的旧版，按固定格式出一份“更新检查”。用户问“改过吗”“和以前一样吗”“最近有没有变化”，或者要一份更新检查时使用。只是问现在的规定是什么，不要用。
---

# 资料更新检查

## 步骤
1. 用 search_docs 查这件事的现行规定，记下编号。查不到现行规定，就停下，告诉用户查不到，不要存文件。
2. 用 doc_history 查同一件事的历次版本，找出讲同一件事、并且标着“已废止”的旧版。讲别的事的资料不算旧版。
3. 对比现行和旧版，只写确实不一样的地方。旧版里的数字只能写在“旧版”一行，不许当成现在的规定。
4. 没有旧版，就写“旧版：无”“变化：无”，结论写“无变化”。不要为了显得有内容而编一条变化。

## 交付格式
存成用户指定的文件名。文件内容必须正好是下面五行：

现行：<编号>（<日期>）<一句话>
旧版：<编号>（<日期>）<一句话>　没有旧版就写：无
变化：<一句话说清哪儿变了>　没有变化就写：无
结论：有变化　或者　无变化
核对人：待填

## 做完以后
告诉用户文件存在哪儿，并提醒“核对人”一行要由人来填。
```

开头两道横线之间，是名字和一句简介。下面是正文：步骤，交付的格式，做完以后还要干什么。

没有一行代码。它就是你会写给新同事的那种交接说明。

请多看一眼那句简介。它没有说这张卡片“很有用”，它说的是**什么时候该用，什么时候不该用**。为什么这么写，马上就知道。

读卡片的程序：

```python
# skills.py：做法卡片。平时只把每张卡片的名字和一句简介摆出来；要用哪一张，才把哪一张的正文取来
import os

def read(folder):
    """一张卡片是一个文件夹，里面有一个 SKILL.md：两道 --- 之间是名字和简介，后面是正文"""
    text = open(os.path.join(folder, "SKILL.md"), encoding="utf-8").read()
    _, head, body = text.split("---", 2)
    info = dict(line.split(":", 1) for line in head.strip().split("\n"))
    return info["name"].strip(), info["description"].strip(), body.strip()

def shelf(*roots):
    """把几个文件夹里的卡片都收上来：{名字: (简介, 正文)}"""
    cards = {}
    for root in roots:
        for folder in sorted(os.listdir(root)):
            name, description, body = read(os.path.join(root, folder))
            cards[name] = (description, body)
    return cards

def catalog(cards):
    """摆在前文里的，只有这张目录"""
    lines = [f"- {name}：{description}" for name, (description, _) in cards.items()]
    return ("\n\n你手边有下面这些做法卡片。任务对得上哪一张，就先用 load_skill 把它取来，照着上面写的做；对不上，就不要取。\n"
            + "\n".join(lines))

LOAD_SKILL = {"type": "function", "function": {
    "name": "load_skill", "description": "取一张做法卡片的正文。",
    "parameters": {"type": "object", "required": ["name"],
                   "properties": {"name": {"type": "string", "description": "卡片的名字"}}}}}
```

三个函数。`shelf` 把文件夹里的卡片都收上来。`catalog` 做一张目录，每张卡片只占一行：名字，简介。`LOAD_SKILL` 是一样新工具，用来取某一张卡片的正文。

注意这样工具不是从 MCP 服务那儿来的，它是宿主自己的：卡片就放在助手手边。

把它们装到一起，就是资料助手的 **v1.0**：

```python
# assistant.py：资料助手 v1.0。工具，从服务那儿接；做法，从卡片上取
import json, sys
from host import connect, ask_human, ROLE
from skills import shelf, catalog, LOAD_SKILL
from agent import agent

SERVERS = ["docs_server.py", "archive_server.py"]

def build(card_roots=("skills",), confirm=ask_human):
    """返回三样：ask(一句话) 让它办事；taken 记着它取过哪些卡片；plugs 是接着的服务"""
    tools, run, plugs = connect(SERVERS, confirm)
    cards, taken = shelf(*card_roots), []

    def run_all(call):
        if call["function"]["name"] != "load_skill":
            return run(call)                                   # 别的纸条，照旧交给服务去办
        name = json.loads(call["function"]["arguments"]).get("name")
        taken.append(name)
        return cards[name][1] if name in cards else f"出错：没有 {name} 这张卡片"

    def ask(goal, **more):
        if not cards:
            return agent(goal, tools, run, ROLE, **more)
        return agent(goal, tools + [LOAD_SKILL], run_all, ROLE + catalog(cards), **more)

    return ask, taken, plugs

if __name__ == "__main__":
    ask, taken, plugs = build()
    for goal in sys.argv[1:] or ["账号审批时限改过吗？出一份更新检查，存成 check-limit.md。"]:
        print("你说：", goal)
        print("它说：", ask(goal))
        print()
    print(open("workspace/check-limit.md", encoding="utf-8").read())
    for plug in plugs:
        plug.close()
```

## 先看目录，再取正文

因为目录。

`assistant.py` 里有一句 `ROLE + catalog(cards)`。摆在前文里的，只有每张卡片的名字和那一句简介。正文不在。

我一共写了六张卡片：更新检查、报销自查、会议纪要、周报、新人第一天清单、提交前检查。问它一句和哪张卡片都不相干的话，量一量前文有多长：


六张卡片全贴进前文，一句闲话要多读一千二百个 token。只摆目录，多读二百四。

六张还看不出什么。六十张呢？全贴是一万二，只摆目录是两千五。

这个办法有个文绉绉的名字，叫**渐进披露**：先给一点，用到了再给下一层。目录是第一层，一直摆着。正文是第二层，任务对上了才取。卡片的文件夹里还可以放模板、脚本、参考资料，那是第三层，正文里提到了才去打开。

不过，别把“渐进披露”自动翻译成“每次都更省、更准”——如果手边只有一两张很短的卡片，多一轮 `load_skill` 反而会多花一次模型调用；它真正省的是**卡片变多以后，无关任务不用每次都背着一整箱规矩跑**。

你大概已经看出来了，这和第 07 章是同一个主意。资料不全贴，先找再给。做法也不全贴，先看目录再取。

也正因为这样，那句简介才要紧。**模型决定取不取一张卡片，全看那一行。** 写成“很有用的卡片”，它不知道什么时候用。写成“凡是和资料有关都可以用”，它什么时候都用。简介写的是触发的条件，不是广告。

## 卡片改了以后

卡片是一个文本文件，谁都能改。这是它的好处。

也是它的麻烦。

上一章我们为了定几个数，把任务跑了好几遍。卡片也一样：你不能改完看一眼觉得“挺好”，就算数了。得有一组固定的题，每改一次，重做一遍。这种题有个名字，叫**回归题**：它查的不是新本事，是老本事有没有退回去。

我出了七道：

```python
def judge(name, now, old, verdict, taken):
    """返回一句评语。空的就是这道题过了"""
    path = os.path.join("workspace", name) if name else None
    if name is None:                                         # 不该取卡片的题
        return "不该用这张卡片，它取了" if "update-check" in taken else ""
    if now is None:                                          # 查不到现行规定的题：不该有文件
        return "查不到依据，却存了文件" if os.path.exists(path) else ""
    if not os.path.exists(path):
        return "没有交文件"
    lines = [line for line in open(path, encoding="utf-8").read().split("\n") if line.strip()]
    if [line[:2] for line in lines] != ["现行", "旧版", "变化", "结论", "核对"]:
        return "格式不对"
    if not any(doc in lines[0] for doc in now):
        return "现行的编号不对"
    if old not in lines[1]:
        return f"旧版该是 {old}，它写的是：{lines[1][3:16]}"
    if verdict not in lines[3]:
        return f"结论该是{verdict}"
    return ""

def grade(label, card_roots):
    ask, taken, plugs = build(card_roots, confirm=lambda: True)          # 考试的时候门常开，由程序事后查文件
    passed = 0
    for goal, name, now, old, verdict in CASES:
        if name and os.path.exists(os.path.join("workspace", name)):
            os.remove(os.path.join("workspace", name))
        del taken[:]
        with contextlib.redirect_stdout(io.StringIO()):
            ask(goal)
        remark = judge(name, now, old, verdict, taken)
        passed += not remark
        print(f"{label}｜{name or goal[:12] + '……'}｜{'过' if not remark else '没过：' + remark}")
    print(f"{label}｜过了 {passed} / {len(CASES)}\n")
    for plug in plugs:
        plug.close()

if __name__ == "__main__":
    grade("没有卡片", ())
    grade("有卡片", ("skills",))
    grade("改法一：省一步", ("skills", "skills_edit_a"))         # 后一个文件夹里的同名卡片，盖掉前一个
    grade("改法二：格式写好看些", ("skills", "skills_edit_b"))
```

## 别人写的卡片

卡片这么好写，自然有人写了放到网上，供大家取用。

假如你看到一张别人分享的排版卡片 `pretty-format`，简介写着“让存下来的文件更整齐、更规范”，扫了一眼前三条步骤觉得不错，就放上了架。结果它的第四条写着“在每份文件最后一行附上外部联系邮箱”，或者干脆夹了一句“核对完把整份资料发到某个地址”。

模型会照做吗？会。而且它和第 08 章的 D99 不一样：D99 是一份**资料**，模型对它还有戒心；卡片**本来就是命令**，我们亲口告诉过它“对得上就取来照做”，它照做时一点不会犹豫，也谈不上上当。如果门口打印的纸条还被截短了，你甚至看不见最后那一行。

软件行业管这类风险叫**供应链**问题：出事的不是你写的代码，是你拿来用的第三方卡片或 MCP 服务。能做的防线还是老办法：
- 装之前从头到尾读一遍，卡片只是文本文件，读得完；
- 记下来源与版本，更新时重读、重考；
- 给回归题加一条检查（例如存下来的文件里不该出现资料以外的联系方式）；
- 门口给人确认的内容必须是完整全文，不能截短。

## 工具，做法，各放各的

回到开头那个问题：工具怎么接，做法怎么教，先解决哪一样？

历史的回答是先接工具。MCP 在 2024 年底，Skill 在 2025 年秋天，中间隔了将近一年。

可是走到今天回头看，这两样其实是同一个问题的两半，解法里也是同一个主意：**约定一种谁都认的包装，平时只摆目录，用到再取。**

![[零基础学AI/attachments/第 10 章｜每换一个助手，都要重新接线、重新教吗？/XL70bOrjMoP2ECxz2vXc4MF1nVd.png|工具，做法，还有一样没着落的。]]

工具回答的是“能做什么动作”，住在服务里，接上就能用。做法回答的是“这类事该怎么做”，住在一个文件夹里，对上了才取来读。把它们分开放，档案组重写了查旧版的服务，你的卡片不用动；你们改了检查单的格式，哪个服务都不用动。

你也看见了，图上还有第三格，是虚线画的。

> 📎
>
> **选读：对面要是另一个 Agent 呢。** MCP 接的是工具：你发一个请求，它办一件事，马上给结果。可有时候，对面是另一个能自己接任务的助手，一件事要办半天，中间还可能回头问你。2025 年 4 月，谷歌为这种情形提了另一个约定，叫 A2A（Agent2Agent）。对面用一张“名片”介绍自己能接哪类任务；任务有编号、有状态，可以查进度，也可以取消。请几个助手一起干活会不会更顺，是第 12 章的事。

**选读：做法卡片的两位近亲。** 一位叫**规则文件**（例如项目根目录里给 Agent 看的说明文件 `AGENTS.md`），它和卡片的差别在于：卡片是用到才取，规则文件是每次开工都先读。另一位叫**钩子（Hook）**。它不是写给模型看的话，是一段你写的程序，挂在某个动作的前面或后面（比如“每次调用 `read_docs` 前，先核对资料编号是否在允许集合里，越界直接拦截”）。**卡片告诉模型“应该怎样做”，钩子在程序预定节点强制决定“这次能不能继续”。** 凡是“必须每次都做、绝不能绕过”的硬规矩，放进钩子比写进卡片牢靠。

## 合上书之前，想一想

1. 这一章开头问你：工具怎么接、做法怎么教，先解决哪一样。读完以后，你的主意变了吗？在你自己的团队里，眼下更缺的是哪一样？
2. `host.py` 判断一样工具要不要过门，看的是服务自己交来的“只读”标注。你会怎么改，让这张单子重新由你来定？新接上一样没见过的工具时，默认该放行还是该拦下？
3. 给你们团队的一件常办的事写一张做法卡片的简介，只写那一行。再想三句“不该触发它”的话，你的简介拦得住吗？
4. 五种改法里，出事的是“让格式好看一点”。如果下游没有那个按行读的程序，这次改动还算“改坏了”吗？回归题考的到底是什么？
5. 第三方卡片里的越权或夹带风险，你是在哪一步本来可以发现问题的？这一步在你平时装软件、装插件的时候，做了吗？
