## 从手拨算盘，到整张 Excel 表同时算：MiniMind 预训练

上一篇末尾，我们用 100 行纯 Python 拼出了一个 592 个参数的迷你大脑 `mini_gpt.py`。它已经能把猜错代价从 `2.93` 降到 `0.89`，开口结结巴巴地接出“新同事先申请账件”。

为什么它结巴，而且练 80 轮就花了好几秒？因为 `Value` 盒子是一个数一个数分开算的，好比拿着一把算盘一颗颗拨珠子。真要让资料助手的大脑长到几千万个参数、读进上百万句话，靠纯 Python 算盘珠子得算到猴年马月。

这时候，就得请出专门干这行的工具 **PyTorch**。你可以把它想成一张支持自动记账的超级 Excel 表（行话叫**张量**）：原本需要写三层 `for` 循环的乘法加法，PyTorch 一句矩阵乘法就能让显卡里的几千个核心同时算完；至于第 02 章那套顺着字条倒着算梯度的逻辑，PyTorch 已经内置在了 `loss.backward()` 里，原理一模一样，只是快了成千上万倍。

开源世界里有一个特别适合教学的极简大模型项目，叫 **MiniMind**（由开源作者 jingyaogong 维护）。它提供了 **26M–64M 参数**量级的小语言模型配置（对比动辄千亿参数的大模型，简直小如芝麻）。但训练多久、花多少钱，得连同代码版本、数据量和机器一起说。这一版没有给出可复现的 MiniMind 训练配置与日志，先不替你许下“两小时几块钱”或“CPU 几分钟”的保证；训练一个更小的模型或下载已有权重，也都要先补齐具体步骤。

整个预训练的代码骨架，其实就干了三件你已经见过的事：

1. **升级版字模箱（BPE 分词，6400 词表）**：第 01 章 `cut.py` 只认识 8 个词，遇到生僻字就变 `0`。MiniMind 用了更聪明的切法：把语料里最常一起出现的字两两合并（比如“账”+“号”→“账号”），攒出一本 **6400 个词** 的词表，既不会漏字，词表又小。
2. **叠高几层的 Transformer**：把上一篇 `mini_gpt.py` 的单层单头注意力叠成 8 层、多头并行，用向量表示每个词；具体层数、头数和维度须按所选 MiniMind 版本的配置核对，这里不把它们当成已经锁定的实验配置。
3. **自监督“完形填空”**：把海量文本切成长条，前几个字当输入，后一个字当标准答案——**文字自己就是考卷和答案，不需要任何人工标注**。

```python
# minimind_pretrain_sketch.py：MiniMind 预训练的核心循环（PyTorch 骨架）
# 注：这是对应原理的示意骨架，不能单独运行；尚未定义数据加载器、模型和优化器，安装 torch 并不足够
import torch
import torch.nn.functional as F

# 1. 模型结构：和 mini_gpt.py 一样，只是把 list[Value] 换成了 nn.Module 张量层
#    每一步输入一串 token 编号 x: [batch_size, seq_len]
#    模型输出每个位置对 6400 个词的打分 logits: [batch_size, seq_len, 6400]
for x, y in dataloader:                 # x 是前文，y 是往后错开一位的“下一个词”
    logits = model(x)
    loss = F.cross_entropy(             # 等价于 mini_gpt.py 里的 -log(probs[nxt])
        logits.view(-1, logits.size(-1)),
        y.view(-1),
    )
    optimizer.zero_grad()               # 等价于 for p in params: p.grad = 0.0
    loss.backward()                     # 等价于 Value.backward()
    optimizer.step()                    # 等价于 p.data -= lr * p.grad
```

对照着 `mini_gpt.py` 看这六行核心循环，你会发现**一行多余的概念都没有**。从 592 个参数到千万级模型，模型结构、数据与训练配置都还要补上，不能只换硬件。不过，训练循环仍能认出那三步：往前猜下一个词、算猜错代价、顺着计算图倒着挪参数。

## 读遍互联网

2018 年，有两个团队给出了同一个回答：**什么都读。** OpenAI 的 GPT 练的是猜下一个词；Google 的 BERT 练的是完形填空，把句子里的词挖掉几个，让它根据两边补回来。两者的思路是一样的：先在海量的文字上练出一身通用的本事，再拿去学具体的事。前一步叫**预训练**，这种自己给自己出题的练法叫**自监督学习**。

GPT-2 是 GPT 的放大版：十五亿个参数，八百万个网页。然后，就有了安第斯山上的独角兽。

![[零基础学AI/attachments/第 04 章｜学着接下一句，为什么接住了许多任务？/Vts9bm6OooBqsoxXmCycXU7anCf.png|八百万个网页。每一页，都是一道“猜下一个词”的练习题。]]

现在回到上一篇开头的第二个问题：没人教过它写摘要，它会吗？

GPT-2 的论文里记着一个小把戏。它读过八百万个网页。你想让它写摘要，可你只能给它一段前文，让它往下接。你会在文章后面加一句什么，把它“骗”进写摘要的状态？

答案是四个字母：**TL;DR**。这是英文网络上的老习惯，意思是“太长不看”，后面通常跟着一句话总结。在文章后面写上 `TL;DR:`，模型就接着写出了一段摘要——它只是在网上见过太多次“长文，TL;DR，一句话”这个套路。

```python
# tldr.py：没人教过它“摘要”这个任务。在文章后面加一个词试试
from ask import chat

article = "一项惊人的发现：科学家在安第斯山脉一个偏远的山谷里，发现了一群会说流利英语的独角兽。"
print(chat(article + "\n\nTL;DR:"))
```

```
安第斯山谷发现会说流利英语的独角兽。
```

这就是第二个问题的答案，也是这一章最重要的一句话：**任务本身，也可以写成字。**

![[零基础学AI/attachments/第 04 章｜学着接下一句，为什么接住了许多任务？/YkFdbSMktoyQTFxI0Stc0plHneg.png|换一种写法，就换了一个任务。]]

分类、翻译、摘要，都能摆成“前文，加上一个等着被接的开头”。它自始至终只做一件事：接下一句。可为了把各种各样的话都接好，它不得不学会语法、常识、文章的套路、两种语言怎么对应。

至于第一个问题，该不该担心？2019 年 11 月 OpenAI 放出了完整版 GPT-2，没过几年，用大模型批量生成的垃圾文章和假消息就成了每个上网的人都躲不开的东西。担心的人和笑话的人各对了一半，只是担心的人对得早了一点。

## 把任务写进前文

2020 年 5 月，GPT-3 来了。一千七百五十亿个参数，是 GPT-2 的一百多倍。

它的论文想说明的，其实就是 `TL;DR:` 那个把戏的升级版：你要它做什么事，不用重新训练它，**把要求和几个例子直接写在前文里就行。** 只写要求、一个例子都不给，叫 zero-shot；给几个例子，叫 few-shot。它照着前文里的例子调整这一次的回答，这个现象叫**上下文学习**。这里的“学习”要打个引号：它一个参数都没有改。

我们的资料助手，第 02 章是拿 20 个例子训练出来的。这一次，我们一个参数都不碰，直接调用第 00 章配好的商汤 Token Plan 大模型接口来考考那张六句话的考卷（`exam.py`）：

```python
# ask.py：资料助手 v0.4，不训练，把四个例子写进前文
# 需要第 00 章配好的环境变量：LLM_BASE_URL、LLM_API_KEY、LLM_MODEL
import json, os, urllib.request
from exam import run

def chat(prompt):
    req = urllib.request.Request(
        os.environ["LLM_BASE_URL"].rstrip("/") + "/chat/completions",
        data=json.dumps({
            "model": os.environ["LLM_MODEL"],
            "messages": [{"role": "user", "content": prompt}],
            "temperature": 0,
        }).encode("utf-8"),
        headers={"Content-Type": "application/json",
                 "Authorization": "Bearer " + os.environ["LLM_API_KEY"]},
    )
    with urllib.request.urlopen(req, timeout=60) as resp:
        return json.load(resp)["choices"][0]["message"]["content"].strip()

FRONT = """把新同事的问题分成两类：账号申请、软件安装。只输出类别名。

问题：怎么开通账号
类别：账号申请
问题：插件装不上
类别：软件安装
问题：登录名怎么获取
类别：账号申请
问题：本地环境怎么部署
类别：软件安装
问题：{q}
类别："""

if __name__ == "__main__":
    print("模型：", os.environ["LLM_MODEL"])
    run(lambda text: chat(FRONT.format(q=text)))
```

运行结果（以 `sensenova-6.8-flash` 为默认模型）：

```
模型： sensenova-6.8-flash
✓ 账号怎么申请？ -> 账号申请
✓ 软件怎么安装？ -> 软件安装
✓ 登录用的身份怎么办理？ -> 账号申请
✓ 开发环境部署失败了 -> 软件安装
✓ 账号已有了，软件怎么安装？ -> 软件安装
✓ 软件已经安装好了，账号怎么申请？ -> 账号申请
6/6
```

六句全对。停在第五句“账号已有了，软件怎么安装？”上多看一眼：第 01 章的规则版在这儿错过，第 02 章的分类器也在这儿错过，因为它们一个认关键词，一个数单字。这是头一回，资料助手真正读懂了“已经有了”是什么意思——而我们为此做的全部工作，只是写了十来行字。

![[零基础学AI/attachments/第 04 章｜学着接下一句，为什么接住了许多任务？/M7GBbtKbeokwEfxIljlcnJgInAe.png|三个版本，一张考卷。]]

先别急着庆祝。我们是见过世面的人了，知道一个满分后面要问什么：

**第一问：只有六道题。** 往后我们会把考卷加厚。

**第二问：它每次都这么听话吗？** 有时候你把模型换成更大、更贵的型号（例如换成同平台的 `glm-5.3` 或其他大模型），它可能会在某一句里客气地多输出几个字，比如回答成 `类别：账号申请`。意思完全对，程序一比对却判了错——**它是在“接话”，不是在“填表”**。另外，实际工程里还常碰到另一件事：网络请求明明返回了成功（HTTP 200），但输出预算设小了、回答写到一半被截断，这同样不算交付。第 05 章我们会专门对付这些问题。

**第三问：代价呢。** 第 02 章的分类器在自己电脑上跑几乎零成本；v0.4 每问一句都要走网络、等回复、花额度。六句话无所谓，六百万句就得算算账了（这也是为什么第 12 章我们会把简单活儿交回给自己训的 MiniMind 小模型）。

**第四问：它说的是真的吗。** 你要是问它“实习生审批入口的网址是什么”，它会接出一个看着很像样的网址。接得出来，不等于查过。这种一本正经的编造，叫**幻觉**。这是第 07 章的主题。

最后，把下面这张图刻在脑子里，后面每一章都要回来看它：

![[零基础学AI/attachments/第 04 章｜学着接下一句，为什么接住了许多任务？/TmdpbNqU5odlkcxjmw0c4KHrnth.png|什么时候改了它，什么时候没改。]]

**改大脑参数（比如 `mini_gpt.py` 和 MiniMind 预训练）**，学到的东西留在了权重里，下次不用再说；**写进前文（比如 `ask.py` 里的四个例子）**，一个参数没动，换一段前文它就忘了。这是好事（改几个字就能换任务），也是麻烦（每一次都得从头交代）。

## 做大，做到多大

2020 年，OpenAI 的研究发现，模型猜词猜得有多准，和参数量、数据量、算力之间有很稳定的规律（Scaling Laws）。2022 年，DeepMind 又用 Chinchilla 对照实验证明：同样的算力预算下，**光长个子（堆参数）不读书（喂数据）是不行的**，小一点但多读几倍书的模型反而赢了。

![[零基础学AI/attachments/第 04 章｜学着接下一句，为什么接住了许多任务？/Uks6bQnDYoqsGVxoRGxcaUmXnOc.png|从词到大模型：2013—2022。]]

> 📎
>
> **选读：模型名字后面那些词。** **混合专家（MoE）**：模型内部分成很多小模块，每次只叫醒其中几个。**蒸馏**：让小模型学着模仿大模型的回答。**开放权重**：把模型的参数放出来谁都能下载，但不等于训练数据也公开。
>
> **选读：训好以后，还能动三处。** **微调**：拿训好的模型，用自己的一批例子接着训一小会儿。**LoRA**：原来几十亿个数一个不动，只在课本页边贴一张可撕的“便利贴”（添一小组新参数）来记部门规矩——第 07 章我们会亲手用它把部门规定“背”进 MiniMind，再和 RAG 翻书做一次硬核对比。**量化**：把每个数存得粗一点（比如 16 位压到 4 位），笔记本也跑得动。

## 下一站

你现在有了一个极其擅长“接下一句”的模型。于是你敲下一句话：“帮我给新同事写一份上手指南。”

假如坐在对面的是 2019 年的预训练基座模型，它多半会顺着往下写：“另外，请把部门介绍和常见问题也整理一份。周五之前给我。”——它把你的话当成了一篇文章的开头，而不是一件要办的活。

怎么把一个“只会接文章”的基座模型，教成一个“听得懂人话、愿意接活”的助手？下一章，我们先用三个回答倾向的玩具实验，亲手看示范（SFT）和偏好（DPO）怎样推着参数变。它不是对 MiniMind 权重的完整微调；把这两课接到真正训好并存盘的模型上，仍是这条资料助手主线待补的一段。
