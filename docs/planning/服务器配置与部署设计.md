# 零基础学 AI：网页书、可执行实验与 AI 导读部署方案

日期：2026-11-18（北京时间）

## 结论与核查状态

2 核 / 4 GiB 可作为首版应用服务器的起点。前提是：轻量 Python 实验在读者浏览器执行；AI 导读使用外部模型 API；视频和大资源交给对象存储 / CDN；需要完整 Linux 的实验使用独立沙箱服务。

**当前不能确认这台已有服务的机器可以直接共用。** 本次 SSH 未建立连接，执行环境返回 `Network is unreachable`，尚未进入认证阶段。没有获得服务器上的服务列表、内存占用、磁盘剩余或端口情况，也没有在服务器上安装、修改或重启任何服务。这不能据以判断服务器离线或密钥错误。

用户提供的机器信息：Ubuntu 24.04，2 核 / 4 GiB，80 GB SSD，上海，公网带宽 10 Mbps。这些是配置资料，不是本次实测结果。本文件不含 SSH 私钥、密码或 API Key。

## 阅读与实验体验

- 桌面双页，手机单页；目录、搜索、字号、书签和阅读进度独立于固定页码。
- 代码采用真正可编辑、可运行的单元。每章共享一个 Python 会话，单元有执行序号、运行、停止、重置、从头运行本章。
- 输出展示 stdout、stderr、表格和图像。长代码、长输出展开到实验区；关闭后返回原阅读位置。
- 代码修改可自动保存，运行变量只在当前会话存活；重新打开需按顺序重跑，不假装已经恢复内存状态。
- 分页避开代码单元内部。只用页角、明确按钮触发翻页，避免选代码、点术语、拖播放器时误翻。
- 运行前可记录猜测，运行后对照真实结果；允许直接运行，保留探索节奏。

## AI 导读

正文经编辑选定的关键词使用细虚线下划线。点击后，在词语旁打开小卡片；手机使用底部面板。卡片支持键盘操作，并可关闭、钉在侧边。

第一层给出已审校的“课程释义”，可即时显示。第二层为“AI 解释”，结合当前段落与章节回答，提供三个入口：“说得更简单”“举个本章的例子”“继续问”。不要把固定释义冒充实时 AI 输出。

例如点击“过拟合”：
1. 解释当前例子为什么属于过拟合。
2. 用本章的训练题与新问法作比喻。
3. 指向本书相关段落，方便返回上下文。
4. 如果读者正在实验，可主动选择附上当前单元和错误，让 AI 给下一步提示。

后端以章节 ID、段落 ID、术语 ID 定位可信课程片段，只补充少量相关内容和近期追问。先做章节索引 / 关键词检索，后续再按实际效果加向量检索。第一版不必引入独立向量数据库。

同一版本的术语标准解释可缓存；包含个人代码或私人追问的答案按用户隔离。每位用户限制频率、同时请求数和用量；服务端限制输入、输出长度和总预算。AI 导读只解释与建议，执行代码仍由读者明确点击。

## 技术分工

| 位置 | 职责 | 资源与边界 |
|---|---|---|
| 读者浏览器 | 翻页、播放器、编辑器、Pyodide 轻量 Python | 运算使用读者设备；首次下载运行时，按需加载课程依赖 |
| 独立执行来源的浏览器页面 | 承载可编辑代码的 Python Worker | 与账号页面隔离；不注入站点凭据或模型密钥；限制可访问网络与消息格式 |
| 现有 2 核 / 4 GiB 主机 | HTTPS 入口、登录、进度与代码保存、AI 请求转发、缓存与限流 | 需要先检查已有服务和高峰余量 |
| 对象存储 / CDN | 视频、图片、课程静态资源、浏览器 Python 包 | 浏览器直接取资源，不经应用服务器转发视频 |
| 模型 API | AI 导读推理 | 费用、请求速率和并发受账号权益限制 |
| 独立云端沙箱 | Linux 子进程、文件锁、较重 Python 依赖等 | 按用户会话隔离，限制 CPU、内存、时长、进程、输出和网络 |

Web Worker 用来避免实验阻塞阅读界面，不能单独代替账号隔离设计。任意代码不能直接交给网站后端的 Python 进程执行。

需要云端实验时，推荐独立沙箱节点或托管沙箱；可采用 gVisor 等增强隔离机制，并施加资源与网络限制。普通 Docker 默认配置不能被视为完整的多人任意代码执行边界。学生实验中不放长期模型主密钥；如需调用模型，通过受限的服务端接口分配额度。

完整模型训练另评估 GPU 与数据规模，不纳入这台 2 核 / 4 GiB 主机的容量承诺。前期可先上线浏览器支持的实验，其余章节显示明确的运行环境要求；如要求首发全书都能执行，就必须同时接入云端沙箱。

## 推荐的最小部署

前端可用 React + TypeScript，书页由 Markdown / MDX 内容生成，代码单元由编辑器组件承载。使用轻量异步 API 服务负责账号、学习记录与模型转发。数据库可从 SQLite（单实例、短事务）起步；若需要较多并发写或已有合适数据库，可复用或选 PostgreSQL，先核查现有部署再定。

复用现有反向代理，通过域名 / 子域路由接入，不抢占已有服务监听端口。构建在开发机或 CI 完成，服务器只运行构建产物，避免构建高峰挤占运行内存。为数据库与用户代码安排外部备份，日志滚动限额。

下列是“整台空闲机器”的初始规划预算，不是实测占用，也不表示已有服务之外还有同等余量：

| 用途 | 初始内存预算 |
|---|---:|
| Ubuntu、反向代理、基础监控 | 0.6 GiB |
| 一个应用服务 | 0.9 GiB |
| 小型数据库 | 0.8 GiB |
| 文件缓存、峰值与余量 | 1.7 GiB |
| 合计 | 4.0 GiB |

80 GB SSD 先放程序、数据库、受限日志和少量静态资源；实验数据集、视频和长期备份使用外部存储。磁盘是否够用取决于现有占用，不能根据标称 80 GB 推断。

## 10 Mbps 带宽

理论上限约为 1.25 MB/s，实际有效传输还受协议、线路、拥塞与共享请求影响。

已对本地课程中的视频元数据进行检查：9 个可读取文件的平均码率约 0.356–0.439 Mbps。因此，按 0.4 Mbps 粗算，10 路持续播放约占 4 Mbps。这个算式**不是容量保证**：播放器会突发预缓冲，拖动会重新取数据，图片与 Python 运行时首次下载也占出口；未来高清素材可能显著提高码率。

另有第 05 章第 2 个视频无法读取元数据，需要重新导出或补齐文件后再验收播放。

建议从首版起使用对象存储直连；多人使用时配 CDN。国内读者所需 Python 运行时与固定依赖也应使用可稳定访问的资源源站，避免首次打开长时间等待。

## AI 接口核对

已核对用户提供的官方文档，列出的 OpenAI 兼容接口为：

- Base URL：`https://token.sensetime.com/api/v1`
- Chat 接口：`POST /chat/completions`
- 凭据仅存服务端的环境变量或凭据管理系统。
- 模型 ID、协议开放情况、流式字段、并发、价格与额度，以账号工作台为准。

本次只查阅公开文档，未使用提供的 API Key 发起模型请求，未验证密钥权限或产生模型调用费用。接入时先验证一个最小请求，再测试流式输出；不支持流式时使用完整回答回传。模型选择通过配置完成，避免写死在前端。

服务器只负责组织上下文和转发请求，不在本机运行大模型，因此 AI 导读通常不会成为本机的主要算力消耗。仍须实测并发连接、缓冲区、数据库写入和模型延迟。

## 容量验证与升级条件

区分“在线阅读人数”“每秒业务请求”“同时等待 AI 的请求”“云端沙箱运行数”。不能仅凭 2 核 / 4 GiB 宣称支持固定人数。

建议第一阶段按 20 / 50 / 100 个模拟会话逐步压测，预先固定翻页、保存频率、AI 请求比例与平均响应长度。这些数字是测试档位，不是已支持人数。

先单独测试本机业务，再接入受限数量的真实模型调用，以区分本机与外部服务瓶颈。记录：
- 普通业务接口的 p95 延迟与错误率。
- AI 首字时间、完成时间、429 / 超时与账号用量。
- CPU、MemAvailable、换页、OOM、磁盘与出口。
- 保存是否丢失，沙箱超时是否影响网站。

初始告警可采用 CPU 持续 10 分钟超过 70%、可用内存低于 20%、持续换页 / OOM、出口持续超过 70%。这些是待调整的运维阈值。数据库、程序、上游额度与带宽问题应分别定位，不能一律用升配解决。

若现有服务占用了主要内存或 CPU，新增独立应用机比直接挤入更稳妥。若只是应用资源不足，可升级到 4 核 / 8 GiB；增加云端实验并发时，扩展的是独立沙箱资源，而不是只升级网站主机。

## 只读服务器检查

在能访问服务器的本机终端设置 COURSE_SSH_HOST、COURSE_SSH_USER 与 COURSE_SSH_PORT，再执行以下命令。默认使用本机已有 SSH 配置 / ssh-agent；若需指定密钥，在 ssh 后添加 `-i /实际的本机私钥文件路径`。不要把私钥正文粘贴进脚本或回传结果。

命令通过 SSH 标准输入临时执行，只查询状态，不安装包、不重启服务、不读取环境变量、密钥文件、应用配置全文或进程完整参数。可选的 sudo 查询使用 `-n`，权限不足会跳过，不索要密码。全部结果打印到本机终端。

```bash
ssh -p "${COURSE_SSH_PORT:-22}" "${COURSE_SSH_USER}@${COURSE_SSH_HOST}" 'python3 -' <<'PY'
import json
import shutil
import subprocess

def probe(name, args, limit=80):
    try:
        r = subprocess.run(args, capture_output=True, text=True, timeout=20)
        print(json.dumps({
            "check": name,
            "exit": r.returncode,
            "output": "\n".join(r.stdout.splitlines()[:limit]),
            "error": r.stderr[:500]
        }, ensure_ascii=False))
    except Exception as e:
        print(json.dumps({"check": name, "error": type(e).__name__}))

probe("system", ["uname", "-srmo"])
probe("cpu_count", ["nproc"])
probe("load", ["uptime"])
probe("memory_MiB", ["free", "-m"])
probe("disk", ["df", "-hT", "/"])
probe("inodes", ["df", "-i", "/"])
probe("listeners", ["ss", "-ltnp"])
probe("process_memory", ["ps", "-eo", "pid,user,comm,pcpu,pmem,rss", "--sort=-rss"], 21)
probe("running_services", ["systemctl", "list-units", "--type=service", "--state=running", "--no-pager", "--plain"])
probe("failed_services", ["systemctl", "--failed", "--no-pager", "--plain"])

sudo_ok = False
if shutil.which("sudo"):
    r = subprocess.run(["sudo", "-n", "true"], capture_output=True, timeout=5)
    sudo_ok = r.returncode == 0
if sudo_ok:
    probe("listeners_with_process", ["sudo", "-n", "ss", "-ltnp"])

if shutil.which("docker"):
    prefix = ["sudo", "-n"] if sudo_ok else []
    probe("containers", prefix + ["docker", "ps", "-a", "--format",
          "{{.Names}} | {{.Image}} | {{.Status}} | {{.Ports}}"])
    probe("container_resources", prefix + ["docker", "stats", "--no-stream", "--format",
          "{{.Name}} | CPU {{.CPUPerc}} | RAM {{.MemUsage}} | NET {{.NetIO}}"])

if shutil.which("vmstat"):
    probe("five_second_sample", ["vmstat", "1", "5"])
PY
```

获得结果后，还需要结合业务高峰的监控判断余量。一次空闲快照不足以确认生产容量。检查结果可用于确定反向代理接入方式、可用端口、数据库选择，以及是否需要新增机器。

## 第一版验收

先完成第 01 章的完整路径：
1. 阅读与视频可用，手机单页、桌面双页。
2. 修改代码后实际执行，输出随修改变化。
3. 翻页保留本章变量，刷新后清楚提示需要重跑。
4. 点击术语得到与本章相关的解释，能追问并返回正文。
5. 密钥不出现在前端资源或实验环境里。
6. 运行错误、超时、AI 额度不足时，仍能继续阅读和保存。
7. 在目标机器的实际已有负载下通过容量与回归检查。
