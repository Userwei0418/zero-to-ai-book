## 第 37 手

2016 年 3 月 10 日，首尔，四季酒店。大厅里架满了摄像机，你坐在解说席旁边，给两位职业棋手打下手。

棋盘两边，一边是李世石，过去十年里最强的围棋手之一。另一边是个替人落子的工程师，他只负责把屏幕上显示的位置摆到棋盘上。真正下棋的，是一个叫 AlphaGo 的程序。

围棋，一直被当作机器最啃不动的一块骨头。

1997 年，IBM 的深蓝就在国际象棋上赢了世界冠军。它靠的是蛮力：每秒钟推算几亿个局面，再用人写好的规则给每个局面打分。可这一套搬到围棋上就不灵了。围棋的合法局面数，大约是 2 后面跟着 170 个零；整个宇宙里的原子，也不过是 1 后面 80 个零。算是算不完的。

那就写规则来判断哪个局面好？还记得第 01 章的那句话吗：我们知道的，比我们说得出来的多。围棋高手管自己的判断叫“棋感”。你问他这步为什么好，他多半会说：“感觉。”

所以，直到这次比赛之前，不少行内人还估计，机器要赢顶尖棋手，大概还得再等十年。

昨天，第一局，李世石输了。大厅里安静了好一阵。

今天是第二局。下到第 37 手，AlphaGo 把一颗黑子放在了棋盘右边的第五线上。

解说席上起了一阵骚动。按人类几百年攒下来的经验，这个位置太高了，像个初学者下的棋。有职业棋手的第一反应是：它下错了。

这一手到底是失误还是妙手，我们过一会儿揭晓。

眼下有个更要紧的问题，请你先想一想：**这步棋，是谁教它的？**

上一章的办法，是给机器看带标准答案的例子。给围棋程序当例子的，当然是人类高手的棋谱：这个局面，高手下在了这儿。可是，没有哪位高手会在那个位置下那样一步棋。它不在任何一张棋谱里。

一个只会照着例子学的东西，是怎么走出一步例子里没有的棋的？

要弄明白这件事，我们得先回答一个朴素得多的问题：中午吃什么。

## 中午吃什么

公司楼下新开了三家小店。实话告诉你，这三家店里，一家十顿只有三顿好吃，一家五顿，一家七顿。可你不知道哪家是哪家，三家看起来都差不多。

接下来的一年，你打算怎么吃？

我猜你的做法和大多数人一样：头几天每家试一次，然后认准印象最好的那家，一直吃下去。稳妥，省心。

还有一种吃法：大部分日子去心里分数最高的那家，但每十天里留出一天，闭着眼随便挑一家。

哪种吃法，一年下来吃得更好？第一种吃法的人，最后有多少真的认准了最好的那家？

先在心里给两个数字，再看程序。我们让 500 个人各吃 1000 顿：

```python
# lunch.py：楼下新开了三家店，只知道每顿好不好吃，该怎么选？
import random

TASTY = [0.3, 0.5, 0.7]      # 三家店“这顿好吃”的真实概率。你并不知道

def one_year(curious, days, rng):
    """curious：有多大比例的日子，你愿意随便换一家试试"""
    visits = [0, 0, 0]
    score = [0.0, 0.0, 0.0]          # 你心里给三家店打的平均分
    happy = 0
    for day in range(days):
        if day < 3:
            shop = day                                   # 头三天，每家吃一次
        elif rng.random() < curious:
            shop = rng.randrange(3)                      # 今天换换口味
        else:
            shop = max(range(3), key=lambda s: score[s])  # 去心里分数最高的那家
        tasty = 1 if rng.random() < TASTY[shop] else 0
        visits[shop] += 1
        score[shop] += (tasty - score[shop]) / visits[shop]
        happy += tasty
    return happy, visits.index(max(visits))

rng = random.Random(42)
for curious in (0.0, 0.1):
    results = [one_year(curious, 1000, rng) for _ in range(500)]
    happy = sum(h for h, _ in results) / 500
    found = sum(1 for _, fav in results if fav == 2) / 5
    name = "认准一家吃到底" if curious == 0 else "十天里有一天换口味"
    print(f"{name}：1000 顿里好吃 {happy:.0f} 顿；最后常去的是最好那家的人占 {found:.0f}%")
```

```
认准一家吃到底：1000 顿里好吃 596 顿；最后常去的是最好那家的人占 63%
十天里有一天换口味：1000 顿里好吃 669 顿；最后常去的是最好那家的人占 98%
```

每十天“浪费”一天去瞎试的人，反而多吃了七十多顿好的。

更值得看的是第一种吃法的后一个数字：63%。也就是说，认准一家的人里，三个就有一个，吃了一辈子不是最好的那家。

为什么？设想一下那位倒霉的同事：他第一次去最好的那家店，恰好赶上师傅发挥失常。于是在他心里，这家店的分数是零。他再也没回去过，也就永远没有机会发现自己错了。

这两种做法各有个名字。去已经知道不错的地方，叫**利用**。去试试不知道的，叫**探索**。只利用不探索，你就会被最初的一点运气困住一辈子。

现在回头想想围棋。照着人类棋谱学，相当于什么？相当于认准了人类去过的那几家店。人类的棋谱再多，也只是所有可能的下法里极小的一块。

不过，在回到首尔之前，请先注意午饭这个例子里一件容易滑过去的事：从头到尾，**没有人告诉你正确答案是哪家店。** 你得到的只是每顿饭之后的一个感受：好吃，或者不好吃。

这和上一章很不一样。上一章，每个例子都附着答案。这里只有打分。做了一个动作，世界回你一个分数，你自己琢磨下回怎么做。这种学法叫**强化学习**。

## 给资料助手造第三块零件：食堂打饭调旋钮

刚才去哪家店吃饭，我们记的是一个账本：每家店吃过几次、平均几分，再留出十分之一的日子换口味。

可我们的资料助手将来要干的事是开口挑词。词典里有几千个词，每个词前面还有千变万化的句子，没法给每种情况单独记一本账。上一章的 `Value` 让我们看清了参数怎样往上调、往下调。这一回先把旋钮当成普通小数，用手写梯度看清更新方向；下面的 `reinforce.py` 不调用 `value.py`，继承的是“按反馈调参数”的思路。

如果没有标准答案，只有一个饭后的打分（好吃是 `1`，不好吃是 `0`），怎么调这些旋钮？

这就好比你在学校食堂打饭，心里有个“平时平均水平”。**今天这盘菜如果比平时好吃，明天就多盛一勺、把另外两道菜少盛一点；如果比平时难吃，明天就绕着这道菜走。**

![[零基础学AI/上册/attachments/Pasted image 20261117122121.png]]

1992 年，Ronald Williams——就是上一章那篇四页反向传播论文的第三位作者——把这句大白话写成了一个通用的算法，起名叫 **REINFORCE**。我们来给资料助手打第三块零件 `reinforce.py`：

```python
# reinforce.py：资料助手的第三块零件。没有标准答案，只靠打分调旋钮
import math, random

TASTY = [0.3, 0.5, 0.7]
logits = [0.0, 0.0, 0.0]                        # 三家店的旋钮，一开始平起平坐
rng = random.Random(42)
avg = 0.5                                       # 心里的“平时水平”

for _ in range(1000):
    exps = [math.exp(l) for l in logits]
    probs = [e / sum(exps) for e in exps]       # 把三个旋钮换算成去三家店的把握（加起来等于 1）
    choice = rng.choices([0, 1, 2], weights=probs)[0]
    reward = 1.0 if rng.random() < TASTY[choice] else 0.0
    adv = reward - avg                          # 这一顿比平时好多少？
    avg = 0.99 * avg + 0.01 * reward
    for i in range(3):
        step = (1.0 if i == choice else 0.0) - probs[i]
        logits[i] += 0.1 * adv * step           # 比平时好就往选的这家挪，不如平时就往反方向挪

exps = [math.exp(l) for l in logits]
print("1000 顿后去三家店的把握：", [round(e / sum(exps), 2) for e in exps])
```

这里连“十分之一的日子换口味”都不用单独写了：只要把握还没涨到 100%，抓阄的时候它自然会偶尔去别的店转转；等哪家店真的全面胜出，把握涨高了，它自己就会收心。跑一下：

```
1000 顿后去三家店的把握： [0.01, 0.01, 0.97]
```

它把 97% 的把握都押在了第三家店上。

请记住 `adv = reward - avg` 那一行：**重要的不是拿了几分，而是比平时多拿了几分。** 到第 05 章教大模型“照人的喜好说话”、第 06 章教模型“自己多想几步”的时候，用的还是这同一把锤子。

## 分数来得太晚怎么办

午饭还有个让人省心的地方：吃完马上就知道好不好吃。

下棋可没这么痛快。一盘棋几百手，中间没有任何人给你打分，只有到最后才有一个结果：赢了，或者输了。

上一章我们是在**空间**（计算图）上倒着做 DP，把误差算回去。现在同一个问题搬到了**时间**上：最后输了，前面两百多步，哪一步该负责？

我们造一个最小的例子来对付它。一个 5×5 的迷宫，`#` 是墙，从左上角的 S 走到右下角的 G：

```
S....
.###.
..C..
.###.
....G
```

规矩很苛刻：只有踩上终点的那一步给 10 分。别的每一步都倒扣 0.1 分，免得它磨蹭。中间那个 C，暂时当它是块普通的空地。

没有地图，没有人指路。它一开始只会乱撞。

动手之前，先想一个问题。假如蒙着眼在里面乱撞的是你，撞上了几百次终点以后，你是怎么慢慢摸出门道的？

你大概会先记住：**终点旁边那一格是个好地方**，因为从那儿再走一步就到了。然后你会发现，能走到那一格的格子，也不错。再然后，能走到“能走到那一格的格子”的格子……

好地方的名声，就这样从终点开始，在时间轴上一格一格地倒着往回传——和上一章的 DP 是同一个路数，只不过现在是边走边用下一步的估计更新这一步。

程序给每个“位置加动作”记一个数，意思是“从这儿这么走，往后一共大概还能拿多少分”。每走一步，就用下面这句话修正一次：

> 我对这一步的估计 ＝ 这一步当场拿到的分 ＋ 我对下一格的估计

它不等终局。它用下一步的估计，来修正这一步的估计。

```python
# maze.py：没有人教它怎么走，只在走到终点时给它 10 分
import random

COIN = "没有"        # 稍后改成 "踩到就给" 或 "走进来才给"

MAP = ["S....",
       ".###.",
       "..C..",
       ".###.",
       "....G"]
MOVES = {"↑": (-1, 0), "↓": (1, 0), "←": (0, -1), "→": (0, 1)}

def step(pos, move):
    r, c = pos[0] + MOVES[move][0], pos[1] + MOVES[move][1]
    if not (0 <= r < 5 and 0 <= c < 5) or MAP[r][c] == "#":
        r, c = pos                                  # 撞墙：原地不动
    reward, done = -0.1, False                      # 每走一步扣 0.1，免得它磨蹭
    if MAP[r][c] == "G":
        reward, done = 10, True
    elif MAP[r][c] == "C":
        if COIN == "踩到就给" or (COIN == "走进来才给" and (r, c) != pos):
            reward += 1
    return (r, c), reward, done

def train(games=3000, seed=0):
    rng = random.Random(seed)
    value = {}                                      # （位置, 动作）→ 它估计的“往后一共还能拿多少分”
    for _ in range(games):
        pos = (0, 0)
        for _ in range(50):                         # 一局最多 50 步
            if rng.random() < 0.1:
                move = rng.choice(list(MOVES))      # 偶尔乱走一步，换换口味
            else:
                move = max(MOVES, key=lambda m: value.get((pos, m), 0.0))
            nxt, reward, done = step(pos, move)
            later = 0.0 if done else max(value.get((nxt, m), 0.0) for m in MOVES)
            old = value.get((pos, move), 0.0)
            value[(pos, move)] = old + 0.5 * (reward + 0.95 * later - old)
            pos = nxt
            if done:
                break
    return value

def play(value):
    pos, path, total, done = (0, 0), [], 0.0, False
    for _ in range(50):
        move = max(MOVES, key=lambda m: value.get((pos, m), 0.0))
        pos, reward, done = step(pos, move)
        path.append(move)
        total += reward
        if done:
            break
    shown = " ".join(path[:14]) + (" ……" if len(path) > 14 else "")
    print(f"金币：{COIN}")
    print(f"它的走法：{shown}")
    print(f"结果：{'到了终点' if done else '50 步用完，没到终点'}，一共 {total:.1f} 分")

def show_map(value):
    print("它心里的地图（站在每一格，估计往后还能拿多少分）：")
    for r in range(5):
        row = []
        for c in range(5):
            if MAP[r][c] in "#G":
                row.append(" 墙  " if MAP[r][c] == "#" else "终点 ")
            else:
                row.append(f"{max(value.get(((r, c), m), 0.0) for m in MOVES):4.1f} ")
        print("".join(row))

if __name__ == "__main__":
    value = train()
    play(value)
    if COIN == "没有":
        show_map(value)
```

`train` 里带 `0.95` 的那一行，就是上面那句话（`0.95` 的意思是：晚拿到的分，稍微打点折）。其余的你都见过：`0.1` 的机会乱走一步，是在“换口味”。

让它练三千局，然后看它怎么走。走几步能到？

```
金币：没有
它的走法：↓ ↓ → → → → ↓ ↓
结果：到了终点，一共 9.3 分
它心里的地图（站在每一格，估计往后还能拿多少分）：
 6.4  6.8  7.3  7.8  8.3 
 6.8  墙   墙   墙   8.8 
 7.3  7.8  8.3  8.8  9.4 
 6.8  墙   墙   墙  10.0 
 5.2  7.5  9.1 10.0 终点 
```

八步，一步冤枉路都没有。

下面那张数字表更值得看，那是它心里的地图。

![[零基础学AI/attachments/第 03 章｜没有标准答案，怎样越练越强？/Ov3RbToqtoeFpSxVFqjcofHLnhc.png|它心里的地图：分数从终点开始，一格一格往回渗。]]

我们只在终点给过分。可是现在，每一格上都有了一个数，而且离终点越近数越大。站在起点，它不需要“看见”终点，只需要往数大的那边迈一步。

这个“我现在的处境有多好”的估计，有个正式的名字，叫**价值**。它就是“账该算在谁头上”的答案：不用等到终局再回头分功劳，每一步都当场记一笔。

这个主意不新。早在 1959 年，IBM 的 Arthur Samuel 就让一个程序用类似的办法学下跳棋，“机器学习”这个词就是他那篇论文带火的。上一章结尾提到的那件事，是这个主意第一次真正惊到人。

1992 年，IBM 的研究员 Gerald Tesauro 让一个神经网络自己和自己下西洋双陆棋。它每走一步，就估计一次“我现在有几成胜算”，再用下一步的估计来修正。没有棋谱，没有老师。它和自己下了一百多万盘。

![[零基础学AI/attachments/第 03 章｜没有标准答案，怎样越练越强？/Y2lAbbaHhox0LpxXnjbcvw7tnNd.png|没有棋谱，没有老师。对手是它自己。]]

这个叫 TD-Gammon 的程序，最后的水平逼近了当时世界上最好的人类棋手。更有意思的是后面的事：有几种开局，它的走法和高手们沿用了多年的走法不一样。高手们拿它的走法去比赛里试，发现它是对的。没过几年，老走法在比赛里几乎绝迹了。

人开始跟机器学下棋了。不过那是西洋双陆棋。轮到围棋，还要再等二十四年。

## 回到首尔

现在可以回大厅了。你手里已经有了看懂 AlphaGo 的全部零件。

![[零基础学AI/attachments/第 03 章｜没有标准答案，怎样越练越强？/UxUZbVwXUo30JHxEYAJc1PvxnAg.png|AlphaGo 的三样本事：直觉和判断是学出来的，推演是算出来的。]]

**直觉**：面对一个局面，哪几个落点有戏。这是一个很深的神经网络，它先看了大量人类高手的棋谱，这是上一章的办法。然后它开始和自己下棋，赢了的下法多用，输了的少用，这是这一章的办法。

**判断**：这个局面，我有几成胜算。这就是迷宫里那张数字地图，只不过格子换成了围棋的局面，查表换成了另一个神经网络。

**推演**：顺着直觉推荐的那几手往后算，算到一定深度，用判断来打分。深蓝也推演，可它是每条路都算；AlphaGo 只算有戏的那几条。

规则写不出来的“棋感”，它用学的办法补上了。从第 01 章走到这儿，这是一次完整的示范：**写不出规则的地方，让它自己学。**

那么，第 37 手呢？

AlphaGo 赢了第二局。复盘的时候，越来越多的棋手说，第 37 手是这盘棋的胜负手，而且，很美。

赛后 DeepMind 公布了一个数字。按 AlphaGo 自己从人类棋谱里学来的直觉估算，一位人类棋手在那个局面下出这一手的可能性，大约是万分之一。

它知道人不会这么下。它还是下了。

因为在它和自己对弈的那几百万盘棋里，它偶尔“换过口味”，试过人类没走过的地方，然后它心里那张地图告诉它：这么下，赢得多。

五局棋的最终比分是 4 比 1。李世石赢的是第四局。那一局他的第 78 手，同样出乎所有人的意料，也同样被估计为万分之一的一手，后来被棋迷称作“神之一手”。

一年多以后的事情更干脆。2017 年 5 月，乌镇，新版 AlphaGo 三比零赢了当时世界排名第一的柯洁。同年 10 月，DeepMind 发表了 AlphaGo Zero：它**一张人类棋谱都不看**，只知道规则，从乱下开始，自己和自己练。三天以后，它和打败李世石的那个版本下了一百盘。

一百比零。

人类几千年攒下的棋谱，在这里成了可有可无的东西。读到这里你也许有点兴奋，也许有点不安。两种感觉都对。

但请记住它成立的三个条件，后面的章节会一再用到：**规则是清楚的，输赢是明确的，可以不花本钱地练上几百万盘。** 围棋三样都有。“给新同事写一份上手指南”，三样都没有。

## 趁热打铁，给迷宫加点甜头

回到我们的小迷宫，做一个你一定会想做的改进。

只有终点给分，它一开始撞来撞去，很久才能碰巧撞上一次终点，学得很慢。那我们帮帮它：在必经之路的正中间放一枚金币，踩到就加 1 分。半路给点甜头，引着它往终点走。

很合理吧？做老师的都这么干。

把 `maze.py` 第四行的 `COIN = "没有"` 改成 `COIN = "踩到就给"`，再练一次。你猜它会怎么走？

```
金币：踩到就给
它的走法：↓ ↓ → → ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ↑ ……
结果：50 步用完，没到终点，一共 42.0 分
```

42 分。比老老实实走到终点的 9.3 分高出一大截。

可它没到终点。看它的走法：下，下，右，右，然后一直“上，上，上，上……”

金币上面那一格是墙。它站在金币上往墙上撞，撞墙等于原地不动，原地不动等于又“踩”了一次金币。每撞一下，净赚 0.9 分。它一口气撞了 46 下。

我得坦白：写这段代码的时候，我想的只是“路过金币，顺手加一分”。撞墙也算踩到，是我没想到的。真实世界里的漏洞多半就是这样来的：不是谁故意留的，只是没想到。

没关系，补上就好。把那一行再改成 `COIN = "走进来才给"`：必须从别的格子走进金币格，才算数。撞墙不算了。

这回它该去终点了吧？

```
金币：走进来才给
它的走法：↓ ↓ → → ← → ← → ← → ← → ← → ……
结果：50 步用完，没到终点，一共 19.0 分
```

右，左，右，左，右，左。

它在金币格和旁边那一格之间来回踱步，每进一次门，领一次赏。19 分，还是比去终点划算。

![[零基础学AI/attachments/第 03 章｜没有标准答案，怎样越练越强？/Bz1ybqbvmoTi0xx3HefcJklnnfc.png|分数怎么给，它就怎么学。]]

打了一个补丁，冒出一个新漏洞。这个滋味，你在第 01 章尝过。

当然可以再补：金币每局只许领一次行不行？

行，不过动手前还得改一个小地方。上一次来金币格，还没领过，应该有奖；下一次回到同一个格子，已经领过了，就没有奖。如果程序只记坐标，这两种处境在它眼里一模一样。**位置一样，事情已经变了。** 所以状态里必须多记一件事：`本局是否已经领过金币`。

把四种模式各自用 10 个随机种子跑一遍，结果是这样的：

| 奖励方式 | 50 步内到终点的次数 | 种子 0 的情况 |
|-|-|-|
| 不给金币 | 10 / 10 | 8 步到达，9.3 分 |
| 只要还在金币格就给 | 0 / 10 | 撞墙领钱，42.0 分 |
| 每次从别处走进来才给 | 2 / 10 | 来回领钱，19.0 分 |
| 每局只给一次，并记录是否领过 | 10 / 10 | 8 步到达，10.3 分 |

每局只给一次、且把“领没领过”写进状态以后，它终于又老老实实 8 步走到了终点。可别忘了：原来不发金币的版本本来就能 10/10 到达终点，不能因为 `10.3` 比 `9.3` 高，就以为中途加金币变强了——计分规则变了，总分不能横着比。

更重要的是，请想想我们刚才在做什么：我们本来只想说一句“请走到终点”，结果却在和一个 25 格的迷宫斗智斗勇。

这不是玩具才有的毛病。2016 年底，OpenAI 的研究者发了一篇博客，讲他们训练程序玩一个赛艇游戏。人人都知道这游戏该干什么：把船开到终点。他们给程序的分数，用的是游戏里现成的得分。

程序在赛道边上发现了一小片水湾。水湾里有三个得分的靶子，撞掉以后过一会儿会重新冒出来。于是它就不走了。它在水湾里一圈一圈地转，掐着时间把刚冒出来的靶子再撞掉。船撞了墙，着了火，逆行了，都不要紧。它一次也没跑完过比赛，得分却比人类玩家平均高出 20%。

![[零基础学AI/attachments/第 03 章｜没有标准答案，怎样越练越强？/WKMqbUnAeo7JfIxQqJIcH3V2nhh.png|它一次也没跑完过比赛。得分比人类玩家高 20%。]]

它作弊了吗？

没有。它做的，正是我们写下来的那件事：拿高分。只不过，“拿高分”和我们心里想的“赢比赛”，中间有一条缝。

**分数只是目标的替身。** 一个足够卖力的学习者，会把替身和目标之间的每一条缝都找出来。

## 给资料助手的回答打分

这件事和我们的资料助手有什么关系？关系很大。

将来我们想让它不只会给问题分类，还要会回答问题，并且越答越好。越答越好，就得先说清楚什么叫“好”。也就是说，我们得写一个打分的办法。

试试看。一个直觉上很合理的想法：回答里和问题重合的字越多，说明越切题；回答越长，说明越详细。

准备四个候选回答：一个认真的，一个简短的，一个“不知道”，还有一个我故意写的。你先读一读代码里的四个回答，猜猜哪个得分最高：

```python
# reward.py：资料助手 v0.3，给回答打分，再看最高分的回答是什么
question = "账号怎么申请？"

candidates = [
    "请在入职系统提交账号申请，经理审批后即可开通。",
    "账号申请见上手指南第一节。",
    "不知道。",
    "账号账号申请申请，账号怎么申请？申请账号很重要，账号申请请申请账号，"
    "关于账号申请，我们需要了解账号申请的流程，账号申请就是申请账号。",
]

def score_v1(answer):
    """第一版打分：和问题重合的字越多越好，越详细越好"""
    overlap = sum(answer.count(ch) for ch in set(question) if ch not in "？")
    return overlap + len(answer) / 10

def score_v2(answer):
    """第二版打分：重合的字只算一次，长度封顶 30 字"""
    overlap = len(set(question) & set(answer) - {"？"})
    return overlap + min(len(answer), 30) / 10

for name, score in (("第一版", score_v1), ("第二版", score_v2)):
    print(f"== {name}打分")
    for ans in sorted(candidates, key=score, reverse=True):
        print(f"{score(ans):5.1f}  {ans[:24]}{'……' if len(ans) > 24 else ''}")
```

```
== 第一版打分
 49.6  账号账号申请申请，账号怎么申请？申请账号很重要，……
  7.3  请在入职系统提交账号申请，经理审批后即可开通。
  5.3  账号申请见上手指南第一节。
  0.4  不知道。
== 第二版打分
  9.0  账号账号申请申请，账号怎么申请？申请账号很重要，……
  6.3  请在入职系统提交账号申请，经理审批后即可开通。
  5.3  账号申请见上手指南第一节。
  0.4  不知道。
```

第一版打分，那段翻来覆去念叨“账号申请”的废话得了 49.6 分，认真回答的那一句只有 7.3 分。

我们打个补丁（是的，又是补丁）：重合的字只算一次，长度封顶 30 个字。结果在下半段：废话 9.0 分，认真的回答 6.3 分。还是废话赢。

别光靠猜。我们手里已经有 `reinforce.py` 里的那套“比平时好就多盛一勺”的调旋钮规则，干脆让资料助手**真的追着 `score_v2` 练上 500 轮**，看看它会说出什么话来：

```python
# babble.py：让资料助手追着 score_v2 练 500 轮，亲眼看它会练出什么话
import math, random
from reward import score_v2

words = ["账号", "申请", "软件", "安装", "怎么", "请在", "系统", "审批", "即可", "开通"]
logits = [0.0] * len(words)
rng = random.Random(7)
avg = 0.0

for step in range(1, 501):
    exps = [math.exp(x) for x in logits]
    probs = [e / sum(exps) for e in exps]
    picks = rng.choices(range(len(words)), weights=probs, k=8)
    sent = "".join(words[i] for i in picks) + "。"
    r = score_v2(sent)
    adv = r - avg
    avg = 0.95 * avg + 0.05 * r
    for idx in picks:
        for i in range(len(words)):
            logits[i] += 0.05 * adv * ((1.0 if i == idx else 0.0) - probs[i])
    if step in (1, 50, 500):
        print(f"第 {step:3d} 轮（{r:.1f} 分）：{sent}")
```

来看看它这 500 轮的“进步”：

```
第   1 轮（5.7 分）：安装申请系统账号请在安装账号请在。
第  50 轮（5.7 分）：账号系统怎么怎么账号账号账号账号。
第 500 轮（5.7 分）：账号账号账号怎么账号账号安装即可。
```

第 1 轮，它还在说“请在”“系统”。练到第 500 轮，它发现只要把“账号”“怎么”凑齐就能稳稳拿满基础分，干脆把“审批”“开通”全扔了，满嘴念叨“账号账号账号怎么账号”。

赛艇在水湾里转圈，是别人的故事。这三行输出，是你亲手写出来的程序，在你自己的电脑上转出来的圈。

![[零基础学AI/attachments/第 03 章｜没有标准答案，怎样越练越强？/TZhrbhx7bo9yHPxqov3cJz5Entg.png|你想要的，你写下的，它学会的。]]

那怎么办？规则写的分数总有漏洞，那就别用规则打分了，让人来打。找两个回答，请人看看哪个更好；这样比上几万次，再训练一个模型去模仿人的口味。

这个主意，后来真的成了让大模型“听懂人话”的关键一步，第 05 章会讲。

不过，你现在读到这个主意，心里应该已经亮起了一盏小灯：人的口味，就不是替身了吗？人喜欢什么样的回答？喜欢口气笃定的。喜欢夸自己的。喜欢顺着自己说的。

一个足够卖力的学习者，会把这些也都找出来。
