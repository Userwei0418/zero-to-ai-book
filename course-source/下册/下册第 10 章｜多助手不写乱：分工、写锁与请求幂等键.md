## 几个帮手一起干活，为什么反而把账本写坏了？

上册第 12 章讲过，一件事拆给几个助手干（比如一个负责翻《上册》搜集知识点，一个负责核对出处，一个负责写进长期记忆），听起来很美，一跑起来却到处是撞车现场：

1. **并发写花文件（Lost Update）**：线程 A 和线程 B 同时调用 `publish_l1()`。俩人几乎同一毫秒读出旧的 `l1_atoms.jsonl`，各自在内存里加上一条新记录，然后先后调用 `open(..., "w")` 写回硬盘——后写完的线程 B 把线程 A 刚写进去的那一行彻底抹掉了。
2. **网络重试导致重复入库**：客户端发了一条整理请求，服务端其实已经执行完了，但回执在半路超时。客户端照着重试逻辑又发了一遍同一条请求，结果 `l0_events.jsonl` 和 `l1_atoms.jsonl` 里多出了两条一模一样的记录，版本号也被白白顶到了 `v2`。
3. **搜集员瞎编行号，整理员照单全收**：搜集员摘录了一句“答对了不等于弄懂了”，顺手编了一个 `[第 01 章｜规则总也写不完.md:99999]`。如果入库前没人去原文件核对一眼第 99999 行到底存不存在，这条假出处就会堂而皇之地写进长期记忆。

## 三道并发治理铁律：单写者锁 + 请求幂等键 + 独立出处审查

我们在 `课件/ch10/worker.py` 里把企业级多智能体后台的三道核心防线写成了不到一百行标准库代码：

### 1. 独立只读审查员（`verify_citation`）

上册第 12 章做过那个实验：“无源审查”光看答卷文字根本抓不出编号错位，必须给审查员看原始材料。

对于文件与行号核对，最稳的审查员甚至不需要调大模型——直接写一个只读函数 `verify_citation(filename, line_no)`：真正去硬盘上打开《上册》里的那个文件，数一数总行数，检查 `1 <= line_no <= len(lines)`。文件不存在或行号越界，当场退回（`rejected_citation`）。

### 2. 单写者文件锁（`fcntl.flock(..., LOCK_EX)`）

所有只读检索（`search.py`、`read_note`）随便多少个线程一起跑；但凡要进 `safe_publish()` 修改状态文件和记忆账本，必须先打开锁文件 `kb_write.lock`，向操作系统申请排他锁 `fcntl.LOCK_EX`。没抢到锁的线程自动在门外排队，等前一个线程写完落盘、`LOCK_UN` 释放锁之后，下一个才能进门。

### 3. 请求幂等键（`request_id` + `idempotency.json`）

每个写请求进门前都必须带一张唯一的身份证号 `request_id`。抢到文件锁后的第一件事，是先翻开 `idempotency.json` 查这个 `request_id` 以前办过没有：

- 如果已经办过了，直接返回 `{"status": "dedup_hit", "atom_id": 原来的结果}`，绝不再写第二遍；
- 如果没办过，才真正写入 L0 与 L1，并在放锁前把 `request_id -> atom_id` 记进幂等账本。

## 完整并发治理实现：`worker.py`

```python
# worker.py：第 10 章实战成品——多助手并发治理（单写者文件锁 + 请求幂等键 + 独立出处核对）
import fcntl
import json
import os
import sys
import threading
import time

sys.path.insert(0, os.path.abspath(os.path.join(os.path.dirname(__file__), "../ch09")))
import memory

STATE_DIR = os.path.join(os.path.dirname(__file__), "worker_state")
LOCK_PATH = os.path.join(STATE_DIR, "kb_write.lock")
IDEM_PATH = os.path.join(STATE_DIR, "idempotency.json")
KB_ROOT = os.path.abspath(os.path.join(os.path.dirname(__file__), "../../../上册"))


def verify_citation(filename, line_no):
    """独立只读审查员：核对宣称的 [文件名:行号] 是否真实存在于上册目录内。"""
    p = os.path.abspath(os.path.join(KB_ROOT, filename))
    if not p.startswith(KB_ROOT + os.sep) or not os.path.isfile(p):
        return False, f"文件不存在：{filename}"
    lines = open(p, encoding="utf-8").read().splitlines()
    if not (1 <= int(line_no) <= len(lines)):
        return False, f"行号越界：{filename}:{line_no}（共 {len(lines)} 行）"
    return True, lines[int(line_no) - 1][:60]


def safe_publish(request_id, topic, key, fact, source_file, source_line):
    """拿到单写者锁后先查幂等表，再核对出处，通过后才写入 L1 记忆。"""
    os.makedirs(STATE_DIR, exist_ok=True)
    with open(LOCK_PATH, "w", encoding="utf-8") as lock_f:
        fcntl.flock(lock_f, fcntl.LOCK_EX)
        try:
            idem = json.load(open(IDEM_PATH, encoding="utf-8")) if os.path.exists(IDEM_PATH) else {}
            if request_id in idem:
                return {"status": "dedup_hit", "request_id": request_id, "atom_id": idem[request_id]["atom_id"]}

            ok, detail = verify_citation(source_file, source_line)
            if not ok:
                return {"status": "rejected_citation", "reason": detail}

            ev = memory.record_l0("worker", "system", f"[{source_file}:{source_line}] {fact}")
            atom = memory.publish_l1(topic, key, fact, [ev["event_id"]])
            idem[request_id] = {"atom_id": atom["atom_id"], "at": time.strftime("%H:%M:%S")}
            with open(IDEM_PATH, "w", encoding="utf-8") as f:
                json.dump(idem, f, ensure_ascii=False, indent=2)
            return {"status": "written", "request_id": request_id, "atom_id": atom["atom_id"]}
        finally:
            fcntl.flock(lock_f, fcntl.LOCK_UN)


if __name__ == "__main__":
    for p in (IDEM_PATH, memory.L0_PATH, memory.L1_PATH):
        if os.path.exists(p):
            os.remove(p)

    results = []
    def task(rid, fact, line):
        results.append(safe_publish(rid, "并发测试", "规则教训", fact, "第 01 章｜规则总也写不完.md", line))

    # 模拟并发：两个线程拿同一个 req_001 重试，第三个线程拿假行号 99999
    threads = [
        threading.Thread(target=task, args=("req_001", "答对了不等于弄懂了", 131)),
        threading.Thread(target=task, args=("req_001", "答对了不等于弄懂了", 131)),
        threading.Thread(target=task, args=("req_002", "编造的结论", 99999)),
    ]
    for t in threads:
        t.start()
    for t in threads:
        t.join()

    for r in results:
        print(r)
```

## 故意弄坏它：三线程并发撞锁、重发与假行号测试

直接运行 `python3 课件/ch10/worker.py`，三个线程同时冲向 `safe_publish()`：

- 线程 1 和线程 2 拿着同一个请求编号 `req_001`（模拟超时重发或并发双击）；
- 线程 3 拿着 `req_002`，但声称出处在《第 01 章》的第 `99999` 行。

看真实输出：

```
{'status': 'written', 'request_id': 'req_001', 'atom_id': 'A-9a4de3c0'}
{'status': 'rejected_citation', 'reason': '行号越界：第 01 章｜规则总也写不完.md:99999（共 615 行）'}
{'status': 'dedup_hit', 'request_id': 'req_001', 'atom_id': 'A-9a4de3c0'}
```

三件事各归各位：
1. 先抢到锁的 `req_001` 核对第 131 行无误，成功写入，拿到 `A-9a4de3c0`；
2. 后进门的 `req_001` 在幂等表里看到这个编号已经办过了，直接返回 `dedup_hit` 和同一个 `A-9a4de3c0`，`l1_atoms.jsonl` 里只有唯一的一条 `v1`；
3. 假行号 `99999` 被只读审查员当场识破（《第 01 章》一共才 615 行），直接拒之门外。

> **老办法，新地方**
>
> “多读者并发、单写者串行（Single-Writer Principle）+ 幂等键（Idempotency Key）+ 入库前外键存在性校验”，这是高并发交易系统和分布式消息队列用了几十年的看家本领。多 Agent 系统再花哨，落到改状态那一刻，依然是个标准的并发工程问题。
