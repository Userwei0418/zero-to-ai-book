## 脱口而出

上一章结尾那道题，你报的是多少？

再看一遍题目：新同事第一天要办四件事。账号审批，30 分钟。下载工具包，20 分钟。安装工具，15 分钟，要等前两件都办完才能开始。环境自检，10 分钟，要等安装完。人手管够，能同时办的可以同时办。最快多久能全部办完？

现在请你拿出纸笔，画一画。画完再往下看。

审批和下载同时开始。下载 20 分钟就好了，可安装还得等审批，所以最早第 30 分钟才能装。装到 45，检到 55。

**55 分钟。**

如果你刚才脱口而出的是 75 或者 45，别不好意思。你不是不会算，你只是答得太快了。一拿起笔，你就算对了。

那么，我们的资料助手呢？

上一章，它把任务卡做得漂漂亮亮。这道题要求清楚，条件齐全，没有一个字含糊，按说难不倒它。我们把同一道题换十二组数字（审批时间取 20、30、40，下载时间取 10、20、30、40），准备好题目和标准答案：

```python
# puzzle.py：同一道排期题，换十二组数字
import re

def text(a, b):
    return (f"新同事第一天要办四件事。账号审批，{a} 分钟。下载工具包，{b} 分钟。"
            "安装工具，15 分钟，要等前两件都办完才能开始。环境自检，10 分钟，要等安装完。"
            "人手管够，能同时办的可以同时办。最快多久能全部办完？")

def truth(a, b):
    return max(a, b) + 15 + 10          # 审批和下载同时开始，等慢的那个，再装，再检

puzzles = [(a, b) for a in (20, 30, 40) for b in (10, 20, 30, 40)]

def last_number(reply):
    """从它的回答里，取最后出现的那个数"""
    found = re.findall(r"\d+", reply)
    return int(found[-1]) if found else None
```

调用模型还是用上一章的 `llm.py`（接的还是商汤 Token Plan 的 `https://token.sensetime.com/api/v1`，默认用 `sensenova-6.8-flash`）。这一章给它加了两个小开关：可以调温度，也可以让它顺便告诉我们这次写了多少 token。另外，网络偶尔会断，所以它会自动重试。

**先给这页账本贴个标签：下面的通过率、回答和 token 数保留自原教材，不是本版商汤接口重新跑出的成绩。原教材来源说明记为 2026 年 11 月、SenseAudio 平台，默认 `senseaudio-s2-flash`，大一号为 `senseaudio-s2`，推理模型为该平台上的 `deepseek-v4.1-flash`。具体运行日、权重版本、当时完整代码版本和原始日志对应关系尚未核验；本版接口也未据此重测。**

```python
# llm.py：和上一章是同一个函数，多了两个开关：temperature，和“把花掉的 token 数也告诉我”
import json, os, time, urllib.request

def chat(messages, json_mode=False, temperature=0, want_usage=False):
    if isinstance(messages, str):
        messages = [{"role": "user", "content": messages}]
    body = {
        "model": os.environ.get("LLM_MODEL", "sensenova-6.8-flash"),
        "messages": messages,
        "temperature": temperature,
    }
    if json_mode:
        body["response_format"] = {"type": "json_object"}
    base_url = os.environ.get("LLM_BASE_URL", "https://token.sensetime.com/api/v1").rstrip("/")
    req = urllib.request.Request(
        base_url + "/chat/completions",
        data=json.dumps(body).encode("utf-8"),
        headers={"Content-Type": "application/json",
                 "Authorization": "Bearer " + os.environ["LLM_API_KEY"]},
    )
    for attempt in range(3):                       # 网络偶尔会断，最多试三次
        try:
            with urllib.request.urlopen(req, timeout=180) as resp:
                data = json.load(resp)
            break
        except (OSError, ValueError):
            if attempt == 2:
                raise
            time.sleep(2)
    text = data["choices"][0]["message"]["content"].strip()
    if want_usage == "all":
        return data                                                      # 原样返回，给想看细节的人
    if want_usage:
        return text, data.get("usage", {}).get("completion_tokens", 0)   # 它写了多少 token
    return text
```

然后像刚才对你那样，让它凭第一感觉报数：

```python
# quick.py：不许想，直接报数

from puzzle import text, truth, puzzles, last_number

right = spent = 0
for a, b in puzzles:

print(f"答对 {right}/{len(puzzles)}，平均每题写了 {spent / len(puzzles):.0f} 个 token")
```

## 2022 年的岔路口

这不是今天才有的毛病。ChatGPT 上线之前，GPT-3 就这样：写文章头头是道，碰到要拐几个弯的题目，张口就错。

假设现在是 2022 年初，你在研究这个问题。你会从哪儿下手？

**一条路：做大。** 模型再大十倍，也许它就会算了。刚才我们看到了，大一号的模型确实好一点。

**另一条路：专门教。** 上一章教它“听话”用的那一套，拿来教它“算数”：攒几万道带详细解答的题，让它练。

两条路听着都靠谱，也都很贵。

那一年，有人走了第三条路。这条路便宜到近乎荒唐，说出来像个玩笑：**在题目后面加一句话。**

先别往下看。猜猜是哪句话。

2022 年 5 月，东京大学和 Google 的几位研究者发了一篇论文。他们在题目后面加了一句英文：“Let's think step by step.” 让我们一步一步想。

模型没换，题目没换。在一套算术题上，他们报告的正确率从 17.7% 涨到了 78.7%。

（再早几个月，Google 的另一组人做过类似的事：在题目前面放几道写了详细步骤的例题，模型就会学着也把步骤写出来。这个办法叫思维链，英文缩写 CoT。五月的这篇论文发现，连例题都不用给，一句话就行。）

我们来试。还是那十二道题，还是那个只对了两道的模型，只把最后那句“只回答一个数字”换成“请一步一步想”：

```python
# steps.py：还是那个模型，只多说一句话
from llm import chat
from puzzle import text, truth, puzzles, last_number

right = spent = 0
for i, (a, b) in enumerate(puzzles):
    reply, tokens = chat(text(a, b) + "请一步一步想：先写出每件事最早几分开始、几分结束，最后一行只写答案的数字。", want_usage=True)
    got = last_number(reply)
    right += got == truth(a, b)
    spent += tokens
    if i == 1:
        print("—— 审批 20、下载 20 那一题，它写的是 ——")
        print(reply)
        print("——")
print(f"答对 {right}/{len(puzzles)}，平均每题写了 {spent / len(puzzles):.0f} 个 token")
```

回到岔路口。做大没有错，专门教也没有错，后来这两条路都有人走，都走通了（这一章后面会讲）。可在它们之前，有人先发现了一件事：**这个模型本来就会算。它只是没有被允许去算。**

为什么一句话就能让它“被允许”？

## 它说出来的话，就是它的草稿纸

这件事的答案，你在第 04 章就已经拿到了。

模型只做一件事：根据前文，接下一个词。

你问它题目，并且要求“只回答一个数字”。这时候，它面前的前文只有题目。它必须在接下一个词的那一下子里，把四个数、三层先后关系全部处理完，直接吐出答案的第一个数字。

这就好比不许你动笔，题目念完，立刻报数。

而当它被允许一步一步写的时候，情况完全不同了。它先写下“审批 0 到 30，下载 0 到 20”。这一行一旦写出来，**就成了前文的一部分**。接下去它只需要回答一个小得多的问题：前文里写着两件事分别在 30 和 20 结束，那么安装最早什么时候开始？这个它接得住。写下“30”，又成了前文。再往前挪一小步。

![[零基础学AI/attachments/第 06 章｜回答太快，那就多想一会儿？/Bv9qbwYzwoR5qSxAZn0c4R9Bnud.png|它没有草稿纸。它说出来的话，就是它的草稿纸。]]

人有脑子里的草稿，也有纸上的草稿。它两样都没有。它唯一能“记下来”的地方，就是它自己正在写的那段话。

所以，不让它写，就等于不让它想。

也顺便回看一眼第 04 章（上）我们自己手搓的那个 592 参数 `mini_gpt.py`：为什么不让它也“一步一步想”？因为它肚子里只见过几句固定规矩，连基本的加减和先后关系都没见过多少。**“一步一步想”能管用，前提是模型底子里本来就装过这些步骤的规律**；把草稿纸递给一个还没认全字的婴儿，纸再大也画不出算式。

即便对大模型，这个道理也有三个容易踩的坑，先提醒你。

**第一，写出来的步骤，不是它脑子里的录像。** 那一段推导是它“接”出来的文字，读着像思考过程，可它内部到底是怎么算的，这段文字并不保证如实反映。别因为步骤写得漂亮，就认定它是这么想的。

**第二，步骤写得漂亮，不等于答案对。** 第一步错了，后面每一步都会沿着错的往下走，最后交给你一篇逻辑严密、层次分明的错误。而且这种错比脱口而出的错更唬人。

**第三，想是要花钱的。** 回头看两次输出的最后一行。脱口而出，平均每题 3 个 token。一步一步想，455 个。贵了一百五十倍，也慢了一大截。

第三条让人心疼。有没有便宜点的办法？

## 多答几次，行不行

你可能已经有了个主意：不让它长篇大论，还是让它直接报数，但是**多报几次**，取多数。一个人蒙不准，五个人投票总该靠谱点吧？

每次 3 个 token，五次才 15 个，比 455 便宜多了。

为了让五次的回答有所不同，我们把第 04 章学过的温度调到 1。动手之前，先猜它能对几道：

```python
# vote.py：不许想，但可以多答几次，少数服从多数
from collections import Counter
from llm import chat
from puzzle import text, truth, puzzles, last_number

right = spent = 0
for a, b in puzzles:
    answers = []
    for _ in range(5):
        reply, tokens = chat(text(a, b) + "只回答一个数字，不要任何解释。", temperature=1, want_usage=True)
        answers.append(last_number(reply))
        spent += tokens
    winner = Counter(answers).most_common(1)[0][0]
    right += winner == truth(a, b)
    print(f"审批 {a} 下载 {b}：五次答 {answers}，多数是 {winner}，应为 {truth(a, b)}", "✓" if winner == truth(a, b) else "✗")
print(f"答对 {right}/{len(puzzles)}，平均每题写了 {spent / len(puzzles):.0f} 个 token")
```

投票能管用，得有个前提：大家各错各的，错得互不相干，这样错误才会相互抵消。可这五次回答是同一个模型、带着同一个毛病答出来的。它们会一起错。

**五份一样的答案，不是五份证据。它是一份证据，抄了五遍。**

这句话请记住。到第 12 章我们请好几个 AI 助手一起干活的时候，同一个问题会换个样子再来：让同一个模型扮成“审查员”去检查它自己写的东西，算不算多了一双眼睛？

（公平地说，“多答几次再投票”本身是个正经办法，也是 2022 年提出来的，论文里叫 Self-Consistency。只不过它是配着“一步一步想”用的：让模型把推导写上好几遍，每遍走不同的推导路线，这时候投票才有的可投。）

> 📎
>
> **再多走一步：要是路线会分叉呢？** 刚才的排期题只有一条主线；如果在真实项目里加上一句限制——比如“审批和下载都要占同一条内网通道，同一时间只能办一件”——事情就会立刻分出两条路：“先审批再下载”，或者“先下载再审批”。一条草稿顺着第一条路写下去，很难半路自己跳出来比第二条。这时候，与其让模型自己乱蒙，不如让外面的程序把它拆成几条分支分别让模型算，最后把不通的枝剪掉、留最快的那一支。这就是后来的**思维树（Tree of Thoughts）**——听上去玄乎，其实只是把“画草稿”变成了“程序管分叉，模型算每一支”。

## 让程序来把关

换一个思路。与其指望它多答几次蒙对，不如找一个**不会跟着它一起错**的东西来检查。

这道题有个好处：一份安排对不对，是可以一条一条核对的。每件事的时长对不对？有没有哪件事抢在了它该等的事前面？这些，一段普通的程序就能查，而且查一万遍都不会累，也不会被说服。

```python
# verify.py：把“看着合理”换成“查得出来”
def verify(plan, a, b):
    """plan 形如 {"审批": [0, 30], "下载": [0, 20], "安装": [30, 45], "自检": [45, 55]}
    返回 (哪里不对, 全部办完的时间)。第一项是 None，表示这份安排行得通。"""
    need = {"审批": a, "下载": b, "安装": 15, "自检": 10}
    wait = {"安装": ["审批", "下载"], "自检": ["安装"]}
    if not isinstance(plan, dict) or set(plan) != set(need):
        return "四件事要一件不多、一件不少", None
    for job, minutes in need.items():
        span = plan[job]
        if not (isinstance(span, list) and len(span) == 2 and all(isinstance(x, int) for x in span)):
            return f"{job}：要写成 [开始, 结束] 两个整数", None
        if span[0] < 0 or span[1] - span[0] != minutes:
            return f"{job}：要花 {minutes} 分钟，你写的起止时间对不上", None
    for job, before in wait.items():
        for other in before:
            if plan[job][0] < plan[other][1]:
                return f"{job}：不能在{other}办完（第 {plan[other][1]} 分钟）之前开始", None
    return None, max(span[1] for span in plan.values())

if __name__ == "__main__":
    plans = {
        "同时办": {"审批": [0, 30], "下载": [0, 20], "安装": [30, 45], "自检": [45, 55]},
        "抢着装": {"审批": [0, 30], "下载": [0, 20], "安装": [20, 35], "自检": [35, 45]},
        "排队办": {"审批": [0, 30], "下载": [30, 50], "安装": [50, 65], "自检": [65, 75]},
    }
    for name, plan in plans.items():
        print(name, verify(plan, 30, 20))
```

先别接模型，我们自己写三份安排给它查。一份是对的；一份“抢着装”，让安装在第 20 分钟就开始；一份“排队办”，四件事一件接一件。猜猜它对这三份各会说什么？

```
同时办 (None, 55)
抢着装 ('安装：不能在审批办完（第 30 分钟）之前开始', None)
排队办 (None, 75)
```

第一份，行得通，55 分钟。第二份被拦下了，还说清了错在哪儿。

第三份呢？行得通，75 分钟。

它说得没错：排队办确实一条规矩都没违反。可这不是最快的。

你是不是觉得这个场面有点眼熟？上一章那个放过了错答卷的 `check`，这一章这个放过了慢安排的 `verify`。同一句话，再说一遍：**你查的是什么？你没查的是什么？** 这个检查器查的是“行不行得通”，它不查“是不是最快”。

![[零基础学AI/attachments/第 06 章｜回答太快，那就多想一会儿？/M3nSbKp8BolmQixNmz3cOesonem.png|交上来的安排，先过这一关。]]

顺带一提，怎样才算真正证明了“55 分钟就是最快”？光拿出一份 55 分钟的安排还不够——你还得证明**不可能比 55 更短**。这里只要看两条必走的路：一条是“审批 → 安装 → 自检”（`30 + 15 + 10 = 55`），另一条是“下载 → 安装 → 自检”（`20 + 15 + 10 = 45`）。哪怕人手无限多，较长那条路也得 55 分钟才能走完，这就叫**下界**。当一份可行方案的时间正好碰上下界，你才算把“最快”钉死了。

现在把模型接上。规矩是这样的：不许解释，直接交一份安排，写清四件事各自几分开始、几分结束。交上来先过检查；过不了，就把错在哪儿告诉它，让它重交，最多三次。

```python
# checked.py：不许想，但交上来的安排要过检查；过不了，告诉它错在哪儿，让它重交
import json
from llm import chat
from puzzle import text, truth, puzzles
from verify import verify

ASK = ('不要解释，只输出一个 JSON，写出四件事各自的起止时间（第几分钟），'
       '形如 {"审批": [0, 30], "下载": [0, 20], "安装": [30, 45], "自检": [45, 55]}。')

right = slow = spent = retries = 0
for a, b in puzzles:
    messages = [{"role": "user", "content": text(a, b) + ASK}]
    finish = None
    for attempt in range(3):
        reply, tokens = chat(messages, json_mode=True, want_usage=True)
        spent += tokens
        try:
            problem, finish = verify(json.loads(reply), a, b)
        except ValueError:
            problem = "这不是合法的 JSON"
        if problem is None:
            break
        retries += 1
        messages += [{"role": "assistant", "content": reply},
                     {"role": "user", "content": "这份安排行不通：" + problem + "。请重新给出 JSON。"}]
    right += finish == truth(a, b)
    slow += finish is not None and finish > truth(a, b)
    print(f"审批 {a} 下载 {b}：它排到第 {finish} 分钟办完，最快应为 {truth(a, b)}", "✓" if finish == truth(a, b) else "✗")
print(f"最快的安排 {right}/{len(puzzles)}；行得通但不是最快 {slow} 题；被打回重交 {retries} 次；平均每题写了 {spent / len(puzzles):.0f} 个 token")
```

猜两个数：它能排对几道？中间会被打回几次？

```

审批 20 下载 20：它排到第 45 分钟办完，最快应为 45 ✓
审批 20 下载 30：它排到第 55 分钟办完，最快应为 55 ✓
审批 20 下载 40：它排到第 65 分钟办完，最快应为 65 ✓
审批 30 下载 10：它排到第 55 分钟办完，最快应为 55 ✓
审批 30 下载 20：它排到第 55 分钟办完，最快应为 55 ✓
审批 30 下载 30：它排到第 55 分钟办完，最快应为 55 ✓
审批 30 下载 40：它排到第 65 分钟办完，最快应为 65 ✓
审批 40 下载 10：它排到第 65 分钟办完，最快应为 65 ✓
审批 40 下载 20：它排到第 65 分钟办完，最快应为 65 ✓
审批 40 下载 30：它排到第 65 分钟办完，最快应为 65 ✓
审批 40 下载 40：它排到第 65 分钟办完，最快应为 65 ✓
最快的安排 12/12；行得通但不是最快 0 题；被打回重交 0 次；平均每题写了 43 个 token
```

十二道全对。平均每题 43 个 token，是“一步一步想”的十分之一。

可是请看那个数：**被打回重交 0 次。**

我们辛辛苦苦写的检查器，一次都没派上用场。它每一份都是一次就交对了的。

这和我预想的不一样。我本来以为会看到它交错、被打回、改正的过程。那么，既然检查器根本没出手，它是怎么从 2 道变成 12 道的？

想一想，再往下看。

答案藏在我们让它交的那样东西里。我们没让它报一个总数，我们让它写出**四件事各自的起止时间**。要写出“安装从 30 开始”，它得先写下“审批到 30 结束”。写下来，就成了前文。

我们以为自己在让它“填表”。其实这张表，就是一张最省纸的草稿。

![[零基础学AI/attachments/第 06 章｜回答太快，那就多想一会儿？/Dg80bkuAYoaU74xPFz6cVrmynDc.png|同样的题，四种花法。]]

这是这一章我最想让你带走的东西：**要它写下来的，不必是长篇大论，只要恰好是那几个中间结果。** “一步一步想”有用，不是因为话多，是因为关键的中间结果被写了出来。你要是知道关键的中间结果是什么，直接让它写那几样，又准又省。

那检查器白写了吗？没有。今天十二道题它没出手，不等于明天换一批题它还能闲着。它便宜，不会累，不会被哄；留着它，是一份保险。只是要记得它保的是什么，不保的是什么。

最后还有一句煞风景的实话。这道题，其实根本用不着模型。翻回去看 `puzzle.py` 里的 `truth` 函数：一行代码，算得又快又准，永远不会错。

**凡是一行确定的代码就能算对的事，别交给模型去想。** 模型该出场的，是那些写不成一行代码的地方。这道题只是我们的练习场。

## 把草稿纸装进模型里

故事回到岔路口上的另外两条路：做大，和专门教。

“一步一步想”是使用的人加的一句话。那么，能不能让模型自己养成这个习惯，不用人提醒，遇到难题就先打草稿？

2024 年 9 月 12 日，OpenAI 发布了一个新模型，叫 o1。你点开它，问了一道题。它没有马上回答。屏幕上出现一行小字：正在思考。过了十几秒，答案才出来，上面多了一行：“思考了 14 秒”。

这是头一回，一个面向大众的模型会先停下来想。

它是怎么练出来的？公开资料说明 o1 用强化学习训练推理，但没有公开完整配方。为了接上第 03 章 `reinforce.py` 的直觉，我们先看一种用程序验分的办法（后面的 R1 论文披露了这一路的具体做法，并非在核实 o1 的完整训练细节）：让模型在回答之前先写一段草稿，再交出答案；由像 `verify.py` 这样能客观验对错的程序来判分——答对了就加分，然后朝着高分去练（因为奖励能由程序直接核对，常被叫作“基于可验证奖励的强化学习”，英文简称 RLVR）。练得多了，它自己就摸出了一套容易拿高分的草稿习惯：把问题拆开，中途检查，发现走不通就退回去换条路。

所以“会思考的模型”，其实拧了两个旋钮：

![[零基础学AI/attachments/第 06 章｜回答太快，那就多想一会儿？/EwBzbxOupoOxijxryRIcai5Jnbf.png|“会思考的模型”，拧的是两个旋钮。]]

一个在练的时候：教它养成先打草稿的习惯。一个在用的时候：这道题，许它打多长的草稿。你在一些产品里见到的“深度思考”开关，拧的就是后一个。

有意思的是那份草稿的去向。o1 的草稿是不给用户看的，你只能看到一个摘要。可它是真实存在的，而且照样算钱——更要紧的是，**它在账单和输出上限里都算成 `completion_tokens`**。

还记得第 05 章（番外）里那个 `max_tokens` 坑吗？如果你调用推理模型时把 `max_tokens` 设得太小，比如卡在 `16` 甚至 `8192`，遇到难题它光在草稿纸里推演就把额度花完了，最后正经回答一个字都没来得及吐出来，只给你返回一个空字符串加上 `finish_reason: "length"`。

口说无凭，我们来掀开帘子看一眼。本版示例把推理模型环境变量 `LLM_MODEL` 设为 `deepseek-v4.1-flash`。下面保留的输出，按原教材说明来自 2026 年 11 月 SenseAudio 平台上的同名模型，尚未在当前商汤接口复测。原实验仍只许它“回答一个数字，不要任何解释”，再看它实际写了多少：

```python
# peek.py：有的模型嘴上只回一个数，背地里呢？

from puzzle import text

data = chat(text(30, 20) + "只回答一个数字，不要任何解释。", want_usage="all")
message = data["choices"][0]["message"]
details = data["usage"].get("completion_tokens_details", {})
print("它的回答：", message["content"].strip())
print("它一共写了", data["usage"]["completion_tokens"], "个 token，其中没给我们看的：", details.get("reasoning_tokens", 0))
hidden = message.get("reasoning_content") or message.get("reasoning") or ""
print("—— 没给我们看的那部分，开头是这样的 ——")
print(hidden.strip()[:260])
```

它的回答只有两个字符：55。可它一共写了 102 个 token，其中 101 个没给我们看。

那 101 个 token，就是它的草稿。接口恰好把这部分也放在 `reasoning_content` 里返回了，于是我们能看到开头：它在用英文飞快地给自己列提纲（“需要用中文回答。先理清排期……”）。我们说了“不要任何解释”，它确实没有向我们解释。它只是先在背后把题做了。

还是那十二道题，还是“只回答一个数字”，这个模型十二道全对，平均每题 118 个 token。

答对的那三行，没有一行是真的“脱口而出”。区别只在于草稿写在哪儿、写多长、给不给你看。

o1 之后四个月，2025 年 1 月，中国的 DeepSeek 发布了 R1。它做了一件 o1 没做的事：把草稿原原本本地摊给用户看。一时间，全世界的人都在围观一个模型自言自语。它的草稿里满是“等等”“让我再想想”“不对”这样的话，读起来像一个人在小声嘀咕。模型的权重也一并公开了，谁都可以下载来研究。它的论文里还有一个更激进的版本（R1-Zero），完全不看人写的示范，只靠“答对加分”硬练，照样练出了回头检查、推翻重来的习惯。

> 📎
>
> **选读：一个“等等”。** 2025 年有一项叫 s1 的研究，把“想多久”这件事做成了一个很具体的开关。模型打草稿打到一半，准备收尾作答的时候，程序把它那个表示“想完了”的记号按住不让出，并替它在草稿末尾接上一个词：“Wait”（等等）。模型看到自己“说”了一句等等，就真的接着往下想了。在一些数学题上，这样多按几次，正确率会涨；按得太多，它就开始原地打转。想得久一点有用，但不是越久越好。

## 多想不是万能的

说了一整章多想的好处，最后得把它的边界画出来。不然你会养成一个坏习惯：什么都开“深度思考”。

**第一，它会碰到天花板。** 2025 年 6 月，Apple 的研究者拿几种可以随意调难度的谜题（比如汉诺塔）去试这些会思考的模型。简单的时候，想不想差不多，有时不想反而更好；中等难度，会想的明显占优；难度再往上，不管许它想多久，正确率都会塌下去。草稿纸再多，也有算不动的题。

**第二，它慢，而且贵。** 这个你已经亲眼看到了。把“回答太快”治好的代价，就是回答不再快。问一句“会议室在几楼”，犯不上让它沉思十四秒。

**第三条最要紧：多想，只治一种病。**

设想部门上周刚发了通知，把账号审批的时限从 30 分钟改成了 45 分钟。你再问它那道排期题，但没把这份新通知给它——甚至题目里还留着旧的“30 分钟”。

它会一步一步想，草稿打得工工整整，每一步推导都无懈可击，然后郑重地告诉你：55 分钟。

每一步都对。答案是错的。

它不是没想清楚。它是不知道。那份新通知不在它的前文里，也不在它读过的任何东西里。条件过期时，思考越严密，越能把错答案算得像模像样。这样的事，想一万步也想不出来。

![[零基础学AI/attachments/第 06 章｜回答太快，那就多想一会儿？/I6WBbCwN5oo7ctx1cRGcU55RnEb.png|它答不好，缺的是哪一样。]]

所以在让它多想之前，先替它诊断一下：它缺的，真的是“想”吗？

如果条件都摆在它面前了，只是环环相扣容易乱，那就让它把中间结果写出来，再找个程序查一查。这是这一章的事。

如果它缺的是一份它没见过的材料，那让它想再久也没用，得先把材料找来。这是下一章的事。

如果它缺的是一双手，要真的去开一个账号、装一个软件，那想得再明白也只是纸上谈兵。这是再下一章的事。

## 这一章你留下了什么

`verify.py` 和 `checked.py`，合起来是资料助手的 **v0.6**。往后它碰到条件一环扣一环的活，就照这个办法来：让它把关键的中间结果写成一张表，交上来先让程序过一遍，过不了就打回去。

`peek.py` 可以留着。以后有人跟你说某个模型“一下子就答出来了”，你可以去看看它背地里写了多少 `reasoning_tokens`。

还有四句话。

它没有草稿纸，它说出来的话就是它的草稿纸。

五份一样的答案，是一份证据抄了五遍。

要它写下来的，不必多，要准。

一行代码能算对的，别让它想。

## 下一站

会听话了，会想了。可是那份改了审批时限的通知，它还是不知道。

不知道，本来也没什么。麻烦的是，它**不知道自己不知道**。你问它，它不会说“这我没见过”，它会给你一个听上去完全合理的答案。

2023 年 6 月，纽约的一间联邦法庭上，一位执业三十年的律师被法官叫去解释一件事。他提交的一份文书里，引用了六个从前的判例来支持自己的主张，案件名称、法院、年份、卷宗号，一应俱全。

对方律师去查了。法官也去查了。

这六个判例，一个都不存在。
