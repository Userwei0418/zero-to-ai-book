*这一章做完：你的助手能自己连着走七八步查多篇《上册》笔记、互相印证后再交卷；遇到重复调用会自动拦下防打转，超过最大步数会体面刹车，中途断网或按下 `Ctrl+C` 后重新运行同一个任务编号，还能直接从第 N 步断点无缝接上。对应上册第 09 章及番外。*

## 放手让它跑多步之后，一定会撞上的三堵墙

上一章的 `agent_tools.py` 已经走通了“想一步 → 递纸条 → 看结果 → 再想下一步”的循环。只要问的是单章小问题，两三步就答完了。

可一旦你交给它一个需要跨越多篇笔记的综合任务——比如：“请依次查阅第 01、02、03 章，对比资料助手从 `v0.1`、`v0.2` 到 `v0.3` 各自用什么算法、考卷得了几分、又留下了什么新问题”——把循环放开之后，三个工程难题马上找上门来：

1. **原地打转（Looping）**：模型查某个词没查到理想结果时，非常容易陷入执念，连续三次递出一模一样的 `read_note(filename="第 01 章...", start_line="1", end_line="60")` 纸条，把上下文塞满一模一样的文本。
2. **没有刹车的无底洞**：如果模型一直觉得“我还没查全，再查一步”，没有步数硬上限的话，它会一直调下去，直到触发第 01 章的预算保险丝报错退出，前面查到的半成品全扔了。
3. **干到第 5 步断网，前功尽弃**：它辛辛苦苦查完了第 01 章和第 02 章，正准备查第 03 章时，网络抖动超时或者你误按了 `Ctrl+C`。因为对话状态全放在内存列表 `messages` 里，进程一退，前面花掉的几十秒和几千个 Token 瞬间归零，重跑还得从第 1 步重头来过。

## 三道护栏：每步落盘 + 重复调用拦截 + 体面刹车

我们在 `课件/ch06/loop.py` 里把内存里的临时变量，升级成一张**每步必落盘的任务状态卡（`checkpoints/<task_id>.json`）**：

### 1. 断点持久化（Checkpoint）

每次启动 `run_task(task_id, goal)` 时，程序先去 `checkpoints/` 目录下找有没有同名 JSON：
- 如果找到了，且 `status == "done"`，说明这个任务之前已经跑完交卷了，**直接返回保存好的答案，一次模型都不调**；
- 如果找到了，且 `status == "running"`（或上次停在半路），直接恢复里面的 `messages`、`step` 和 `seen_calls`，从第 `step + 1` 步接着往下跑；
- 每当模型走完一步、工具执行完毕，立刻调用 `save_ckpt()` 把最新状态写回硬盘。

### 2. 重复调用签名拦截（`seen_calls`）

我们在状态卡里维护一个列表 `seen_calls`。每当模型递来一张纸条 `c`，先算一个唯一签名：

```python
sig = f"{c['function']['name']}::{c['function'].get('arguments', '')}"
```

如果这个签名已经在 `seen_calls` 里出现过了，程序**根本不去执行工具**，而是直接往 `tool` 消息里塞回一句清醒的提示：

> `"提示：你此前已经用完全相同的参数调用过该工具，请勿原地打转；请换检索词、换起止行号，或直接根据已有信息作答。"`

这一下就把原地打转的路堵死了。

### 3. 步数刹车（`max_steps`）

循环最多走 `max_steps`（默认 8 步）。万一走到第 8 步模型还在递纸条，程序不会粗暴抛异常崩溃，而是把状态标为 `"stopped_max_steps"` 并保存断点——你随时可以调大 `max_steps` 从第 9 步继续跑。

## 完整可运行代码：`loop.py`

```python
# loop.py：第 06 章实战成品——带断点续传、重复调用检测与步数刹车的自主执行循环
# 用法：python3 loop.py task01 "对比第 01、02、03 章资料助手演进，写一份三点总结"
import json
import os
import sys

sys.path.insert(0, os.path.abspath(os.path.join(os.path.dirname(__file__), "../ch02")))
sys.path.insert(0, os.path.abspath(os.path.join(os.path.dirname(__file__), "../ch05")))
import llm
import toolbox

CKPT_DIR = os.path.join(os.path.dirname(__file__), "checkpoints")


def _ckpt_path(task_id):
    os.makedirs(CKPT_DIR, exist_ok=True)
    return os.path.join(CKPT_DIR, f"{task_id}.json")


def save_ckpt(task_id, state):
    with open(_ckpt_path(task_id), "w", encoding="utf-8") as f:
        json.dump(state, f, ensure_ascii=False, indent=2)


def load_ckpt(task_id):
    p = _ckpt_path(task_id)
    return json.load(open(p, encoding="utf-8")) if os.path.exists(p) else None


def run_task(task_id, goal, max_steps=8, allow_write=False):
    state = load_ckpt(task_id)
    if state and state.get("status") == "done":
        print(f"[{task_id}] 任务已完成（从断点直接返回结果）")
        return state["answer"]

    if state:
        print(f"[{task_id}] 检测到未完成断点，从第 {state['step'] + 1} 步继续执行…")
    else:
        state = {
            "task_id": task_id,
            "goal": goal,
            "step": 0,
            "status": "running",
            "seen_calls": [],
            "messages": [
                {
                    "role": "system",
                    "content": "你是严谨的知识库助手。请分步调用工具查证《上册》原文后回答，每条结论附 [文件名:行号]；不要重复调用完全相同的工具参数。",
                },
                {"role": "user", "content": goal},
            ],
            "answer": "",
        }
        save_ckpt(task_id, state)

    specs = toolbox.specs(allow_write=allow_write)
    while state["step"] < max_steps:
        state["step"] += 1
        _, _, model = llm._cfg()
        body = {"model": model, "messages": state["messages"], "tools": specs, "temperature": 0}
        with llm._post(body) as resp:
            data = llm._parse(resp.read().decode("utf-8", "replace"))
        llm._book(data.get("usage"), 0.0)
        msg = data["choices"][0]["message"]
        calls = msg.get("tool_calls") or []

        if not calls:
            state["status"] = "done"
            state["answer"] = msg.get("content") or ""
            save_ckpt(task_id, state)
            return state["answer"]

        state["messages"].append({"role": "assistant", "content": msg.get("content") or "", "tool_calls": calls})
        for c in calls:
            sig = f"{c['function']['name']}::{c['function'].get('arguments', '')}"
            if sig in state["seen_calls"]:
                res = "提示：你此前已经用完全相同的参数调用过该工具，请勿原地打转；请换检索词或直接根据已有信息作答。"
            else:
                state["seen_calls"].append(sig)
                res = toolbox.execute(c, allow_write=allow_write)
            state["messages"].append({"role": "tool", "tool_call_id": c["id"], "content": res})
        save_ckpt(task_id, state)

    state["status"] = "stopped_max_steps"
    state["answer"] = f"已达最大步数刹车上限（{max_steps} 步），当前进度已保存至断点 {task_id}.json。"
    save_ckpt(task_id, state)
    return state["answer"]


if __name__ == "__main__":
    tid = sys.argv[1] if len(sys.argv) > 1 else "demo_task"
    q = " ".join(sys.argv[2:]) or "请分别查阅第 01、02、03 章，总结资料助手 v0.1 到 v0.3 的演进。"
    print(run_task(tid, q))
```

## 故意弄坏它：只给 1 步上限先刹住，再放开上限从第 2 步接回来

为了验证断点续传是不是真的管用，我们不需要等它自然断网，直接用代码模拟一次“半路停机再恢复”：

1. 第一次调用 `run_task("test_resume", ..., max_steps=1)`，故意只给 1 步上限，让它在查完第 1 步后立刻触发步数刹车停在半路；
2. 检查硬盘上的 `checkpoints/test_resume.json`，确认 `step == 1` 且 `status == "stopped_max_steps"`；
3. 第二次把 `max_steps` 放开到 `6`，传入同一个 `"test_resume"`，亲眼看它直接从第 2 步接着往下跑。

> **老办法，新地方**
>
> “把长任务拆成离散的 Step，每走完一步先把状态落盘（Checkpoint），故障重启后从最近的 Checkpoint 恢复而不是从头重算”，这和数据库预写日志（WAL）、大模型训练时的定期存盘（Save Checkpoint）以及游戏里的存档点一模一样。

现在，你的知识库已经能解析、能混合检索、能安全调工具、还能断点续传了。但目前为止，它还只能活在你自己写的命令行脚本里。如果你平时写代码或写文档最顺手的外壳是 **Claude Code**、**Cursor** 或其他现成的桌面助手，怎么把你的知识库原封不动地插进去？

**第 07 章**，我们用不到一百行标准库代码，把它变成一个标准的 **MCP（Model Context Protocol）** 服务。
