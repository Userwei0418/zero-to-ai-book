# 探索拓展 E｜办公／知识工作：报告写出来，工作还剩多少？

*附录｜探索拓展。这一条支线讲的是“助手走进办公室”。它的头一站是一枚人人嫌弃的曲别针，最近的一站是一只人人想养的龙虾。这一篇可以单独读，结尾接回第 14 章的验收。*

## 周五下午的一份简报

周五下午四点，组长在群里说：下周一要一份第三季度的缺陷简报。灯塔、海豚、松鼠三条产品线，各自新增多少，关闭多少，哪一条最该担心。三百字就行。

材料都在共享盘里，五份：灯塔的缺陷统计，一张从系统里导出来的小表；海豚的周报汇总，有 v1 和 v2 两版；松鼠的季度表，原件是一张带合并格子的表，你手里的是另存出来的纯文本；还有一份周会纪要。

这一篇就拿这份简报当尺子。同一件事，放到六个年份里，看助手站在哪儿、帮得上什么。

## 第一站：一枚曲别针

1997 年，微软的 Office 里多了一个角色。你刚敲下“尊敬的”三个字，屏幕角上就蹦出一枚长着眼睛的曲别针：看起来你在写信，需要帮忙吗？

它叫 Clippit，中文用户管它叫大眼夹。

![[零基础学AI/attachments/探索拓展 E｜办公／知识工作：报告写出来，工作还剩多少？/EI1abPZU0otYF7xbdmZcYl03ncd.png|你什么都没问。它自己冒出来了。]]

它是很多人这辈子见到的第一个“办公助手”，也是被骂得最狠的一个。打扰人，烦人，帮不上忙。几年以后的版本里它被默认关掉，2007 年彻底拿掉了。后来有博物馆的刊物说，它是软件设计史上最糟的失误之一。

请记住它错在哪儿。它不知道你在干什么，却不请自来。在这一站，你的简报还得自己写，旁边多一枚曲别针。

## 第二站：另一个窗口

2022 年底，ChatGPT 来了。和附录 A 的第二站一样，办公室里的头一种用法也是搬运：把材料贴进聊天框，说一句话，把结果贴回文档。

这一回它是你请来的，而且真帮得上忙。它待在另一个窗口里，看得见的只有你贴给它的东西。

## 第三站：坐进办公软件

2023 年 3 月 16 日，微软宣布了 Microsoft 365 Copilot：把模型放进 Word、Excel、PowerPoint、Outlook 里。那年 11 月 1 日起，它开始卖给大企业，每人每月 30 美元，起先要一次买三百个以上的名额。

二十六年前那枚曲别针待过的角落，换了一位新住户。这一位你不叫它，它不出声。你叫它，它就在你正写着的那份文档里干活，不用你搬来搬去。

（2025 年 10 月，微软真的又给它配了一个会动的小形象，报道说它很像当年那枚曲别针。不到一年，这个形象又被拿掉了。）

## 第四站：只认你给的资料

助手坐进来以后，头一个麻烦是它爱凭印象说话。这是第 07 章的老问题。

2023 年，谷歌拿出了一个叫 NotebookLM 的工具，思路反着来：你把资料交给它，它只根据这些资料回答，每句话都能点回原文。2024 年 9 月，它多了一个出圈的功能：把你的资料变成两位主持人聊天的一段播客。同年 6 月，Claude 有了 Artifacts，回答的旁边直接摆出一页成品：一份文档，一张图表，一个能点的小页面。

到这一站，我们可以真做了。五份材料全贴进去，把组长的话抄一遍，请它写。为了方便贴进表格，再让它在末尾附一行汇总。写三遍。第一遍交回来的是这样：

```
第三季度缺陷简报：
灯塔新增131条，关闭105条；海豚新增135条，关闭88条；松鼠因8月系统迁移数据缺失，
仅统计7、9月共45条，关闭数未知。海豚最该担心，其9月新增激增且整体关闭率偏低，
积压风险最大。
```

![[零基础学AI/attachments/探索拓展 E｜办公／知识工作：报告写出来，工作还剩多少？/YZbCbjRmSo8f94xviUCcQZ3WnOg.png|它交上来一页干干净净的简报。]]

通顺，简洁，有数，有结论。一共花了九百多个 token。

可那五份材料是我备的，我在里面埋了五处要留心的地方。请你先猜一猜，它会栽在哪一处。

- **版本。** 海豚的 v1 里，9 月新增是 27 条。v2 的修订说明写着：录反了，应为 72 条。
- **单位。** 松鼠那张表给的是“关闭率”，90% 和 60%。别的两条线给的都是关闭了多少条。
- **缺项。** 松鼠 8 月那一格写的是“系统迁移，未统计”。
- **冲突。** 灯塔的表，三个月加起来是 131 条。周会纪要里，灯塔的负责人口头说的是 141 条。
- **结论。** 上面几处都走对了，最该担心的才是海豚。

```python
# report.py：把材料全贴给它，让它直接写简报。写三遍，每一遍都拿去对答案
import glob, json, os, re, sys
from llm import chat, SPENT

ASK = """组长要一份测试组第三季度的缺陷简报，三百字以内：灯塔、海豚、松鼠三条产品线各自新增多少、关闭多少，哪一条最该担心。
简报写完以后另起一行，附一行 JSON，方便贴进表格，格式是：
{"灯塔": {"新增": 数, "关闭": 数}, "海豚": {"新增": 数, "关闭": 数}, "松鼠": {"新增": 数, "关闭": 数}, "最该担心": "产品线名", "待确认": ["……"]}
拿不准的数填 null。没有要找人确认的事，待确认就填空列表。"""

def materials(folder="materials"):
    return {os.path.basename(p): open(p, encoding="utf-8").read()
            for p in sorted(glob.glob(folder + "/*.txt"))}

def pack(files):
    return "\n\n".join(f"【{name}】\n{text}" for name, text in files.items())

def summary(reply):
    """把简报末尾那一行 JSON 取出来"""
    return json.loads(re.search(r"\{.*\}", reply, re.S).group(0))

def grade(reply):
    """五处该留心的地方，一处一处对。对的是末尾那行汇总，和简报里说没说"""
    s = summary(reply)
    return {
        "版本：海豚用了改过的那一版（新增 135）": s["海豚"]["新增"] == 135,
        "单位：没有把松鼠的关闭率当成条数": s["松鼠"]["关闭"] in (33, None),
        "缺项：说了松鼠 8 月没有数": any(w in reply for w in ("未统计", "迁移", "缺失", "没有数据", "缺少")),
        "冲突：指出灯塔的 131 和纪要里的 141 对不上": "131" in reply and "141" in reply,
        "结论：最该担心的是海豚": "海豚" in str(s["最该担心"]),
    }

if __name__ == "__main__":
    files = materials()
    for n in (1, 2, 3):
        before = SPENT["tokens"]
        reply = chat(ASK + "\n\n下面是手头的全部材料。\n\n" + pack(files))
        open(f"_report_{n}.txt", "w", encoding="utf-8").write(reply)
        marks = grade(reply)
        print(f"直接写 第 {n} 遍：{SPENT['tokens'] - before} 个 token，五处对了 {sum(marks.values())} 处")
        for name, ok in marks.items():
            if not ok:
                print("    没对：", name)
```

```
    没对： 冲突：指出灯塔的 131 和纪要里的 141 对不上
```

五处对了四处，三遍都一样。

我本来押的是版本和单位。它一处都没栽。两三年前要专门设防的毛病，今天有不少它自己就绕开了。

漏的是哪一处，先放一放。有一处没出事的地方，值得先回头看一眼。

## 格子没了

松鼠的那张表，原件长这样。你手里的纯文本，长那样。

![[零基础学AI/attachments/探索拓展 E｜办公／知识工作：报告写出来，工作还剩多少？/VPhabLwarocrIzxdkiAcAN2inAd.png|一张表，另存成纯文本以后。]]

右边那一列字，是我用电脑自带的转换工具真转出来的，一个字没改。

字一个没少。少的是格子。在一张表里，“20”这个数的意思有一半写在它的位置上：它在“7 月”那一行，“新增”那一列。格子一拆，位置没了。

这一回模型把它拼回去了，拼得对。这张表只有三行，又很规整。请你设想一张三十行的表，中间有几格是空的。空格子在纯文本里什么都不留下，后面的数会悄悄往前挪一位。

办公室里的材料，大半是这个样子：PDF，扫描件，截图，从别的系统里另存出来的表。它们得先变成模型读得了的文字，这一步叫**解析**。2024 年下半年，接连有两个开源工具专做这件事：8 月的 Docling，9 月的 MinerU。

第四站说“只认你给的资料”。资料是怎么给进来的，排在所有事情的最前头。

## 漏掉的那一处

它漏的是冲突。

灯塔的表加起来是 131。周会纪要里，负责人说的是 141。差十条。

简报里写的是“灯塔新增 131 条”。141 这个数，三遍里一遍都没有出现过。末尾“待确认”那一栏，三遍都只写了松鼠 8 月的数据。

它没有写错。它只是在两个说法之间替你选了一个，然后没有告诉你它选过。

请留意这种毛病的样子。简报里没有一个错字，没有一个错数。你把它读十遍，也读不出问题。问题在它没写的那一句上。

## 第五站：替你去查，替你去点

2025 年，助手开始自己出门了。

2 月，OpenAI 推出了 Deep Research。你提一个题目，它自己去网上翻几分钟到半小时，交回来一份带引用的报告。1 月，同一家公司放出了 Operator：它在一台虚拟的电脑里自己开浏览器，替你填表、下单、订位子。3 月 6 日，一个叫 Manus 的产品开放内测，说自己是能独立把一件事办完的 Agent，邀请码一度很抢手。

这是第 09 章的那个圈，套在了“查资料、写报告、点网页”上。它一次干的事更长了，交回来的东西更像成品了。上一节的那个毛病，也跟着放大了：它翻了五十个网页，在其中一百处替你做了取舍。你看到的只有最后那一份。

所以这一站最要紧的一样东西，是**出处**。

我们的简报不用上网，可是道理一样。换一种做法：头一步不写简报，只摘数。每摘一个数，都得写明它出自哪份文件，并且把那一行原文一字不差地抄下来。程序一条一条去对。同一条线、同一个月、同一个项目，要是摘出了两个不一样的数，程序就列出来。第二步才让它写。

头一回跑出来是这样：

```
先摘再写 第 1 遍：5001 个 token。摘了 24 个数，出处对不上的 0 个，对得上却认不出月份的 4 个，程序发现互相打架的 1 处。五处对了 4 处
    没对： 冲突：指出灯塔的 131 和纪要里的 141 对不上
先摘再写 第 2 遍：4778 个 token。摘了 22 个数，出处对不上的 0 个，对得上却认不出月份的 2 个，程序发现互相打架的 1 处。五处对了 4 处
    没对： 冲突：指出灯塔的 131 和纪要里的 141 对不上
先摘再写 第 3 遍：4778 个 token。摘了 22 个数，出处对不上的 0 个，对得上却认不出月份的 2 个，程序发现互相打架的 1 处。五处对了 4 处
    没对： 冲突：指出灯塔的 131 和纪要里的 141 对不上
```

摘了二十多个数，出处一个不差。花的 token 是直接写的五倍。五处对了四处。漏的还是那一处。

怎么回事？程序发现的“互相打架”只有一处：海豚 9 月，v1 说 27，v2 说 72。灯塔的那一处它没发现，因为表里写的是三个月各多少，纪要里说的是全季一共多少。在我的程序眼里，这是两件不相干的事。它不会做加法。

这一回漏掉冲突的，有两个：模型，和我写的那把尺子。

给程序添几行，让它把三个月的数加起来，再去和别处报的全季数比。

```python
# trace.py：先摘数，每个数都要带着出处；程序把出处一条一条对过，再让它写
import json
from collections import defaultdict
from llm import chat, SPENT
from report import ASK, materials, pack, grade

PICK = """先不要写简报。把下面材料里和缺陷数量有关的每一个数都摘出来，同一件事在几份材料里都出现的，每一份各摘一条。
输出 JSON：{"facts": [{"产品线": "", "月份": "7月/8月/9月/全季", "项目": "新增/关闭/关闭率", "数值": 数, "文件": "文件名", "原文": ""}]}
“原文”必须是从那份文件里一字不差抄下来的一整行，里面要有这个数。"""

def check(facts, files):
    """回链：文件在不在，原文在不在文件里，数在不在原文里。再看这一行认不认得出说的是哪个月"""
    good, bad, weak = [], [], []
    for f in facts:
        line = str(f.get("原文", "")).strip()
        if f.get("文件") not in files or line not in files[f["文件"]] or str(f.get("数值")) not in line:
            bad.append(f)
            continue
        good.append(f)
        if "月" not in line and "季度" not in line:      # 抄下来的这一行里没有月份：对得上，却说明不了什么
            weak.append(f)
    return good, bad, weak

def clashes(facts):
    """同一条线、同一个月、同一个项目，摘出了不一样的数"""
    seen = defaultdict(set)
    for f in facts:
        seen[(f["产品线"], f["月份"], f["项目"])].add((f["数值"], f["文件"]))
    for (line, month, item), vs in list(seen.items()):            # 后添的：三个月的数加起来，和别处报的全季数比一比
        for _, name in vs:
            months = [f["数值"] for f in facts if (f["产品线"], f["项目"], f["文件"]) == (line, item, name)
                      and f["月份"] != "全季"]
            if month != "全季" and item != "关闭率" and len(months) == 3:
                seen[(line, "全季", item)].add((sum(months), name + " 三个月相加"))
    return {k: sorted(v, key=str) for k, v in seen.items() if len({n for n, _ in v}) > 1}

if __name__ == "__main__":
    files = materials()
    for n in (1, 2, 3):
        before = SPENT["tokens"]
        facts = json.loads(chat(PICK + "\n\n" + pack(files), json_mode=True))["facts"]
        good, bad, weak = check(facts, files)
        diff = clashes(good)
        table = "\n".join(json.dumps(f, ensure_ascii=False) for f in good)
        notes = "\n".join(f"{'／'.join(k)}：" + "，".join(f"{v}（{name}）" for v, name in vs) for k, vs in diff.items())
        reply = chat(ASK + "\n\n只许用下面这张核对过出处的表里的数，原始材料附在后面备查。\n\n" + table
                     + "\n\n程序发现下面这些地方对不上，请在简报里交代你用了哪一个、为什么：\n" + (notes or "（没有）")
                     + "\n\n" + pack(files))
        open(f"_trace_{n}.txt", "w", encoding="utf-8").write(table + "\n----\n" + notes + "\n----\n" + reply)
        marks = grade(reply)
        print(f"先摘再写 第 {n} 遍：{SPENT['tokens'] - before} 个 token。摘了 {len(facts)} 个数，"
              f"出处对不上的 {len(bad)} 个，对得上却认不出月份的 {len(weak)} 个，程序发现互相打架的 {len(diff)} 处。五处对了 {sum(marks.values())} 处")
        for name, ok in marks.items():
            if not ok:
                print("    没对：", name)
```

这回五处全对。简报里多了一段：


![[零基础学AI/attachments/探索拓展 E｜办公／知识工作：报告写出来，工作还剩多少？/ITnvbGJIRoNZ6nxzAA5cnWv6n2b.png|同一份简报，三种做法。]]

这张表有三件事要看。

头一件，分数从四处到五处，靠的是程序多会了一样加法。“每个数都带出处”买来的是另一样东西：简报里的每一个数，现在都能点回原文的那一行。

第二件，回链也有虚的。每一遍都有两到四个数，程序报的是“对得上，却认不出月份”。它们全出自松鼠那份被拆了格子的表。模型抄下来的“原文”就是一行“20”。前面丢掉的格子，在这儿又让你付了一次账。

第三件，请再读一遍那段“数据说明”。它说用 131，“因前者可追溯”。这个理由讲得通。可这是该由它来定的事吗？它把冲突亮出来了，然后又顺手替你裁决了。

## 第六站：住进你的电脑

2026 年，助手从“替你出门”变成了“住在你家”。

1 月，Anthropic 放出了 Cowork 的研究预览：和附录 A 里那些终端工具是一路的，换了一个图形界面，让它直接在你的文件夹里干活。2 月它接上了网盘和邮箱，3 月你可以从手机上给它派活。

也是这一年的 1 月，还有一样东西火得更凶。一位奥地利程序员做了一个开源的个人 Agent，装在你自己的电脑上，你在平常用的聊天软件里给它发消息，它替你收邮件、排日程、跑腿。它在三个月里改了五次名字，其中一次是因为撞了别家的商标，最后定下来叫 OpenClaw。它从头到尾拿龙虾当招牌，国内用的人管它叫“小龙虾”。到 3 月初，它在代码托管网站上拿到了二十四万多颗星。

![[零基础学AI/attachments/探索拓展 E｜办公／知识工作：报告写出来，工作还剩多少？/GJRAbZhcSot7RCx9Cn4cdPGvnee.png|你把一整串钥匙递给了它。]]

它为什么这么招人？因为它什么都能替你办。它为什么什么都能办？因为你把邮箱、日历、聊天账号的钥匙全给了它。

麻烦也从这儿来。有人把它装好了，门却开着，谁都连得上。别人发来的一封邮件里藏一句话，它就可能照办，这是第 13 章讲过的“谁发来的话，都算你说的吗”。安全公司在别人写的技能包里找到了偷数据的。3 月，国内限制了机关、国企和银行使用它。微软的掌门人说它像“病毒”，可没过几个月，微软自己也在试一个基于它的东西。

第一站的曲别针被嫌弃，是因为它不请自来，又帮不上忙。第六站的龙虾被追捧，也被提防，是因为它真帮得上忙，而你为此把钥匙给了它。

## 还剩多少

现在回答题目。

简报写出来了，花了不到一千个 token。算上摘数和核对，五千。

剩下的是这些：

去问灯塔的负责人，那十条是怎么回事。

去找松鼠的人，8 月的数什么时候补。补上之前，“最该担心的是海豚”这句话要不要加一个前提。

把那二十多条回链抽几条点开看看，尤其是松鼠的那几条。

下个月有人接着做第四季度的，他得知道这一份里哪些数是确认过的，哪些还挂着。

![[零基础学AI/attachments/探索拓展 E｜办公／知识工作：报告写出来，工作还剩多少？/XLl6bn1LZonYKqxq8g0cx90inyd.png|简报写完了。还有两件事得打电话问。]]

这几件事里，没有一件是“写”。它们是问、等、核、交代。六站走下来，写的那一段被压到了几乎不花工夫。这几件，没有哪一站替你做了，其中两件它还替你悄悄做了决定。

有两项研究量过这笔账。

一项是对照实验。2025 年发表，66 家公司，7137 位做文字工作的员工，一半人拿到了嵌在邮件、会议和写作软件里的 AI 工具，为期六个月。真用了工具的那些人，每周花在邮件上的时间少了两个小时。同一篇摘要里还有一句：没有看出他们手上任务的数量和构成有什么变化。

另一项在丹麦，把大规模的使用情况调查和官方的劳动记录接在了一起。结论是：ChatGPT 上线两年以后，无论按个人看还是按单位看，收入和工时都量不出变化，大于 2% 的影响可以排除。

这两项说的都是早期，大约是第三站前后。它们也都没有说 AI 没用：每周两小时是实打实的。它们说的是，从“这件事快了”到“这份工作变了”，中间还隔着一大段。那一大段里装的，就是上面那张单子。

## 接回验收卡

第 14 章的验收卡上有一节，叫“量过什么”。知识工作的交付物，这一节要多填五行：

**材料是怎么进来的。** 哪些是原件，哪些是转出来的，转的时候丢了什么。

**每个数的出处。** 能不能点回原文的那一行。哪些回链是虚的。

**哪些地方是它替你选的。** 两版用了哪一版，两个说法信了哪一个，理由是什么。

**哪些事还挂着。** 该问谁，问了没有。

**它手里有哪几把钥匙。** 它能读什么，能发什么，谁发来的话它会照办。这一行是第六站添的。

最后一行是这一篇的题目：**下一位同事拿到这份东西，能不能接着做。** 能，这份简报才算写完了。

## 合上之前，想一想

1. 曲别针和龙虾，一个被嫌弃，一个被追捧。请用自己的话说出它们最要紧的三处不同。有没有哪一处，其实是一样的？
2. 直接写的那三遍，简报里没有一个错数，却少了一句“纪要里说的是 141”。请设想你是组长，周一拿到的是这一份。你有没有办法发现它少了这一句？
3. 我的程序头一回没发现 131 和 141 的冲突，因为它不会加法。请再想一种它现在仍然发现不了的冲突。（提示：同一件事，两份材料用了不一样的叫法。）
4. “因前者可追溯”，它替你在两个数之间做了裁决。请改一改 `trace.py` 里交给它的那段话，让打架的地方一律进“待确认”，不许它自己定。这样改，有没有什么坏处？
5. 假如你要在自己的电脑上养一只“小龙虾”，请列出你愿意给它的三把钥匙，和你无论如何不给的三把。你是按什么分的？
