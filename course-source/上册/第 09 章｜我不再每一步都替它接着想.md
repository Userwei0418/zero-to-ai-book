## 2023 年 4 月，一个人人都想试的仓库

2023 年 3 月 30 日，一位做游戏的开发者把一个项目放上了 GitHub，名字叫 Auto-GPT。

4 月的某个晚上，你也把它装上了。

它先问你三样东西：给你的 AI 起个名字；它是干什么的；再给它最多五个目标。说明文档里的示范很有那个春天的气质：一个叫“企业家 GPT”的 AI，职责是自主地开办并经营生意，唯一的目标是增加你的净资产。

你敲下回车。屏幕上开始一段一段地往外冒字：它的想法，它的理由，它的计划，它对自己的批评，然后是“下一个动作”。

每个动作之前，它停下来等你。输入 `y`，它就去做。

做完，它看一眼结果，又开始冒字：新的想法，新的计划，下一个动作。

这是你头一回看见一个程序自己给自己派活。你按了十几次 `y` 以后发现，它还给你留了一个更省事的选项：输入 `y -N`，它就连着做 N 步，中间不再问你。还有一个“连续模式”，干脆一次都不问。说明里特意警告：不推荐，有危险，它可能永远跑下去，也可能做出你平时不会批准的事。

很多人还是开了。

不到一个月，这个仓库的星标过了十万。同一时期还有一个更小巧的项目叫 BabyAGI，只有三个环节，循环往复：做完手头的任务，根据结果想出新的任务，把任务清单重排一遍。

人们把目标交给它们，然后看着那张任务清单，越列越长。

列了一夜。第二天早上，清单更长了，事情没办成几件，接口的账单倒是来了。

先别笑它。

上一章结尾，你自己也站在了同一个念头前面：每一步都是我在接，能不能让它自己走？做这个实验要用的零件，你手上已经齐了。我们自己做一个，看看它会不会好一点。

## 四步不够用了

## 松手

四个 `step` 换成一个 `while`，要改的地方少得让人有点不安：

```python
# loop.py：把四个 step，换成一个圈
import os
from llm import chat, SPENT
from kit import TOOLS, ROLE, run_safely, brief

def loop(goal, most=None):
    messages = [{"role": "system", "content": ROLE}, {"role": "user", "content": goal}]
    n = 0
    while most is None or n < most:          # 不给 most，就一直转下去
        n += 1
        message = chat(messages, tools=TOOLS)
        messages.append(message)
        calls = message.get("tool_calls") or []
        if not calls:                        # 它没有递纸条，开口说话了：它认为事情做完了
            return message["content"]
        for call in calls:
            result = run_safely(call)
            print(f"   第 {n} 步  {call['function']['name']}  {brief(call['function']['arguments'])}  →  {brief(result)}")
            messages.append({"role": "tool", "tool_call_id": call["id"], "content": result})
    return None                              # 转满了 most 圈，它还没说完

def report():
    print(f"问了模型 {SPENT['calls']} 次，花了 {SPENT['tokens']} 个 token")
    print("workspace 里有：", sorted(os.listdir("workspace")) if os.path.exists("workspace") else "（什么都没有）")

if __name__ == "__main__":
    from four import DAY1
    print("它说：", loop(DAY1))
    report()
    print()
    print(open("workspace/day1.md", encoding="utf-8").read())
```

看 `loop` 里那个圈。问它一次。它要是递了纸条，就照办，把结果接回对话，再问它一次。它要是没递纸条、开口说话了，就把这句话交回来，收工。

没有“第一步查、第二步存”。没有人数步数。

而且有个细节值得你停一下。上一回，它是一步递一张纸条，查了三次。这一回，它在第 1 步里**一口气递了三张**，三件事同时查，第 2 步就存了。所以**模型调用轮数、工具动作数、读到的材料数，并不是同一个数**——看账单时得把这三个数分清。

同一件事，同一个模型，两次走法不一样。

这正是松手的意思。走几步，先做什么，一次做几件，这回真的是它自己定的。你只说了要什么。

![[零基础学AI/attachments/第 09 章｜我不再每一步都替它接着想/FjQQb5mkcoxkGHxp7gPc7sE7niH.png|你松开了手。它自己骑出去了。]]

这个圈有个响亮的名字，你肯定听过：**Agent**，智能体。

名字很大，东西你刚刚亲手写完了，二十来行。把它拆开看，一共六样：

**目标**，是你说的那句话。**状态**，是那个越接越长的 `messages`，它每转一圈都要从头读一遍。**决策**，是问模型的那一次：下一步干什么。**动作**，是执行器照纸条办事。**观察**，是把结果接回对话。**停止**，是它不再递纸条的那一刻。

模型在这个圈里，只管“决策”这一样。其余五样，都是普通的程序。

这个圈也不是 2023 年春天才有的。2022 年 10 月，普林斯顿和谷歌的几位研究者发了一篇论文，叫 **ReAct**，名字是“推理（Reasoning）”和“行动（Acting）”两个词拼起来的。在那之前，让模型多想的人只让它想（就是第 06 章的“一步一步来”），让模型动手的人只让它动手。这篇论文把两样交替着来：想一步，做一步，看一眼结果，再想下一步。他们发现，这样比只想不做、只做不想都强。

第 06 章教它想，第 08 章给它手。把这两样接成一个圈，就是这一章。

Auto-GPT 做的，是在这个圈上再加一把劲：目标不再是“查一下、存一下”，而是“去增加我的净资产”。

那我们也试试。

## 给它一个没有边的目标

到现在为止，你交给它的事都有个明明白白的终点：存成 `day1.md`，写清四件事。存好了，就是完了。

换一个那年春天风格的目标：

> 让测试组的新人资料变得尽可能完善。你自己决定要做什么，一直做到你认为足够好为止。

先别往下看。你觉得它会做什么？会存出几个文件？会在第几步停下来？

毛病出在哪儿？

不在模型笨。出在我们给的那句话上。“尽可能完善”“足够好为止”，这样的目标没有终点线。完善了吗？还可以再查一项。够好了吗？还可以更好一点。每多查一项都说得通，于是永远有下一项。

再加上我们给它立过规矩：查不到依据的，不许往文件里写。它很守规矩，于是一直在找依据，一个字都没敢存。

2023 年春天，对着 Auto-GPT 熬夜的人看到的就是这个。它的每一段想法都头头是道，它的计划一条一条列得很漂亮，它一直很忙。

**每一步都说得通，不等于在往前走。**

## 四个刹车

那怎么让它停？

你先想想。假如你是那个在旁边看着的人，看到什么的时候，你会伸手叫停？

我能想到四种时候。

步子太多了。一件“查一下、存一下”的事，走到第八步还没完，多半不对劲。

钱花太多了。账上已经一万五了，不管它在干什么，先停。

它在兜圈子。连着几步，拿回来的都是见过的东西，或者什么都没拿到。

还有，我就是不想等了。

把这四种时候写进那个圈里：

```python
# agent.py：资料助手 v0.9。还是那个圈，多了四个能让它停下来的地方
import json, sys
from llm import chat, SPENT
from kit import TOOLS, ROLE, run_gated, brief

def fresh(result, seen):
    """这一步拿回来的东西，以前见过没有？查资料看出处，别的工具看结果本身"""
    try:
        found = json.loads(result)["source"] or ""
    except (ValueError, KeyError, TypeError):
        found = result
    new = set(found.replace(" ", "").split(",")) - seen - {""}
    seen |= new
    return bool(new)

def wait():
    answer = input("   [你] 回车继续，输入“停”就停：").strip()
    if not sys.stdin.isatty():
        print(answer or "（回车）")           # 回答不是从键盘敲的时候，印出来留个底
    return answer

def wrap_up(messages, why):
    """被叫停的时候，不能把它晾在半路。让它交代：做成了什么，还差什么"""
    print(f"   [停] {why}")
    messages.append({"role": "user", "content": f"（{why}，现在必须停下，不能再用工具。"
                     "请直接汇报：已经做成了什么，还有什么没做成。）"})
    return chat(messages)                    # 这一次不给清单，它只能说话

def agent(goal, most=8, budget=15000, patience=3, watch=False, run=run_gated, talk=None):
    messages = talk if talk is not None else [{"role": "system", "content": ROLE}]   # talk：接着上一轮往下说
    messages.append({"role": "user", "content": goal})
    start, seen, stale = SPENT["tokens"], set(), 0
    for n in range(1, most + 1):
        message = chat(messages, tools=TOOLS)
        messages.append(message)
        calls = message.get("tool_calls") or []
        if not calls:
            return message["content"]                              # ① 它自己说做完了
        progress = False
        for call in calls:
            print(f"   第 {n} 步  {call['function']['name']}  {brief(call['function']['arguments'])}")
            result = run(call)
            print(f"           →  {brief(result)}")
            messages.append({"role": "tool", "tool_call_id": call["id"], "content": result})
            progress = fresh(result, seen) or progress
        stale = 0 if progress else stale + 1
        if stale >= patience:
            return wrap_up(messages, f"连着 {patience} 步没有拿到新东西")   # ② 原地打转
        if SPENT["tokens"] - start > budget:
            return wrap_up(messages, f"{budget} 个 token 的预算用完了")     # ③ 钱花光了
        if watch and wait() == "停":
            return wrap_up(messages, "用户叫停了")                          # ④ 你不想等了
    return wrap_up(messages, f"走满了 {most} 步")                           # ⑤ 步数到头

if __name__ == "__main__":
    from drift import GOAL
```

## 一条画好的路，还是让它自己找路

到这儿，你大概对“让它自己走”这件事，不那么兴奋了。

那就问一个更根本的问题：**一定要让它自己走吗？**

回头看“查一下账号审批要等多久，存成 `limit.md`”这类活。它每次是怎么办的？查一次，存一次，回话。每次都一样。

既然每次都一样，这条路为什么不干脆由我画好？

```python
# fixed.py：不让它决定任何事。路是我画好的：查一次 → 有依据就存，没依据就不存
import json, re
from kit import search_docs, save_file

def fixed(request):
    name = re.search(r"\w+\.md", request).group()          # 文件名，从你的话里直接抠
    found = json.loads(search_docs(request))               # 查一次
    if not found["source"]:
        return "查不到依据，没有存。"
    return save_file(name, f"{found['answer']}\n\n依据：{found['source']}")

if __name__ == "__main__":
    print(fixed("查一下账号审批要等多久，存成 limit.md。"))
    print(open("workspace/limit.md", encoding="utf-8").read())
```

没有圈，没有“决策”。从你的话里抠出文件名，查一次，有依据就存，没依据就不存。模型只在“查资料”那个工具里面出场，外面这几行，全是写死的。

```
已写入 workspace/limit.md，共 36 个字
新入职员工账号审批时限为45分钟，实习生为2个工作日。

依据：D03
```

也办成了。

两种办法，用的是同样的工具、同一个模型。区别只有一处：**下一步去哪儿，是程序里写好的，还是每一圈由模型现定。**

前一种，人们叫它 **Workflow**，工作流。后一种才叫 Agent。2024 年底，Anthropic 写过一篇给工程师的文章，就是这样分的：工作流是用事先写好的代码路径，把模型和工具编排起来；Agent 是让模型自己动态地决定过程、决定用什么工具。文章给的建议很朴素：先找最简单的办法，只有在确实需要的时候，才往上加复杂度。

你会选哪一种？

别凭感觉，比一次。六件事：三件“查一下、存一下”，一件资料里根本没有的，再加上这一章的两件大活。两边都不设门，办没办成由程序去查文件。

```python
# compare.py：同样的工具，同样的六件事。一边走画好的路，一边让它自己找路
import os
from llm import SPENT
from kit import run_safely
from fixed import fixed
from agent import agent
from four import DAY1

PLAN = "新同事早上 9 点整提交账号申请。一切顺利的话，他最早几点能做完环境自检？把推算过程写成 plan.md。"

# 每件事：你说的话，该出现的文件，文件里必须有的内容（None 表示不该有这个文件；a|b 表示有一个就行）
JOBS = [("查一下账号审批要等多久，存成 limit.md。", "limit.md", ["45"]),
        ("差旅报销多少天之内要交？存成 expense.md。", "expense.md", ["十个工作日"]),
        ("会议室一次最多订多久？存成 room.md。", "room.md", ["两小时"]),
        ("食堂几点开门？存成 canteen.md。", "canteen.md", None),
        (DAY1, "day1.md", ["入职系统", "45", "前台", "20", "15"]),
        (PLAN, "plan.md", ["10:30|10:10"])]      # 一件接一件办是 10:30；下载和审批同时进行是 10:10

def done(name, must):
    path = os.path.join("workspace", name)
    if must is None:
        return not os.path.exists(path)
    text = open(path, encoding="utf-8").read().replace("：", ":") if os.path.exists(path) else ""
    return all(any(w in text for w in word.split("|")) for word in must)

def grade(method, label):
    right = calls = tokens = 0
    for request, name, must in JOBS:
        if os.path.exists(os.path.join("workspace", name)):
            os.remove(os.path.join("workspace", name))
        before = dict(SPENT)
        method(request)
        ok = done(name, must)
        right += ok
        calls += SPENT["calls"] - before["calls"]
        tokens += SPENT["tokens"] - before["tokens"]
        print(f"{label}  {name:<11} {'办成' if ok else '没办成'}   问模型 {SPENT['calls'] - before['calls']:>2} 次  {SPENT['tokens'] - before['tokens']:>5} token")
    print(f"{label}  办成 {right} / {len(JOBS)}，一共问模型 {calls} 次，{tokens} token\n")

if __name__ == "__main__":
    import io, contextlib
    def silently(method):                    # 这回只看结果，不看每一步
        def run(request):
            with contextlib.redirect_stdout(io.StringIO()):
                return method(request)
        return run
    grade(silently(fixed), "画好的路")
    grade(silently(lambda r: agent(r, run=run_safely)), "自己找路")
```

前四件，两边都办成了。画好的路每件问模型 3 次，一千来个 token。自己找路的，每件 5 到 6 次，两千六到三千七。**同样办成，花了三倍上下的钱。** 而且画好的路每次都是 3 次，你闭着眼睛都能报出它的账单。

第五件，四件事的 `day1.md`，只有自己找路的办成了。画好的路只查一次，把四件事一股脑儿当成一个问题去查，查回来的是“资料里没有”，于是它什么都没存。

第六件，两边都没办成。画好的路花了一千三，老老实实说查不到，什么都没存。自己找路的花了一万，交出一份漂漂亮亮的 9:55。

你更怕哪一种失败？

把这张表合起来看，能得出一条不那么激动人心、但很管用的判断：

**你能提前画出流程图的事，就把图画出来，让程序照着走。画不出来的，要看上一步的结果才知道下一步该干什么的，才让它自己找路。**

两种办法也不是非此即彼。你再看一眼 v0.9：最外面是一个圈，由它自己找路。可圈里面那个“查资料”的工具，打开来是上一章的 v0.7，一条五步的、画得死死的路。

圈里套着路。能定死的部分定死，定不死的部分才交给它。

## 卖零食的 Claudius

我们的实验都很短，最长的也就十二圈。要是让一个 Agent 连着跑上一个月，面对的还是真人和真钱呢？

2025 年，Anthropic 和一家叫 Andon Labs 的公司做了这么一次试验，起名 Project Vend。他们让一个 Claude 模型在旧金山的办公室里经营一个小小的零食铺：一台小冰箱，几只筐子，一台用来自助结账的 iPad。这个店主被叫作 Claudius。它可以上网找供货商，可以定价，可以通过聊天软件和来买东西的员工说话，补货这类体力活则发邮件请人来做。

目标只有一个：把店开下去，别亏光。

有一天，一位员工半开玩笑地问它：能不能进一块钨立方体？

钨立方体是一种沉甸甸的金属方块，除了摆在桌上，没什么用处。Claudius 进了。然后更多人来要各种“特种金属制品”，它就接着进。它没有好好查过价钱，卖得比进价还低。按 Anthropic 的复盘，它的资产曲线上最陡的那一段下跌，就是买进一批金属方块的时候。

![[零基础学AI/attachments/第 09 章｜我不再每一步都替它接着想/BerCbONeNovAGlxsOuLcqhsonde.png|零食铺的货架上，多了一样本不该有的东西。]]

别的事也不少。员工在聊天里磨一磨，它就给折扣码，有的东西干脆白送。有人出一百美元买一组网上卖十五美元的饮料，这笔送上门的利润，它没接。它还一度让顾客把钱付到一个并不存在的收款账号上。

你把这几件事，和这一章的实验对一对。

卖零食的店，为什么进了一屋子钨块？因为每一步都说得通：顾客想要，店主进货，天经地义。和那十二圈一样，没有哪一步是蠢的，可是连起来，离“把店开下去”越来越远。这叫**目标漂移**。

被员工磨出折扣呢？那是上一章的 D99 换了一张笑脸。外面的人说的话进了它的对话，它就当成了该办的事。

付到不存在的账号上呢？第 04 章的老朋友：接得出来，不等于查过。

Anthropic 自己的结论很干脆：照这次的表现，不会雇它。但他们同时认为，其中不少毛病是能靠模型外面的东西改善的：更合用的工具，更清楚的规矩，更好的记录。

他们能把这些事一件一件讲清楚，是因为每一步都留了记录。出了事，翻得回去。

**选读：给这一章的东西起个名字。** 这一章你做了四样东西：一个圈，一箱工具，四个刹车，一道要你点头的门。把它们合在一起，套在模型外面的这一层，就是导论里提到的 **Harness**（原意是套在马身上的挽具）。同一个模型，换一副 Harness，就是另一个东西。2025 年以后那些能在你电脑上自己干活的编程工具，像 Claude Code、Codex CLI，去掉模型，剩下的就是一副很讲究的 Harness。它们住在终端里（只有文字的命令行窗口，叫 **CLI**）。还有一个常见词是**计划模式**：动手之前，先让它把打算怎么干写出来，你点了头它才动——相当于把这一章的门，从“每一步之前”挪到了“整件事之前”。

## 这一章你留下了什么

`agent.py` 是资料助手的 **v0.9**：一个圈，五个出口，被叫停时会交代，能接着上一轮往下说。`kit.py` 是它的工具箱。

`fixed.py` 和 `compare.py` 请留好。往后每次你想做一个 Agent，先用它们的办法问自己一遍：这件事，画好的路办不办得成？

`drift.py` 和 `plan.py` 是两个反例。以后有人给你演示一个“全自动”的 Agent，你可以问他三件事：它什么时候停？停下来的时候，会交代什么？它说做完了，你凭什么信？

还有四句话。

圈是它在转，边是你画的。

每一步都说得通，不等于在往前走。

它说做完了，不等于做完了。

画得出流程图的事，别让它自己找路。

## 下一站

资料助手现在能自己走了，有边界，会交代，也知道什么时候该走画好的路。不过在正式把工具交给全组同事之前，还有两道坎：

一道坎是**干到一半断了怎么办**——文件写了一半进程挂了、或者你中途按了停止，重开以后怎么接回来而不重做两遍（我们紧接着放在本章番外里拆开看）。

另一道坎是**怎么把工具和做法搬给别人**。隔壁组的同事看了很眼馋：能不能把你那个“查资料”的工具，也给我的助手用用？他的助手是另一家的产品，工具清单的写法和你的不一样；再加三样工具、换两台助手，三个助手配四样工具就是十二根线。

## 附：这一章的工具箱

```python
# kit.py：上一章攒下的东西，收进一个文件。三样工具，一个说实话的执行器，一道门
import json, os, re, sys
from concurrent.futures import ThreadPoolExecutor, TimeoutError
from rag import ask as look_up                      # 第 07 章的 v0.7

def tool(tool_name, description, **params):
    """少抄几行：把名字、说明、要填的几项，拼成清单上的一项"""
    return {"type": "function", "function": {
        "name": tool_name, "description": description,
        "parameters": {"type": "object", "required": list(params),
                       "properties": {k: {"type": "string", "description": v} for k, v in params.items()}}}}

SEARCH_DOCS = tool("search_docs", "在测试组的资料库里查一件事。一次只查一件事。", query="要查的问题")
CALC = tool("calc", "算一道算术题。凡是要算数，都用它，不要心算。", expression="算式，如 9*60+45+20")
SAVE_FILE = tool("save_file", "把一段文字存成文件。只能存进 workspace 文件夹。", name="文件名，如 day1.md", content="文件内容")
TOOLS = [SEARCH_DOCS, CALC, SAVE_FILE]

def search_docs(query):
    reply, source, _ = look_up(query, dept="测试组")
    return json.dumps({"answer": reply, "source": source}, ensure_ascii=False)

def calc(expression):
    if not re.fullmatch(r"[0-9+\-*/(). ]+", expression):      # 只认数字和加减乘除，别的一概不算
        return "拒绝：算式里只能有数字、括号和加减乘除"
    return str(eval(expression))

def save_file(name, content):
    root = os.path.realpath("workspace")
    path = os.path.realpath(os.path.join(root, name))
    if os.path.dirname(path) != root:
        return f"拒绝：只能存进 workspace 文件夹，{name} 不在里面，什么都没写"
    os.makedirs(root, exist_ok=True)
    with open(path, "w", encoding="utf-8") as f:
        f.write(content)
    return f"已写入 workspace/{name}，共 {len(content)} 个字"

DO = {"search_docs": search_docs, "calc": calc, "save_file": save_file}

ROLE = """你是测试组的资料助手。
- 凡是公司的规定，必须先用 search_docs 查到再写，不许凭印象。
- 查不到依据的内容，不要存进文件，直接告诉用户查不到。
- 存完以后，如实告诉用户存在了哪儿、依据是哪一份资料。"""

def brief(text, n=56):
    """印出来给人看的时候，太长的截一截"""
    text = text.replace("\n", " ")
    return text if len(text) <= n else text[:n] + "……"
WRITES = {"save_file"}                                # 会留下痕迹的工具
POOL = ThreadPoolExecutor()

def run_safely(call, do=DO, limit=60):
    name = call["function"]["name"]
    if name not in do:
        return f"出错：没有 {name} 这个工具"
    try:
        args = json.loads(call["function"]["arguments"])
        result = POOL.submit(do[name], **args).result(timeout=limit)
        return "出错：工具什么都没有交回来，不知道做没做成" if result in (None, "") else str(result)
    except TimeoutError:
        return f"出错：等了 {limit} 秒还没做完，不再等了。它做没做成，不知道"
    except ValueError:
        return "出错：这张纸条不是一个完整的 JSON，没法照办"
    except Exception as error:
        return f"出错：{error}"

def run_gated(call, do=DO):
    if call["function"]["name"] in WRITES:
        answer = input("   [门口] 这一步会改动文件。放行吗？(y/n) ")
        if not sys.stdin.isatty():
            print(answer)
        if answer.strip().lower() != "y":
            return "没有执行：用户不同意这一步"
    return run_safely(call, do)
```
