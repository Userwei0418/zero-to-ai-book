# 第 06 章（番外）｜先别让它写长文：判断、校准与模型分工

配套课件在这里：[[零基础学AI/attachments/mygpt-companion-20261117-r4-8c90a8fb.zip|下载上册配套代码与实验材料（r4）]]。解压后先读 README，按对应章节说明使用。

上一章我们看到，让模型“多想一会儿”虽然能把排期题算对，代价却很明显：又慢，又贵。

可日常工作里，很多事根本不需要它写一篇长文，更不需要它沉思十四秒。有时候，你只是想让它对着一条便条，点一个头，或者留一个问号。

## 这回，先别请它再写一篇

回到新同事入职的核对清单。现在清单上还有一格没有勾：**“在新电脑修改方案，保存，关掉再打开，确认修改还在。”**

你翻到一条交接记录：“在新电脑已经打开了活动方案第 3 版，页面预览正常。”

这一格，可以勾了吗？

不能。打开看过，和改完还能保存，是两回事。也不能写成“保存失败”——记录里根本没说试过保存。现在最诚实的状态是：**这项检查还没有得到证据。**

如果资料助手每天帮你整理这类记录，你希望它交回来什么？是一段客客气气的长文说明，还是下面这张清清楚楚的三格状态：

- **支持**：记录明确证明这件事做成了；
- **相反**：记录明确证明这件事失败了；
- **不足以判断**：证据不够，这一项继续留在待查清单里。

第三个位置不是给模型留面子，它有实打实的用处：把“还没证据”的格子留出来，下一步才知道该去补测哪一项。

假如记录本来就是程序产生的，字段清清楚楚：

```python
record = {"open": True, "edit": None, "save": None, "reopen": None}
```

`True` 表示通过，`False` 表示失败，`None` 表示还没测。此时**不用请任何模型猜**：四项全是 `True` 才算完成；出现 `False` 就报失败；其余情况一律待验证。就像第 01 章和第 06 章反复提醒的那样：**规则没有因为大模型出现就失去价值，已经确定的条件直接写进程序。**

但眼前的便条不是四个布尔字段。有人写“改完关掉，再开，新加的段落还在”；有人写“按了保存，再开却少了那一页”。要把这些自然语言接到清单上，才轮到语言模型出场。

## 把十二张便条交到桌上

问题缩到一件可以核对的小事：**这条记录，能不能支持旁边这句话？**

先拿三对来试：

| 记录 | 待核对的话 | 应该放在哪一格 |
| :--- | :--- | :--- |
| 增补预算说明，保存后关掉，再打开，新增段落还在 | 编辑、保存和重开检查已完成 | **支持** |
| 保存后再打开，刚才增加的预算说明没有了；保存检查未通过 | 保存检查已通过 | **相反** |
| 已经打开第 3 版，页面预览正常 | 已修改、保存并重开确认修改保留 | **不足以判断** |

参考课件里准备了 12 条这样短小明确的练习记录（支持、相反、不足以判断各 4 条），分别让轻量的对话模型交两种答卷：
- **第一种**：只交判断标签；
- **第二种**：除了标签，还要逐字抄回依据原句，并自报一个 0 到 1 的把握值（`confidence`）。

| 答卷方式 | 12 题标签正确 | 输入 token 合计 | 输出 token 合计 |
| :--- | :--- | :--- | :--- |
| 只交标签 | 12/12 | 3,045 | 799 |
| 标签 + 原句 + 自报把握 | 12/12 | 3,741 | 2,043 |

两种答卷一样准，多交材料没有让正确率更高，却多花了一倍多的输出 token。那为什么要多要这一步？**为了让你能回查。**

![[零基础学AI/上册/attachments/Pasted image 20261117030321.png]]

带了原文依据，你就能立刻用程序查一件简单的事：**它抄回来的那段字，在输入里真的出现过吗？** 这是确定的字符串检查，一毫秒就能跑完，不会出错。

可接下来要当心另一个陷阱。假设我们亲手构造一份坏答卷：原文只有“打开第 3 版，页面预览正常”，答卷却写着“支持：编辑、保存、重开检查已完成，把握 0.99”，引用的原句一字不差。程序一查：JSON 合法，原句也找得到。**可这份答卷依然是错的。**

**出处存在，不等于出处支持结论。** 而且，即使模型对“资料不足”报出 `0.95` 的把握，也不矛盾——它有把握的是“这句话没有被记录支持”，不是“保存这件事已经成功”。

到这里，分工已经清楚了：程序核对出处是否存在、版本号和字段是否齐全；模型帮助判断自然语言之间的关系；真正决定能不能收起旧电脑的，还是人在新电脑上的实际操作。

## 2017 年，九成把握是什么意思

把时钟拨回 2017 年。那一年，图像分类模型已经很准，大家开始想把它们接进业务：模型说有九成把握的先自动放行，拿不准的再交给人。

系统给了类别，也给了 0 到 1 的分数。可这里差了一道关键检查：**所有报出“九成把握”的判断，合起来是不是真的对了九成？**

2017 年，Guo 等人系统研究了现代神经网络的**置信校准（Confidence Calibration）**。他们发现，很多很准的模型，报出来的概率却常常虚高——嘴上说着 0.95，实际只对七成。类别分得准不准，和概率报得准不准，是两张不同的考卷。

拿十个手算样本体验一下阈值怎么坑人。假设分数从 `0.99` 排到 `0.89`，其中 `0.98` 和 `0.92` 两项是错的。如果把放行阈值从 `0.90` 提高到 `0.95`：

| 放行条件 | 收下多少题 | 其中答对 | 其中答错 | 收下部分正确率 |
| :--- | :--- | :--- | :--- | :--- |
| 全部收下 | 10 | 8 | 2 | 80% |
| 分数 ≥ 0.90 | 9 | 7 | 2 | 77.8% |
| 分数 ≥ 0.95 | 4 | 3 | 1 | 75% |
| 分数 ≥ 1.00 | 0 | 0 | 0 | — |

![[零基础学AI/上册/attachments/Pasted image 20261117030546.png]]

阈值一味拧高，收下的少了，这一小批里的正确率反而从 `7/9` 降到了 `3/4`。高分并没有把错误排干净；最后一行零错误，只是因为它一件活都没接。

所以，聊微信或调用 API 时让模型顺手写进 JSON 里的 `confidence`，首先只是一个**接出来的数**，不是经过校准的真实概率。

## 2026 年，把专门判断放进系统里

既然很多地方只需要“有范围的判断”，能不能干脆用专门为结构化判断设计的模型，而不是每次都请通用生成模型现写？

2026 年，TypeSafe 推出的 **Jev**（官方称为 System One 模型）就是一个典型思路：不让你写长文，而是把状态材料和带类型的问题交进去，直接取回带类型的结果——比如在给定选项里挑一个（`Choice`）、按等级打分（`Score`）、对是非返回 0 到 1 的值（`Noul`），或者在图片里框出区域（`Box`）。官方还强调，这类模型只负责**局部判断**，再由外面的代码把判断和明确条件组合成最终决策；它的训练路线（RLCD，面向校准决策的强化学习）瞄准的也是让这一批概率输出在统计上有可用含义。

但即便用了专门的判断模型，有两个工程坑依然要防：

1. **两个数字，不等于两份证据**：有些接口会同时返回各选项概率和另一个 `confidence` 字段，但后者往往只是用最高概率 `p` 和选项数 `n` 换算出来的（例如 `(p - 1/n) / (1 - 1/n)`）。同时检查这两个数，并没有多出一份独立证据，就像第 06 章把同一个模型问五遍投票一样。
2. **输出形状合法，不等于对象存在**：比如 `Box` 框图接口，哪怕图里根本没有目标，也可能老实返回四条坐标边界。所以程序必须先问“有没有”，再决定要不要用返回的坐标。

## 把岗位留给合适的部件

走到这里，你再看“做个资料助手”，脑子里就不该只剩下一个聊天框了。不同的活，本来就该分给不同的部件：

| 眼前要完成的事 | 先考虑谁来接 | 交回的结果还不能证明什么 |
| :--- | :--- | :--- |
| 核已知字段、时长、版本号、原句是否存在 | **普通程序与规则** | 未输入的事实不会自动被发现 |
| 判断便条与断言是否支持 / 相反 / 未决 | **有限分类或专门判断模型**（生成模型也可承担） | 标签正确不等于原始记录真实 |
| 从几百上千份材料里找相近候选 | **关键词检索或向量检索** | 相近不等于能支持这句话 |
| 比较候选和问题的贴合程度 | **重排模型或其他排序方法** | 排序高分不是授权，也未必是真实概率 |
| 把核过的结果整理成通顺说明 | **生成模型** | 写得通顺不等于文件已保存或检查已执行 |

所谓**模型路由（Model Routing）**，核心就在这张表里：程序先用便宜、确定的规则拦掉能算清的部分，再把需要理解的部分交给合适规模的模型，最后把组织语言的事交给生成模型。

## 带着三份记录去下一章

合上这一篇之前，我们把前几章遇到过的几种不对劲摊在同一张桌上，练一次**排障分诊**：

1. **排期算成旧结果**：下载时间已经改成 40 分钟，模型还算出 45 分钟——打开**它收到的输入材料**，发现里面根本没放进新通知（缺的是“料”，不是“想”）。
2. **建议里多出无依据数字**：模型提醒“做一次修改-保存-重开检查”，动作没错，却顺嘴添了一句“花一分钟”——拆开**它的回答**，保留有依据的动作，去掉无依据的时长承诺。
3. **文件保存了但活没干完**：助手真的把接续清单写进了硬盘，新进程也能读回——核对**真实产物和外部状态**，发现“保存清单”不等于“清单上的成本表已补齐、实机测试已跑完”。

以后助手再让你觉得“哪里怪怪的”，别笼统地下一句“模型不够好”。先打开**输入材料、模型回答、实际产物**这三份记录，留下三句话：**我现在怀疑什么；下一步先查哪一份记录；看到什么证据，我会改变主意。**

至于表中空出来的那两格——**当材料变多、条件更新时，怎么把最新、最对的那几份放进模型眼前的书包里**——这就是第 07 章要动手解决的事。
